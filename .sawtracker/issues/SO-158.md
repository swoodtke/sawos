**Distinct index types in the kernel core.** The owner asked for this on Nov 24. Today the kernel core indexes its tables with bare `Int`s. A process record index, a process body index, a thread slot, a handle-table index, a grant row, a slab slot and a handle block's index are all `Int`, so passing one where another is meant compiles silently. `process_band_map(p: Int, child: Int, raw: UInt)` reads `PROCESS_RECORDS[child]` and `PROCESSES[body_of(p)]`: two index spaces in two lines.

**Saw already gives the tool.** `type ProcessIndex = Int` is a *distinct* type: it flows to `Int`, back only through `ProcessIndex(i)`, at no runtime cost. The ABI already does this for handles (`ProcessHandle`, `ThreadHandle`…). An array subscript takes `Int`, so a distinct index still indexes any table. Each table therefore gets an accessor that takes its own index type, `record(p: ProcessIndex)` or `body(b: BodyIndex)`, and code goes through it rather than subscripting the array.

**The types** (named in the first section, with final names decided there):
- `ProcessIndex`, a record;
- `BodyIndex`;
- `ThreadIndex`, a slot;
- `HandleIndex`, an index in a process's table;
- `GrantRow`;
- `SlabSlot`, per slab where the kinds differ;
- `BlockIndex`.

**One issue, one patch per section.** Each section is scheduled only when no other patch in flight touches its files (the owner's rule). It's mechanical: no behaviour changes, and the whole gate and the S3 smoke pass unchanged, each transcript byte for byte. Each patch lists every signature it retypes.
1. **The types and the process tables:** `pslot.saw` and `process.saw`'s records and bodies, with their accessors.
2. **Threads and the scheduler:** `threads.saw`, `sched.saw`, `preempt.saw`.
3. **Handle tables and blocks:** `objects.saw`, `refs.saw`.
4. **Memory, grants, pools and mappings:** `mem.saw`, `areas.saw`, `slab.saw`, and the memory arms of `dispatch.saw`.
5. **Waitables, time and interrupts:** `waitables.saw`, `time.saw`, `irq.saw`.
6. **`dispatch.saw`'s remaining arms, `loader.saw`, `stats.saw`, `diag.saw`:** anything still bare.

A section may split if a patch passes about 1,500 changed lines. A section that turns up a real mix-up stops and reports it as a bug on its own, separate from the retyping.

**From the sawlang lead (m1451):** SL-1012 U3, submitted and not yet in a tag, makes `type X = Y` aliases fully distinct.
- **Conversions:** a raw value into the alias needs `X(v)`, while the alias still flows into a `Y` parameter. Sibling aliases no longer mix in flows, operators or casts, and `x as X` becomes `X(x)`. Operators on an alias give the underlying type, and `h += 1` is refused.
- **Consequences for this issue:**
  - The index types give their full protection only on a pin that carries SL-1012 U3, so the sections should wait for that pin bump.
  - The same bump will break the 16 handle aliases in `kernel/abi/src/types.saw` at each raw-to-handle site; each fix is a construction.
  - The pin bump and the handle-alias fixes belong together, before SO-158's first section.

**On the owner's direction (c17): the compiler holds half of 'a call that touches the same table goes after the block'.** I probed it with v0.24.6 on a table shaped like THREADS (an unsafe static with a private array and at()):

**An option for the owner: let the compiler hold both halves of the rule.** It holds them if each table is a declared static root that lends its wrapper. These are probes with v0.24.6, files under `so158_p2/` in my scratch, not kernel code.

**The form:**
- The static becomes module-private.
- One function per table lends the wrapper: `func threads() unsafe sync borrows(sync, THREADS) -> &var ThreadTable { lend THREADS }`.
- `ThreadTable` keeps its private slab and typed `at()`, so every access reads `borrow var t = threads() { borrow var s = t.at(i) { … } }`.

**What the compiler then refuses, which it does not refuse today:**
- **A bypass.** Naming `THREADS` outside the root function is `borrows.root-named-outside`. Today that is a review sweep.
- **A call inside a window that reaches the table, however deep.** It is `loan.window-root-call` and names the chain (`helper → table`). Today a call compiles, so review has to follow every call inside every window. That is the gap c18 describes.

**What still works:**
- The direction's own shape, with the call after the block and then a new window. It compiles and runs as written.
- Reading the table's geometry (`t.capacity()`) before the element's window opens. Reading it inside that window is refused, correctly.

**The costs, as the spec states them (§"Lending a static"):**
- A root must be a module-private static. `THREADS` is `public(package)` today, so the other kernel files reach it only through `threads()`.
- A `borrows` function must lend, so geometry and donation become wrapper methods called inside `threads()`'s window (`borrows.result` refuses a root function that returns an `Int`).
- One root per function, and the function is `sync`.
- Each access gains one level of window.

This changes section 1's shape and every section's, so it's the owner's to rule on. I haven't measured the code cost. Under SL-1199 `threads()` is a lend of the whole static with no epilogue, so I'd expect it to inline, but that's UNVERIFIED.

## Description

**The ESP32-S3's CPU clock: raise it, and measure what it buys on `kill_churn`, with a profile of where a round's time goes.** The user asked for this on Nov 14, after the board run showed `kill_churn` taking about 129 ms a round on the part (SO-72 has the capture). The kernel changes no clock today, so the part runs at whatever the ROM leaves, which has never been read (`hal/xtensa-esp32s3/ABI.md`, "Clock").

**What is built.**

1. **`hal.clock_init()` on the ESP32-S3 HAL**, called by `kmain` before anything else that depends on a clock, as the PSRAM design's contract says a clock change must be (`.claude/lead/so102-design.md` in the lead's checkout, sections 3.1 to 3.3: which registers and fields make the system clock, what the ROM is believed to leave, the three open readings, and what a clock change owes the memory-SPI clock). It is the only code that writes the clock's fields. On every other HAL it does nothing.
2. **The clock is chosen at build time, per image**, by one key the runner passes to the kernel build for the S3 (a case key and a command-line override for `--emit-flash`): `rom` (write nothing; the default, so the gate's images are byte for byte what they are today), and each speed this unit can reach: the crystal undivided (40 MHz), and the PLL at 80, 160 and 240 MHz. If a speed cannot be reached soundly, say why and leave it out; do not ship a guess.
3. **Every step is taken from ESP-IDF v5.4.1's own clock code and the ROM** (`rtc_clk_init`, `rtc_clk_cpu_freq_set_config`, `rtc_clk_bbpll_enable` and `rtc_clk_bbpll_configure`, `rtc_clk_cpu_freq_to_pll_mhz`, `clk_ll_*` in `hal/esp32s3`, the `regi2c` BBPLL words, and the ROM functions they call, with the ROM's addresses from its linker scripts). For each write: the register, the field, the value, the file and function it is taken from, and what happens if it is skipped. Do not work from memory of how these chips behave: read the source at that tag and cite it. Where the design's section 3 and the source disagree, say so.
4. **What a clock change must carry with it**, each stated with its source and either handled or shown not to move:
   - the console: UART0's divisor is for the clock the ROM left; either the UART's clock source does not move with the CPU's, or the divisor is rewritten, and nothing is printed while the two disagree;
   - SYSTIMER, which the kernel times with (16 MHz from the crystal on this chip: confirm it does not move);
   - the flash: the code runs from flash through the cache, so the memory-SPI core clock and the flash divider must stay valid across the switch (the switch itself runs from IRAM; the design's section 3.3 says what it believes holds at `CORE_CLK_SEL` 0);
   - the watchdogs `_start` already disables, and anything else whose period is derived from the APB clock.
5. **Each image says what it runs at.** One line at boot, printed after the switch (and after the console is right again), with the clock words before and after: `SOS-S3: clock <name> sysclk=<before>-><after> cpu_per=<before>-><after>` (the format is yours; it must be one line, and present only when the key is not `rom`, so no gate transcript moves). In a `rom` image a board-only probe line may print the same two words read and unchanged.
6. **A measured CPU speed, not only a configured one:** `CCOUNT` advanced over a fixed SYSTIMER interval, printed on that line as MHz. Reading SYSTIMER takes a write of its snapshot bit, which the kernel's own timekeeping already does.
7. **The profile.** A board-only variant of `kill_churn` (`kill_churn_profile`; the runner needs a `board_only` key that `--emit-flash` builds and a smoke run skips, if it has none) in which root stamps the clock around each phase of a round (create, the gives, start, settle, kill and status, release) and prints the six totals and the whole at the end, in microseconds, once: nothing is printed per round by root. The kernel's own teardown line is a large part of a round at 115200 baud, so the profile needs the console's share separated: say how (a count of bytes written and the baud is arithmetic; a kernel built with that line off for this case is a measurement; choose and say why). If create dominates, split it once more inside the kernel under a build key that only this case sets (the image's copy, the zeroing, the rows), so the gate's kernel carries no instrumentation.
   Printed values are for a reader: nothing here is asserted, and no case in the gate gains a time-dependent value.

**The emulator.** Espressif's QEMU runs `CCOUNT` at 40 MHz of host time whatever the registers say, so the smoke can show only that an image with each clock key still boots and prints, and that the `rom` images are unchanged. Say what the emulator does with each register this unit writes (ignored, stored, modelled), found by running, and add smoke cases for the keys that can run there.

**The board.** For each clock key, a flashable `kill_churn` and `kill_churn_profile` image (`--emit-flash`), each with its SHA-256 and expected text. Nothing is flashed by this unit: the lead sends the images to the reviewer, who flashes on the user's word. What may be done to the part is `write-flash 0x0` of our image and nothing else. Every write `clock_init` makes is volatile and a reset undoes it; state that for each register, and say what a wrong value does (the part hangs until reset and can be flashed again through the ROM's download mode) so the request to the board can say it.

**Order.** First the crystal undivided, which needs no PLL, then the PLL speeds. Hand back after the first if the PLL's bring-up turns out to need more than this unit should carry (the analog calibration words), with what you found.

**Not in this unit:** making a faster clock the default (the user decides after the numbers); PSRAM; the board description's `[clock]` section.

**What it does.**
- `kmain` calls `hal.clock_init()` first. It is empty on every HAL but the S3's, where a build key chooses the module that provides it: `keys/clock-rom` (empty, the default) or `keys/clock-xtal40`.
- **`xtal40` on the part writes:** one store to `SYSTEM_SYSCLK_CONF` (0x600C_0060) clearing the pre-divider field [9:0], made by `sos_clock_store` from IRAM (boot.S, no literal, read back); SYSTIMER's clock-enable and unit-0 work-enable bits and its snapshot bit, to measure `CCOUNT` against SYSTIMER before and after. If the source select reads PLL (the emulator's fixed word) a second store selects the crystal; a source of RC_FAST or 3 refuses with a line before any write. UART0 is not written on a part whose UART clock select reads crystal, which is what the ROM's `Uart_Init` leaves. Every register written is volatile; none is RTC-retained; no eFuse access.
- It prints one line, after the switch: the clock words before and after, the measured MHz before and after, and the UART, memory-SPI and RTC date words read.
- **The profile:** `kill_churn_profile` (board-only: built by `--emit-flash`, skipped by the smoke with its reason printed) totals root's time in each phase of a round and prints one line at the end. The console's share is measured, not computed: a `stall-on` key times every wait for FIFO room from the tick's arming and prints the total at the clean stop.
- The runner: per-case keys `clock`, `console_stall` and `board_only`, `--clock` for `--emit-flash`, and a build directory per set of keys.
- `ABI.md` §14: the whole sequence ESP-IDF v5.4.1's bootloader and `rtc_clk_init` run, with sources, what this unit takes and why each part left out is safe to leave out, and an empty table for the part's values.

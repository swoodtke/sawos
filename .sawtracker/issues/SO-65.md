## The defect

A child that is created (`ProcessCreate`) but never started, and that nothing
names any more, is never torn down. `reclaim_process_record` reclaims only
`Gone` records, and nothing ends a `Created` process. Everything in its boot
set stays held: regions, pipe ends, Events, Threads made through its handle
(inert since SO-41), and a given Interrupt, whose line then stays bound for
good. Its body is held too, and bodies are scarce.

## The ruling

**When the last reference to a `Created` process is dropped, the kernel tears
it down**, as if it had exited:
- its boot set is released;
- every object it owns is invalidated or freed per §2.10;
- its body is freed;
- its record is reclaimed at once, since no reader of its status word remains.

Choose the status word written (`Exited` with a sentinel code, or a new kind),
say why, and note that nobody can read it.

## The change

1. **Where the count reaches zero.** The record's `refs` reaches zero through
   `drop_reference`'s Process arm, `free_object`'s Process arm, the reap's
   process scan or `unref_teardown`. Find every path. On reaching zero on a
   `Created` record, run the teardown for it.
2. **The teardown runs for a process that isn't the caller.** This is the
   strand hazard SO-41 removed. `end_process` must work when the dying process
   is not the caller's:
   - It has no running thread: a `Created` child's only threads are inert ones
     made through its handle (SO-41).
   - `CURRENT_THREAD` belongs to the caller and must not be cleared.
   - Nothing may strand the caller.
   
   Read `end_process` closely, especially the `CURRENT_THREAD` comment and
   SO-62's `PENDING_FREE`, and make it safe for this case. A separate entry
   such as `end_unstarted(p)` that skips the caller-only steps is fine. Say
   which you chose, and trace it.
3. **Reentrancy.** The trigger can fire inside another process's teardown,
   when the launcher dies holding its never-started child's only handle. That
   means a teardown nested in a teardown. Either make it safe, or defer it the
   way the reap handles other `Gone` records (the reap's process scan already
   runs after the close-all). Say which, and trace it.
4. **Spec:** remove the §11 known-limit line SO-63 added ("a child that is
   created but never started, once nothing names it, is never torn down"), and
   state the rule in §2.7 (process lifecycle) and §8. No issue numbers; 80
   columns.

## Tests (probe first)

1. **Released handle.** Root creates a child, gives it a bound Interrupt, a
   region and a pipe end, and releases the child's handle without starting it.
   The line can be bound again at once, the region comes back (count capacity),
   the pipe's peer sees `PeerClosed`, and the body is free (a new create
   succeeds in it).
2. **The launcher dies.** A launcher child creates a grandchild, gives it a
   bound Interrupt (the launcher needs a System handle with `InterruptBind`;
   give it one), and exits without starting it. Root can bind the line again.
   This covers the nested teardown.
3. **An inert thread inside it:** a thread made through the unstarted child's
   handle is invalidated, and a held handle to it answers `Revoked`.

**Lead review, SO-65.p1.** This implements the user's ruling: a never-started process whose last handle goes is torn down.

**Trigger.** Every path to a `Created` record at zero refs ends in `reclaim_process_record`, which sets `UNSTARTED_PENDING`.

**The non-caller teardown.**
- `end_process`'s body is now `teardown_process(p, kind, code, is_caller)`.
- `end_unstarted(p)` runs it with `is_caller = false`. That leaves `CURRENT_THREAD` and `PENDING_FREE` alone, skips the exit line, and spares the running and pending-free slots in the thread sweep.
- The `Created` process has only inert threads, so the caller-only steps are no-ops for it. `clear_domain` is safe for a non-current body.

**No nesting.** `drain_unstarted()` runs at the head of `pick_next` and in `end_process` before `resume_after_death`, looping while the flag is re-raised. A teardown that drops another `Created` process's last reference only raises the flag.

**Status word.** `Exited` 0, which nobody can read.

**Probe (old kernel).** The released child's body leaked, the pipe end was held, a join hung, a rebind faulted `LineBound` and the pool cut faulted. In the launcher case, root's rebind faulted.

**Tests.**
- `unstarted_released`: bodies, `PeerClosed`, the inert thread → `Revoked`, the line rebinds and the region comes back.
- `unstarted_launcher`: the nested case; root's first syscall after waking binds the line.
- Mutants (no flag, no `pick_next` drain, no `end_process` drain) are caught.
- Seven existing transcripts gain one teardown line for a released unstarted child. They are subsequence matches, so no assertion changed.

**Lead edit.** A spec §11 known-limit line for the remaining cycle: a `Created` process whose last references sit in its own boot set never reaches zero.

**Runs.** The full suite passes locally (556 runs), plus the C3 smoke.

Approved patch SO-65.p1 (revision 1)

**Air: SO-65.p1, approved.** It implements the user's ruling. I read the kernel at 1144f1d + p1.
- **The trigger never reclaims early.** `reclaim_process_record` answers a `Created` record at zero refs by raising `UNSTARTED_PENDING` and returning, so neither the reap scan nor a release can free a never-started record's slot before its teardown.
- **The drain completes before the releaser is back in user space.**
  - `drain_unstarted()` is the first statement of `pick_next` (sched.saw:139), ahead of both early returns (`cur == NO_THREAD`, `stays_running`). `pick_next` runs at every trap return, so a release's teardown is done before the releaser resumes, and a rebind of the child's line right after the release succeeds.
  - It also runs in `end_process` before `resume_after_death` (:959), the launcher-dies case.
  - It loops while the flag is re-raised and re-scans every record, so several pending children, and a child whose teardown releases another's last name, are all handled without nesting.
- **The non-caller teardown is safe.** `teardown_process(…, is_caller: false)`:
  - leaves `CURRENT_THREAD` and `PENDING_FREE` alone;
  - spares both slots in the thread sweep;
  - skips the caller-only exit path.
  The unstarted process's own threads are inert (`Thread.Start` faults on a `Created` owner, SO-41), so invalidating them only wakes other processes' joiners with `Revoked`, which `unstarted_released` pins. `clear_domain` on a non-current body is fine.
- **Tests:** `unstarted_released` (the body, `PeerClosed`, `Revoked`, the line rebinds, the region returns) and `unstarted_launcher` (the nested case) catch the three mutants. The added teardown lines in seven transcripts are subsequence matches.
- **The §11 limit line for the self-referencing cycle** (a `Created` process whose last references sit in its own boot set) is right to mark.

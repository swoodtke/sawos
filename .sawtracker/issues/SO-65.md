## Description

## Finding

claude-air-reviewer found this in the SO-63.p1 review. The mechanism is pre-existing; SO-63 makes it reachable for interrupt lines.

A child that is created but never started, and that nothing names any more, is never torn down. `reclaim_process_record` reclaims only `Gone` records, and nothing ends a `Created` child. Everything given into its boot set stays held: memory regions, pipe ends, Events, and now an Interrupt, whose line can then never be bound again (`LineBound`).

The §9 launch flow (bind, give, start) walks into this whenever `start` is refused, for example by the thread quota or a full slab, and the launcher then drops the child.

## Proposal (lead; needs a user ruling)

When the last reference to a `Created` process is dropped (a handle release, or its creator's teardown), the kernel tears it down, as if it had exited. Its boot set is released, its body is freed, and its record is reclaimed at once, since no reader of its status word remains.

The alternative is to leave it as a documented known limit, which SO-63 adds to spec §11.

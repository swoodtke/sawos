## Description

On the ESP32-C3, `irq_line_valid` (hal/riscv32-esp32c3/kernel/lib.saw) accepts every line up to `INTMATRIX_MAX_SOURCE`, except `IRQ_NONE`. That includes `SYSTIMER_TARGET0_SOURCE` (37), the matrix source the kernel routes to `TIMER_CPU_INT` for its own tick.

The risk: an `InterruptBind` on line 37 may succeed. Depending on how bind programs the matrix, the binder could then re-route or take over the kernel timer's source. The kernel's own timer is reported as `IRQ_TIMER`, which sits above the matrix range, so nothing user-facing needs 37.

Next steps:
- Probe it: bind 37 from root on the C3 and see what happens to the timer smoke.
- If the bind reaches the matrix, refuse kernel-owned sources in `irq_line_valid`.

Found by the SO-27 r2 implementer. The C3 is non-gating, hence low priority.

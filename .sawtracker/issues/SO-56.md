## Description

## Finding

claude-air-reviewer found this by code reading during the SO-53.p1 review. It is pre-existing; SO-53 did not make it worse. It has not been probed.

A `Gone` process slot whose last reference (a handle entry or an attachment) is dropped by **another** process's teardown reaches `refs == 0` and is never reclaimed:
- the teardown's close-all uses `unref_teardown`, which deliberately does not free at zero;
- `reap_unreferenced`, which frees what nothing names at the end of the teardown, does not scan `PROCESSES`.

So the slot stays `Gone` with nothing naming it, and process capacity shrinks by one for good.

## Proposed fix

- `reap_unreferenced` also reclaims every `Gone` slot at zero, through `reclaim_process_slot`;
- or `unref_teardown`'s Process arm reclaims at zero.

Pick whichever fits the teardown's counting.

- [ ] The fix, with the case asserting the slot is reused.

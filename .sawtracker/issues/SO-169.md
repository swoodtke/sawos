**riscv32: page-align `.text`'s end, the emulator's sub-page PMP cliff.**

On riscv32 a process's image rows are PMP TOR regions on the 4-byte grain. So root's `.text` row ends partway through a page that also holds `.rodata`, which is another row. Code fetched from a page a PMP rule covers only partly runs far slower under QEMU.

`arena_race` shows it: hot heap code on that page takes it from 0.04 s to 10 s. The case then times out at the default job count once v0.24.4's slightly larger `SpinLock` prologue pushes `highest_bit` across. sawlang's SL-1196 measured both directions; the table is in its last comment.

**The fix:** `. = ALIGN(4096)` before `_text_end` in `hal/riscv32/user/user.ld`, costing up to 4 KiB per process.

**Its consequence:** `arena_race` and `arena_churn` hold today only because the cliff made riscv32 slow, and their comments say the faster profiles "cannot fail". They need their contention made true by construction, not by slowness.

This blocks the v0.24.4 pin bump (SO-167).

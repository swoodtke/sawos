**Lead: SO-163.p1 is A3-2, `drivers/virtio`.** It is one commit on current main: a new hosted package with no dependencies. The runner's `HOSTED_TESTS` gains one line, and CLAUDE.md gains the repo-map entry and the hosted-package list.

**Modules**
- `transport`: the register map, probe, the bounded reset, negotiation, config space read at each field's width with the generation re-read, and the interrupt ack masks.
- `queue`: the `Dma` trait, the memory plan, the split-queue layout and index arithmetic, barrier placement, and every used-ring check.
- `lifecycle`: `begin`, `setup_queues`, `go_live`, `pin_ring`, `ring_address` and `give_up`, with the failure classes and exit codes 0 to 4.
- `fake`: a device modelled on QEMU's, behind `Registers` and `Dma`, keeping one event log.

**What A3-4 needs to know**
- `Dma.pin` answers with the object already mapped.
- `setup_queues` pins the queue memory before any address register is written. Every device address comes from the pin's answer, so "pin before address" holds by construction. The fake counts any stray address.
- A frame's address comes only from `ring_address`, which panics if the ring isn't pinned or the range falls outside it.
- Completions come back in the device's order. Releasing a completed prefix belongs to the pktring side.
- `give_up(Refused)` unpins but does not unmap, as §3.9's table says.

**Mutants:** 85, all red. M39 survived its first run, so a chain-5 assert was added to make it red. Every row of §7.4 has a test.

**Runs:** `blade test` in `drivers/virtio`, 7 tests. The server runs the full suite.

Requested changes on patch SO-163.p1 (revision 1)

**Changes requested, revision 1.** The transport, negotiation, used-ring checks and failure classes are right and well tested. The address discipline, though, holds only on the path `setup_queues` takes, and 30 of 123 mutants survive `blade test`.

I built with sawlang v0.24.3. `blade test` passes 7. The kill tests and probes below are in f549. Each kill test passes on r1 and goes red under the survivors it names.

## 1. A frame's descriptor carries a length `ring_address` never checked
`ring_address(offset, len)` checks `offset + len` against the ring and answers a bare `UInt64` (lifecycle.saw:152-158). `post_rx` and `post_tx` then take the address and a separate `len` (queue.saw:294, 308). Nothing ties the two lengths together, so a buffer can run past the pinned ring:
- `ring_address(0x2000 - 60, 60)`, then `post_rx(…, len: 2048)`, is accepted. The device may write up to 1073817540; the ring ends at 1073815552.
- The fake counts no stray address, because `check_address` tests the start only (fake.saw:341-349, 572-580).
- `ring_address(0x2000, 0)` answers one past the end.

Design §4.2 says the descriptor's "length is the checked private copy".

**Asked:**
- `ring_address` answers one value carrying the address and length, constructible only in the package, and `post_rx` and `post_tx` take that value.
- The fake checks the whole range `[addr, addr+len)`.

## 2. Pin before address holds only inside `setup_queues`
Inside `setup_queues` every address comes from the pin (lifecycle.saw:115-132). The public API reaches around it:
- `Queue.new(0, plan.rx, plan.rx_headers, 0x9000_0000)` then `program`, from a test, gives `pins=0 stray=3 QueueReady writes=1`. `Queue.new`, `program` and `clear_rings` are `public` (queue.saw:223, 383, 400).
- The `Queues` that `setup_queues` returned, programmed again after `give_up(ClientGone)` unpinned them, gives `stray 3`.
- `Lifecycle` falls in the automatic Copy tier. A copy taken before `give_up` still answers `ring_pinned` true, and `ring_address(0, 64) = 1073807360`, after the original unpinned.

**The fix, probed:**
- Change: `Queue.new`, `program` and `clear_rings` made `public(package)`, plus `extension Lifecycle: NoCopy {}`.
- Tests: the 7 pass, after two edits to tests/queue.saw (`extension Up: NoCopy {}` and `lc: move lc`).
- The same misuse probe is refused at compile time: "`virtio.queue.Queue` has no method `new` this module can see", and `transfer.implicit-copy` on the `Lifecycle` copy. Against the patch's package it compiles clean.

**Asked:** that, or an equivalent that makes the claim true of the package's public surface.

## 3. `check_rx`'s bound is the caller's `buffer`, not the length posted
`post_rx` posts 100 bytes. The device reports `len` 2060, and `check_rx(buffer 2048)` answers ok. `post_rx` throws its `len` away (queue.saw:294-306), and `next` hands the device's `len` back in a public `Completion` before any check (queue.saw:353-365). Design §4.3 asks for at most 12 plus the slot size.

**Asked:** record each chain's posted length beside `in_flight`. Then check `len` and `num_buffers` against it in `next` for the receive queue, or in a `check_rx` with no `buffer` parameter.

## 4. Nine caller-misuse panics have no test
These survive:
- `next` with nothing pending;
- `post_rx`'s two panics;
- `post_tx`'s two;
- `ring_address`'s four: not pinned, the range check gone, `>` written `>=`, and the offset alone.

`ring_address`'s panic is the library's only enforcement of §7.4's row "the Pin of a ring before its first slot address is posted". tests/lifecycle.saw:180-185 is a control on the fake only.

All nine go red under `zkill_panics`, which runs a child per misuse as `drivers/pktring/tests/panics.saw` does.

**Asked:** those tests, or your own.

## 5. Eighteen boundaries and orders the tests leave open
Each mutant survives, and each goes red under `zkill_boundaries` or `zkill_more`:

| Mutant | Kill |
|---|---|
| the reset accepts any status with bit 0 clear | status 0x40 with `reset_never` must exit 4 |
| `read_link`'s generation loop `<` written `<=` | 2·CONFIG_READS−2 bumps accepted, −1 refused |
| the ring slot `% MAX_QUEUE` instead of the queue's size (two sites) | a 4-entry queue, its avail slot poisoned before each post |
| `pending` counted from `seen`, not `taken` | it answers 1, then 2 |
| the used id bounded by MAX_QUEUE | a 32-entry queue, id 32 → `UsedIdInvalid(32)` |

| the TX header zeroed 8 bytes at a time | dirty +4 too |

| `clear_rings` after `QueueReady` | the used idx stored before the first `QueueReady` |
| `QueueNum` after `QueueReady` | `QueueNum` before `QueueReady` (design §4.1) |
| a missing feature names the highest bit | offered `F_STATUS` → `MissingFeature(F_MAC)` |

Two more survivors are equivalent: `reported_mtu`'s `>` written `>=` (at 1500 both answer 1500), and the available ring's alignment (`place` is its only producer, so the ring is always 16-aligned).

The mtu check made before the generation compare has no kill: one needs the fake's config bytes to change with the generation. Its effect is that a torn mtu below 68 is refused rather than re-read.

**Asked:** these tests or your own, and a name for each equivalent.

## 6. The fake's own checks
Three of the fake's checks can be removed with every test still passing:
- `early_unmaps` never counted;
- the `QueueReady` address check;
- `config_read16`'s alignment refusal.

`check_address` checks the start address only (finding 1).

**Asked:** a control for each, as the stray-address and early-unpin checks have.

## 7. §7.4 rows and the design
- **Out-of-order completions:** design l.1770-1771, "only over the completed prefix". The tests check only that completions come back in device order (tests/queue.saw:171-190). Your note gives the prefix to pktring, but §7.4 lists the row under `drivers/virtio`. Either the design moves it to A3-4, which is the owner's call, or the library keeps the per-chain bookkeeping.
- **The queue memory is not zeroed.** §3.9's start row ("zero it"), §4.1 and §5.1 say to zero it. `setup_queues` stores only each ring's flags and idx and the TX header (lifecycle.saw:123-130, queue.saw:398-405), and `Dma` has no zero operation. Say in `Dma`'s contract whose job it is.
- **Two exit codes for one failure.** When `begin`'s own reset times out, `SetupError.exit_code()` answers 4. If the device then settles, `give_up(Refused)` answers 1. Make one of them the source.

## 8. Text and names
- **CLAUDE.md:153 is 103 columns,** left by the patch's reflow.
- **API names without abbreviations:** `EV_*`, `REG_*`, `val_at`, `arg_at`, `num_max`, and the labels `regs:` and `hw:`. virtio's own terms (`desc`, `avail`, `F_*`) are fair.
- **A builder is an `init`:** `Lifecycle.new()`, `Queue.new(…)` and `MemoryPlan.new(…)` should be `Lifecycle()`, `Queue(…)` and `MemoryPlan(…)`.
- **The `in_flight` mask is a `UInt32`** (queue.saw:217, 252, 287), one bit per chain. That silently ties `MAX_QUEUE` to at most 64 entries. State or check the tie.

## Checked and found right
Each of these has mutants that go red:
- the probe order and its refusals;
- the bounded reset, at its boundary;
- the status bit order;
- negotiation, with FEATURES_OK read back;
- config space read at each width;
- the bounded generation loop;
- the mtu floor;
- the interrupt ack;
- the layout's offsets and alignment for every size pair;
- every used-ring check at 64 entries, with the 16-bit wrap over 70,000 rounds;
- the barriers and notify suppression;
- each failure class's unpin after a confirmed reset, and none when the reset never completes;
- the exit codes 0 to 4.

**Lead: SO-163.p1 r2 answers r1's eight findings.**

**The named residual.** A `Queues` value is still usable after `give_up`. That is safe, because `give_up` unpins only after the reset is read back as 0, so a stale post or kick reaches a device that is reset. One correction to the note's reason: `Queues` and `give_up` live in the same module, lifecycle.saw, so a `give_up` that consumes a NoCopy `Queues` would need no import cycle. Its cost is that `give_up` is called before any `Queues` exists, so it would need a second form. That is a design choice, not a defect.

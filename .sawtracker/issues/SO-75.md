## Description

## Scope

SOS boots on the emulated ESP32-S3: an Xtensa architecture HAL and the S3
board, on the `Flat` protection tier, with a gating smoke.

- **The architecture half:** vectors and trap entry, the trap frame as the
  thread context, the `syscall` stub for user images, `resume_frame`, and the
  leaves the arch-free kernel calls through `hal`. `hal/riscv32-common` is the
  model for the split, and `hal/riscv32-flat` for the tier.
- **The board half:** boot, the console, the timer seam (`timer_now_ns`,
  `timer_set_deadline_ns`), the interrupt controller, the memory map and the
  linker scripts for the kernel, root and a child.
- **The harness:** `--board esp32s3` in `tools/sos_runner.py`, a
  `make sos-smoke-esp32s3` target, and the server's `tests.json`.
- **Smoke cases:** boot to the banner; a Timer fire reaches a process; a
  child is created, exchanges a pipe message and exits; two threads are
  preempted by the tick harness.

Every board fact comes from `hal/xtensa-esp32s3/ABI.md` (the probe unit).

**Lead, Nov 12: facts from the sawlang sweep (SL-1063), for these notes.**
- **call0** is the absence of the `windowed` feature. In C the spelling is
  `-Xclang -target-feature -Xclang -windowed`; Espressif's clang has no
  `-mabi`. Every SOS image is call0 and builds with `-fp`.
- **No call0 multilib exists:** libgcc, libclang_rt and the ROM's helpers are
  windowed, so no SOS image may call or link them. 64-bit divide comes from
  std's own helpers.
- **The trap frame:** compiled Saw code touches a0 to a15, SAR and SCOMPARE1.
  Save those, plus LBEG, LEND and LCOUNT until the compiler side rules out
  the `loop` instruction.
- **Word atomics are inline** (`wsr scompare1` + `s32c1i`), so the HAL sets
  ATOMCTL at boot. SO-73 probes the value.
- **Tools:** Homebrew's `ld.lld` can't link Xtensa; use the `ld.lld` beside
  Espressif's clang or `xtensa-esp-elf-ld`. Use the QEMU under
  `~/.espressif`, not the one on `PATH`.
- **Image format:** `SosimgArch` Xtensa = 3.
- **Triple:** the sweep recommends `xtensa-esp-unknown-elf` with the CPU
  named; the user decides.

(patch SO-73.p1) is the contract; section numbers below are its. The stub's

### 75a: the architecture's assembly and C

- **Build** (§1): `--target=xtensa-esp-elf -mcpu=esp32s3`, the two
  `-Xclang -target-feature` pairs for `-windowed` and `-fp`,
  `-fintegrated-as`, linked with the `ld.lld` beside Espressif's clang.
- **Boot** (§2): the magic words at flash 0x400 and 0x404, entry at 0x408.
  The ROM arrives windowed: reset `WINDOWSTART` and `WINDOWBASE`, clear
  `PS.WOE`, and park anything needed across the `WINDOWBASE` write in a
  special register, as the stub does. Then copy the vectors to IRAM, set
  `VECBASE`, copy `.data` and zero `.bss`.
- **Vectors** (§5a): lift the stub's table. `syscall` and level-1 interrupts
  arrive at the user vector; a fault with `PS.UM = 0` arrives at the kernel
  vector and is fatal; the window vectors are fatal under call0.
- **The frame** (§7c): the stub's layout, with `EXCSAVE1` holding the running
  thread's frame. Zero `LCOUNT` on entry (§7c says why).
- **`syscall`** (§5b): cause 1, `EPC1` at the instruction, return with
  `EPC1 += 3`. The user stub is `syscall` with the op and arguments in the
  registers the kernel's syscall accessors read; choose them to match how
  `hal/riscv32-common/user/syscall.c` passes its arguments.
- **Literals** (§1c): every output section lists `.literal*` before `.text*`.

### 75b: the `hal` facade

- **Tier:** `Flat` (§5e): the core has no privilege.
- **Timer seam** (§6): `timer_now_ns` from SYSTIMER at 16 MHz;
  `timer_set_deadline_ns` arms a TARGET0 one-shot (the periodic mode
  miscounts on the emulator). Route matrix source 57 to CPU interrupt 1.
- **Idle** (§6d): `waiti` cannot sleep with interrupts masked, and the kernel
  takes interrupts from user mode only. So `wait_for_irq` is empty, as on the
  C3 board, and `irq_poll` reads the `INTERRUPT` special register.
- **Console** (§4): UART0, one byte store.
- **Exit** (§10): `simcall` with SYS_exit under `-semihosting`, and the halt
  lines the C3 prints (`halt pass` / `halt fail code=…`) for the transcript.
- **Atomics** (§8): leave `ATOMCTL` as the ROM set it.
- **Watchdogs** (§2c, §11): nothing to do under the emulator; SO-76 adds the
  silicon handling.

### 75c: the board, the harness and the smoke

- **Memory** (§3a): IRAM from 0x4037_8000 and DRAM from 0x3FC8_C000 stay
  disjoint however silicon aliases them; keep out of
  0x4037_0000 to 0x4037_7FFF and of the ROM's RAM (§3b) while on its stack.
- **Read-only data:** link `.rodata` at its data-bus address (0x3C00_0000 +
  the flash offset), not in the instruction window. The ROM maps flash at
  both windows, and loading data through the instruction window is one of
  the things §11 says silicon may refuse.
- **The runner:** the flash image is 4 MiB of `0xFF` with each segment at
  `LMA - 0x4200_0000` (§1e); run with `-semihosting`; kill on a deadline.

**Split and models:** 75a and 75c are Sonnet units. 75b is Sonnet with this
list; if the seam turns out to need a design choice the list doesn't make,
it stops and asks. All three wait on SO-74.

**Lead, Nov 12: the triple is ruled (user, through the sawlang lead).**
- **Triple:** `xtensa-esp-unknown-elf`, which implies the ESP32-S3 CPU. Test
  packages name it in their manifests (`[sos.xtensa-esp-unknown-elf]`).
- **Default features:** `-windowed,-fp,-loop,-mac16,-bool`, with `s32c1i`
  on. So Saw objects are call0, use no FPU, and contain no loop, MAC16 or
  boolean-register instruction; word atomics are inline.
- `--target-features` adds to that default on this triple, so a package
  never needs to restate call0.
- The frame keeps LBEG, LEND and LCOUNT for C code and as insurance.
- C sinks that reach `__udivdi3` or a soft-float helper are satisfied by
  std's weak call0 definitions once Saw objects are in the link; a C-only
  image would have to supply its own.
- The sawlang lead posts the main sha when their unit that makes
  `sawc build --freestanding -c --target xtensa-esp-unknown-elf` write an
  object has merged (SL-1067). That sha is what 75a and 75c build against
  through `SAWLANG_ROOT` before SO-74's pin exists.

## First dispatch (lead, Nov 12): the kernel boots on the emulated ESP32-S3

This replaces the 75a/75b/75c split above for the first step. sawlang now
has a provisional compiler for the target, so the kernel can be built before
Blade can make a root image. One unit takes the kernel as far as it can go
without Blade; the user-process half follows when Blade's side lands.

**Model:** Opus. A first boot on a new architecture is debugging against an
emulator with no second opinion, and it is the week's critical path.
**Rules:** `.sawtracker/docs/implementer-rules.md`.

### The toolchain is provisional

- `SAWLANG_ROOT` is a sawlang checkout at an unreviewed commit that adds the
  target `xtensa-esp-unknown-elf` (the dispatch prompt gives the path). It
  writes Xtensa objects from Saw: call0, no FPU, no loop, MAC16 or boolean
  instructions, inline `s32c1i` atomics.
- It is not the pin, so the gate cannot build this unit yet. The deliverable
  is a commit in the worktree and a report. The lead uploads it after SO-74.
- Blade's architecture answer and the image format's Xtensa tag (3) are not
  in it. Nothing in this unit may need Blade for the S3.
- If the compiler refuses, crashes or miscompiles something, reduce it to a
  minimal repro, record it for the sawlang lead, and work around it only if
  the workaround is small and you say so. Otherwise stop and ask.

### Layout

One directory, architecture and board together, as `hal/arm64/` is:
`hal/xtensa-esp32s3/` with `kernel/` (`boot.S` with the vectors and the trap
entry, `sink.c`, `lib.saw`, `esp32s3.ld`) and `user/` (`syscall.c`, linker
scripts). The riscv32 split into a shared core and boards exists because two
boards share it; there is one Xtensa board.

### What to build

1. **The assembly and C,** lifted from the probe's stub (path in the dispatch
   prompt) and `hal/xtensa-esp32s3/ABI.md`, which is the contract: the boot
   sequence (§2), the vector table (§5a), one trap entry that saves the frame
   (§7c) and calls `ktrap`, the restore path, `resume_frame`, and the leaves
   `lib.saw` needs for special registers. `hal/riscv32-common/kernel/trap.S`
   and `sink.c` show what each piece owes the arch-free kernel.
2. **`kernel/lib.saw`, the `hal` module.** Its public surface is whatever
   `kernel/core/` and `kernel/main.saw` import from `hal`. Use
   `hal/riscv32-esp32c3/kernel/lib.saw` and the `rv32core` module it
   re-exports as the checklist, name by name, and
   `hal/riscv32-flat/kernel/lib.saw` for the protection seam on a tier that
   cannot deny: `prot_isolated()` is false and the `prot_*` calls install
   nothing. Board facts come from `ABI.md`: the console (§4), SYSTIMER at
   16 MHz for `timer_now_ns` and a TARGET0 one-shot for
   `timer_set_deadline_ns` (§6), matrix source 57 routed to a level-1 CPU
   interrupt, `wait_for_irq` empty and `irq_poll` reading the `INTERRUPT`
   register (§6d), `ATOMCTL` left as the ROM set it (§8), the exit through
   `simcall` under `-semihosting` plus the halt lines the C3 prints (§10).
   The FP seam is three no-ops: no thread may use the FPU on this profile.
   `arch_tag()` answers 3.
3. **The linker script,** from the stub's and §1c, §3: text and literals in
   the flash instruction window with every `.literal*` before its `.text*`;
   `.rodata` at its data-bus address (0x3C00_0000 plus the flash offset);
   vectors in IRAM; `.data`, `.bss`, the arena and the stacks in DRAM,
   keeping clear of the ranges §3a and §3b name.
4. **The harness:** a `--board esp32s3` section in `tools/sos_runner.py`
   beside the `esp32c3` one, which is the model in every respect (its own
   build directory, the Espressif tools found under `~/.espressif`, a clear
   error and exit 2 when one is missing, stderr dropped, a deadline). Run
   QEMU with `-semihosting`. Add `make sos-smoke-esp32s3`.
5. **Smoke cases that need no Blade:**
   - `boot`: the kernel's banner, then whatever the kernel says when the
     image carries no root, as the C3's `boot` case does;
   - a first entry to user mode, a syscall and its return, and a timer
     interrupt taken from user mode, using a hand-assembled user payload in
     the image's `.payload` section. The tree has kernel entries under
     `tests/` that load such payloads on the `virt` boards; find the smallest
     and write its Xtensa payload under `tests/xtensa/`;
   - a harness kernel that arms the tick, as the C3's `timer` case does, if
     it runs without a user image.
6. **Docs:** `hal/xtensa-esp32s3/README.md`, as the C3's; spec §5b names the
   profile and states its tier is `Flat`; the README and CLAUDE.md repo maps
   gain the directory. Don't add the smoke to `.sawtracker/tests.json` yet:
   the gate can't build it until the pin moves, and the lead adds it then.

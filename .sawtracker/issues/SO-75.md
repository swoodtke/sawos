## Description

## Scope

SOS boots on the emulated ESP32-S3: an Xtensa architecture HAL and the S3
board, on the `Flat` protection tier, with a gating smoke.

- **The architecture half:** vectors and trap entry, the trap frame as the
  thread context, the `syscall` stub for user images, `resume_frame`, and the
  leaves the arch-free kernel calls through `hal`. `hal/riscv32-common` is the
  model for the split, and `hal/riscv32-flat` for the tier.
- **The board half:** boot, the console, the timer seam (`timer_now_ns`,
  `timer_set_deadline_ns`), the interrupt controller, the memory map and the
  linker scripts for the kernel, root and a child.
- **The harness:** `--board esp32s3` in `tools/sos_runner.py`, a
  `make sos-smoke-esp32s3` target, and the server's `tests.json`.
- **Smoke cases:** boot to the banner; a Timer fire reaches a process; a
  child is created, exchanges a pipe message and exits; two threads are
  preempted by the tick harness.

Every board fact comes from `hal/xtensa-esp32s3/ABI.md` (the probe unit).

**Lead, Nov 12: facts from the sawlang sweep (SL-1063), for these notes.**
- **call0** is the absence of the `windowed` feature. In C the spelling is
  `-Xclang -target-feature -Xclang -windowed`; Espressif's clang has no
  `-mabi`. Every SOS image is call0 and builds with `-fp`.
- **No call0 multilib exists:** libgcc, libclang_rt and the ROM's helpers are
  windowed, so no SOS image may call or link them. 64-bit divide comes from
  std's own helpers.
- **The trap frame:** compiled Saw code touches a0 to a15, SAR and SCOMPARE1.
  Save those, plus LBEG, LEND and LCOUNT until the compiler side rules out
  the `loop` instruction.
- **Word atomics are inline** (`wsr scompare1` + `s32c1i`), so the HAL sets
  ATOMCTL at boot. SO-73 probes the value.
- **Tools:** Homebrew's `ld.lld` can't link Xtensa; use the `ld.lld` beside
  Espressif's clang or `xtensa-esp-elf-ld`. Use the QEMU under
  `~/.espressif`, not the one on `PATH`.
- **Image format:** `SosimgArch` Xtensa = 3.
- **Triple:** the sweep recommends `xtensa-esp-unknown-elf` with the CPU
  named; the user decides.

### 75a: the architecture's assembly and C

- **Build** (§1): `--target=xtensa-esp-elf -mcpu=esp32s3`, the two
  `-Xclang -target-feature` pairs for `-windowed` and `-fp`,
  `-fintegrated-as`, linked with the `ld.lld` beside Espressif's clang.
- **Boot** (§2): the magic words at flash 0x400 and 0x404, entry at 0x408.
  The ROM arrives windowed: reset `WINDOWSTART` and `WINDOWBASE`, clear
  `PS.WOE`, and park anything needed across the `WINDOWBASE` write in a
  special register, as the stub does. Then copy the vectors to IRAM, set
  `VECBASE`, copy `.data` and zero `.bss`.
- **Vectors** (§5a): lift the stub's table. `syscall` and level-1 interrupts
  arrive at the user vector; a fault with `PS.UM = 0` arrives at the kernel
  vector and is fatal; the window vectors are fatal under call0.
- **The frame** (§7c): the stub's layout, with `EXCSAVE1` holding the running
  thread's frame. Zero `LCOUNT` on entry (§7c says why).
- **`syscall`** (§5b): cause 1, `EPC1` at the instruction, return with
  `EPC1 += 3`. The user stub is `syscall` with the op and arguments in the
  registers the kernel's syscall accessors read; choose them to match how
  `hal/riscv32-common/user/syscall.c` passes its arguments.
- **Literals** (§1c): every output section lists `.literal*` before `.text*`.

### 75b: the `hal` facade

- **Tier:** `Flat` (§5e): the core has no privilege.
- **Timer seam** (§6): `timer_now_ns` from SYSTIMER at 16 MHz;
  `timer_set_deadline_ns` arms a TARGET0 one-shot (the periodic mode
  miscounts on the emulator). Route matrix source 57 to CPU interrupt 1.
- **Idle** (§6d): `waiti` cannot sleep with interrupts masked, and the kernel
  takes interrupts from user mode only. So `wait_for_irq` is empty, as on the
  C3 board, and `irq_poll` reads the `INTERRUPT` special register.
- **Console** (§4): UART0, one byte store.
- **Exit** (§10): `simcall` with SYS_exit under `-semihosting`, and the halt
  lines the C3 prints (`halt pass` / `halt fail code=…`) for the transcript.
- **Atomics** (§8): leave `ATOMCTL` as the ROM set it.
- **Watchdogs** (§2c, §11): nothing to do under the emulator; SO-76 adds the
  silicon handling.

### 75c: the board, the harness and the smoke

- **Memory** (§3a): IRAM from 0x4037_8000 and DRAM from 0x3FC8_C000 stay
  disjoint however silicon aliases them; keep out of
  0x4037_0000 to 0x4037_7FFF and of the ROM's RAM (§3b) while on its stack.
- **Read-only data:** link `.rodata` at its data-bus address (0x3C00_0000 +
  the flash offset), not in the instruction window. The ROM maps flash at
  both windows, and loading data through the instruction window is one of
  the things §11 says silicon may refuse.
- **The runner:** the flash image is 4 MiB of `0xFF` with each segment at
  `LMA - 0x4200_0000` (§1e); run with `-semihosting`; kill on a deadline.

**Split and models:** 75a and 75c are Sonnet units. 75b is Sonnet with this
list; if the seam turns out to need a design choice the list doesn't make,
it stops and asks. All three wait on SO-74.

- **Triple:** `xtensa-esp-unknown-elf`, which implies the ESP32-S3 CPU. Test

**Lead, SO-75.p1: item 1's mechanism changed before it was built.** The
plan above gave a CPU interrupt back on every mask, by unrouting the line.
The implementer probed that on the gate's emulator first and found it
loses fires and invents them there:

- the installed build's matrix model (`qemu-xtensa`
  `esp_develop_9.2.2_20250817`) stores a route write and changes no CPU
  interrupt's level, and sends a source's level only to the CPU interrupt
  it is routed to at that moment. So a still-asserting source routed to a
  new CPU interrupt does not raise it, and a CPU interrupt freed from an
  asserting source stays high for the next line to take;
- Espressif's later model drives each CPU interrupt as the OR of its
  sources, which is what silicon's combinational matrix does. The installed
  build predates it.

**What is being built instead:** a mask keeps the line's route and
assignment and only disables at `INTENABLE`. An unmask reuses the line's
own CPU interrupt, else takes an unassigned one, else takes one back from a
masked line, preferring one not pending. The stop is then reachable only
with more lines unmasked at once than there are CPU interrupts, which the
Interrupt slab rules out. The same cases and the same mutant hold. What a
take-back can cost on the installed emulator, and that it costs nothing on a
combinational matrix, goes into the function's doc and `ABI.md` §6c with
the probes.

A compile-time assert of the slab against the board's count would need a
constant in every other HAL, so it is not added.

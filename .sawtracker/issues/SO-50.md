## Description

## Ruled design (user, Nov 9)

A new `SystemRight.ProcessObserve` gates two System ops:
- `ProcessNext(cursor)`: iterate processes for a ps-style tool, answering one
  process's handle and the next cursor.
- `ProcessByPid(pid)`: the only op that accepts a pid (pid issue). A pid that
  no longer names a process answers a status.

Both mint the **observe set** (`Wait | Stats`), capped by the caller's ceiling
(SO-40), the same set as the sender handle. The lookup is the indexed form of
the walk, so it adds no authority beyond the iteration.

Ordinary servers identify clients through the sender handle without this right;
only system tools (ps, a debugger) hold it.

To settle in the brief: whether `Gone` processes appear in the iteration, and
the status for an unknown pid.

## Sequencing

After the pid issue. The brief is written at dispatch.

## Implementation notes (lead, Nov 12)

Two dispatches, after SO-49 merges. **Rules:**
`.sawtracker/docs/implementer-rules.md`.

### Step 1: the spec (Opus, or the lead; the user reviews before step 2)

A spec-only patch. It settles:
- `SystemRight.ProcessObserve` (`kernel/abi/src/rights.saw`) and the two
  `SystemOp`s (`kernel/abi/src/ops.saw`);
- `ProcessNext(cursor)`: the cursor's type and start value, the end status
  (the boot-set drain answers `Drained`), and what happens when a process is
  created or reclaimed mid-walk;
- whether `Gone` records appear in the walk. Lead proposal: yes, while a
  reference still names them, since a ps wants to show a zombie; the user
  rules;
- `ProcessByPid(pid)`: the status for a pid that names no record;
- both mint the observe set (`Wait | Stats`), capped by the caller's ceiling.

### Step 2: the implementation (Sonnet, from the merged spec)

- The walk is a scan of `PROCESS_RECORDS`, as `drain_unstarted`
  (`kernel/core/sched.saw`) scans it.
- The ops sit beside `ProcessSelf` and `ProcessCreate` in the System arm of
  `kernel/core/dispatch.saw`.
- The mint goes through the same capped mint SO-49's sender handle uses.
- sysapi: `System.process_next` and `System.process_by_pid` in
  `kernel/sysapi/src/system.saw`.
- Tests as the description lists, plus: a System handle without the right
  faults; the observe handle's `rights()` is exactly the observe set.

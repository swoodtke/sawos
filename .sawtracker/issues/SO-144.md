## Description

`kernel/sysapi/src/lib.saw`'s module doc says `System`'s and `Process`'s
handle fields "stay private because only their own module touches them", but
at the pin a bare field of a public struct is public: `p.handle` on a
`Process`, and `s.handle` on a `System`, typecheck from a package outside
`sos` (`system.saw`'s `handle` fields). The reviewer found it while probing
SO-124's design (thread t6 of `SO:sosmain-startup`).

A process can therefore read the raw word and hand it to the floor directly,
past the wrapper's discipline (its rights checks, the parked boot word).

Fix: make both fields private (or `public(package)` if a sibling needs them),
then check that nothing outside `sos` reads them (the stock root, drivers,
tests, the product template); a reader that needs the word gets a named,
documented accessor. The doc's sentence then stays true. If sawlang's rule
for a bare field is meant to be "public", say so in the doc instead.

**Lead: SO-144.p1: the handle words inside `sos`'s wrappers cannot be read from outside `sos`.** One commit on b77c8d44, rebased by the lead onto current main without conflict. Gate against a baseline at b77c8d44: sos-test 1333 → 1336 (`handle_fields_sealed` on three profiles), S3 206 = 206; with row numbers masked, only those rows, the total and one S3 flash size (`console_service`, −16 bytes) moved. Images: most move by bytes at the same size, because comment lines added above `bootset.saw`'s and `system.saw`'s code shift the source line numbers baked into `__saw_fail*` calls and debug metadata (checked by building `tests/child-main` from the commit's and the base's three files: every IR difference is a line-number argument or `!dbg`); on Xtensa one constant took a shorter encoding.

**Made private:** `System.handle`; `Process.names_caller` (it was written `private` but was public, see below); `BootSet.records` and `BootSet.count`; all 14 `BootHandle` wrapper slots (`memory`, `pool`, `process`, `system`, `iomemory`, `inlet`, `outlet`, `reply`, `request`, `event`, `thread`, `waiter`, `timer`, `interrupt`), which only `system.saw` builds or reads. **`public(package)`:** `Process.handle` (`bootset` reads it in the drain and in `heap_process`). The doc comments say each field's marker and why; `lib.saw`'s module doc lists the `public(package)` wrapper fields (Pool added), the private ones, and that a bare field of a `public` struct is public. **Swept and left:** the other wrappers' `handle` fields, `PipeHandles`' and `StatsRegion`'s internals (already `public(package)`, which holds even below a `///` comment); `ThreadBlock.thread` (already private); and the plain-data fields public on purpose (`BootEntry`, `HeapInfo`, `PoolAvailable`, `BootHandle.tag`/`.kind`, `PipeMsg`'s, `WaitResult`'s, `ProcessStats`, `QuotaRow`, `StatsRegion`'s base, rows and self row). **No reader outside `sos`** (root, `rt/main`, `rt/common`, drivers, tests including `heapkit`, the template and the product fixture); no accessor needed.

**A compiler bug, worked around here, and reported to the sawlang lead:** at the pin, `private` on a field with a `///` doc comment directly above it is ignored, so the field stays public (`public(package)` is unaffected). In this tree that made `Process.names_caller` public: a process could set it on a `Process` naming another process and get past `thread_create(run:)`'s self-only check. The patch writes the notes above `names_caller` and every `BootHandle` slot as `//` (each struct has one comment saying why, pointing at the test); no other `///` sits above a `private` field in the tree.

**Test:** `tests/handle-sealed` (`handle_fields_sealed`, an `expect_build_error` case on the three gate profiles) reads `System.handle`, `Process.handle`, `Process.names_caller`, `BootSet.records[0]` and `BootHandle.memory`, and asserts all five refusals ("`<type>` has no member `<field>` this module can see"). **Mutants** (built with Blade for riscv32): each field made bare drops its own refusal; `memory`'s note turned back into `///` with `private` kept drops its refusal (the compiler bug); all bare compiles.

# Brief: pin sawlang v0.20.0

You are moving sawos's sawlang pin from 0.8.0 to **v0.20.0**, the first
release in which sawlang's compiler is self-hosted. The lead wrote this
brief. **If it is wrong, contradicts what you find, or leaves a decision you
can't make from it, STOP and end your turn with a message beginning
`CLARIFICATION REQUEST:` and the exact question.**

The changes, and why:

1. **`sawlang.pin`:** `version = "0.20.0"` and `sha =
   "17431561a91cd470e2a9270973b333aa02092ed7"`, the COMMIT sha. The tag
   object `e8f0e9ca…` is not a commit. Change both lines together, and update
   the comment above them only if it is now false.
2. **`tools/toolchain.py`:** replace it verbatim with sawlang v0.20.0's
   `tools/toolchain.py`. sawos's copy recognises a checkout by
   `sawc/sawc.py`, which v0.18.0 deleted. The file travels verbatim between
   the two repos: don't edit it.
3. **`tools/sos_runner.py`:**
   - `_build_blade` adds `--module-path blade=<root>/blade/src`, because
     Blade is a multi-module package now.
   - The `task_dump` / `task_dump_empty` expectation strings carry the
     `taskdump.saw:NN` / `taskdump_empty.saw:NN` line numbers. Update them
     to the new lines after change 7, and check each against the file.
4. **`chars()` → `scalars()` (0.11.0):** 8 sites, plus `sosrt.ascii_byte`
   now takes a `Scalar` and calls `.value()` (`rt/common/src/lib.saw`). The
   sites are in `hal/arm64/kernel/lib.saw`, `kernel/core/diag.saw`,
   `kernel/sysapi/src/system.saw`, four UART test programs and
   `tests/uartproto/src/lib.saw`.
5. **`kernel/core/slab.saw` `Slab.[]`:** `@synthesize(shared)` plus
   `(&var self, i: Int) unsafe borrows -> &var T`. A bare `borrows -> T`
   is refused (SL-916; it caused about 3,500 errors), and `&var self`
   without `@synthesize(shared)` makes every read an exclusive window (645
   errors). **Rewrite that accessor's doc comment** under the comment
   rules (no design or issue references; say what the accessor does and why
   reads stay shared). It was the one doc the cleanup deliberately skipped.
6. **`rt/common/src/lib.saw`:**
   - `__saw_rt_write` returns `Int` (0).
   - Add `__saw_rt_write_line(parts, count) -> Int`: it writes `count`
     `{ptr, len}` pairs at **the target's word size** (the survey's first
     version hard-coded 4 bytes and broke arm64), then a newline.
   - Add `__saw_rt_last_raw_code() -> Int` returning 0: SOS has no errno.
   - Replace the string-literal-as-pointer at the panic path with
     `.c_string()!`.
   - Check every signature against sawlang v0.20.0's `runtime/ABI.md`. The
     build checks the seams, so a wrong one fails loudly.
7. **`tests/taskdump.saw` and `tests/taskdump_empty.saw`** (the
   `--runtime-provider` cases):
   - Port `reactor_create`, `reactor_register` and `reactor_poll` to their
     v0.20.0 signatures.
   - Add `thread_executor` / `set_thread_executor` (one `unsafe static var`
     word: SOS is single-threaded per executor here).
   - Add `output_lock` / `output_unlock` as no-ops.
   - Add `write_error`, which writes to the console: on SOS, stderr is the
     console.
   - `reactor_register` must return a NONZERO status, never 0. SOS has no
     reactor, so claiming an arm would park a task forever. Return `-16`:
     ABI.md's portable tag table has no "unsupported" tag, and ENOSYS falls
     under tag 16, `Other` ("any other errno"). Say so in a one-line
     comment.
8. **`hal/arm64/kernel/lib.saw`, two shifts:** `(1 as UInt32) << (...)`.
   A literal in `1 << x` no longer adopts `UInt32` from context.
9. **`tests/thread-preempt/src/main.saw`:** split the one-line catch body
   (`let _ = proc.exit(0)  return`) across lines in the tree's guard shape.
   Two statements on one line are refused.

## Description

**Move the sawlang pin from v0.23.0 to v0.24.0.** The sawlang lead tagged it on Nov 14: `24442cc9ae3c08e30ade41eee4e0c0053187c3dc`, `sawc --version` there says `sawc 0.24.0`. It carries Blade's `--linker-script`, `--out-dir` and `--module-path` (which the builder's generated link scripts need), the scratch-file fix for two builds to one output, and fixes for holes this tree has been working around.

**What is built.**
- `sawlang.pin`: both lines together, the version and the sha, as the file's own comment requires. Check the pair against a fetch: resolve the toolchain by fetch (no `SAWLANG_ROOT`), and `sawc --version` in the fetched checkout must print the version the pin names.
- Whatever the new compiler refuses or changes in this tree, fixed in the same patch. The sawlang lead's list of what a project moving from v0.23.0 should expect (the full list is the description of sawlang's SL-1127):
  - **Can refuse code that built:** a list literal against an array length that is not a known constant (SL-1115); a const generic value that faults, is negative or does not fit at an instance (SL-457); `@synthesize` over a field that does not meet the trait (SL-925); Blade now refuses a flag or word it does not know, on every subcommand (check every `blade` invocation the runner, the Makefile and the builder make).
  - **Changes meaning with no source change:** a lone raw-backed error enum's case in an erased `Result` slot is now `Err` where it was `Ok(raw)` (SL-1090). Sweep every `.saw` file for a function returning `Result<_, Box<any Error>>` (or another erased error) that returns a bare enum case, and every caller that worked around the old meaning by binding first or casting; say what you found, and remove a workaround only where the new meaning makes it dead.
  - **riscv32 with no `--target-features` now states `+m,+a,+c`:** the objects should be what clang's default already built, but riscv32 image sizes may move. The gate's report prints image sizes; diff the report against main's and explain every size that moves.
  - `kernel/core/limits.saw`'s derived lengths and static_asserts: with SL-457 in, a `static_assert` that reads a size through a static is checked; confirm each still holds and that none was silently unchecked before in a way that hid a false one.
- **Not fixed in v0.24.0:** an owning Optional on the left of `==` or `!=` with a bare non-literal right side is still miscompiled (SL-1124). The tree has no such comparison; check again at the new pin and say so.
- `CLAUDE.md` and any doc that names the pinned version, where it does.
- Blade's up-to-date check still misses some inputs until sawlang's SL-1102, so every `--force` the runner passes stays.

**The oracle.** The gate at the new pin, resolved by fetch as the server does: `make sos-test sos-smoke-esp32c3 sos-smoke-esp32s3`, with the console transcripts and the report diffed against a run of main at the old pin, not just read as green. Anything that moves in that diff is a finding to explain (image sizes on riscv32 are expected; nothing else is).

**Not in this unit:** using the new Blade flags (the builder's generated link scripts are their own unit), or removing the Python image path.

## Description

**ESP32-S3: the CPU at 160 MHz, then 240 MHz.** `pll80` (SO-113) runs the CPU from the PLL at 80 MHz; `hal/xtensa-esp32s3/ABI.md` §14c says what 160 and 240 add. The owner ruled on Nov 16: ramp the speed, 160 first, then the full 240, then the flash (a separate issue). The LDO writes are approved by that ruling.

**Two patches, each with its own board run before it merges:**
1. **160 MHz:** a key `pll160` beside `pll80`: CPUPERIOD_SEL 1 at Q3, the digital LDO set to ESP-IDF's `g_dig_dbias_pvt_non_240m` as `rtc_init` does before 160 is reached (the bootloader's 80 never does), the slaves as §14c says (all six on as the ROM leaves them). `kill_churn` and `kill_churn_profile` on the board at 160, beside 80's numbers in §14h.
2. **240 MHz:** a key `pll240`: CPUPERIOD_SEL 2, the PLL at 480 MHz, the digital and RTC LDO raised through I2C_DIG_REG (block 0x6D) to the eFuse calibration values ESP-IDF reads (Q1; the eFuse reads are reads only, never a write or a burn), and put back when leaving it (X6, Q7). The same board measurements at 240.

Each patch: the emulator's trace of every register write the bring-up makes, checked against ESP-IDF's sequence with its version cited; a case per stop (a PLL that does not lock, a calibration value out of range); ABI.md §14 brought up to date (§14c's "not built" text, §14d's "OPTIONS0's three bits read 0 before every run" fixed at the first of them). The flash stays 20 MHz at every CPU speed (§14c). Board requests through the reviewer under the owner's standing approval: the image's device writes traced in the emulator first; the only write is `write-flash 0x0` of the image; no eFuse burn or write, no erase.

**Review standard (the owner's ruling, Nov 15):** every check and stop has a case that goes red when it is removed or inverted; list the mutants.

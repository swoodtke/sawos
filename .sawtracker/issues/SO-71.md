## Description

## Ruling (user, Nov 12)

The kernel must be able to take the processor away from a process that keeps
running. The shipping kernel arms a scheduler tick.

## Where the tree stands

- `kmain` (`kernel/main.saw`) arms no timer. Spec §7 says so: "No shipping
  kernel image arms the tick". A process that never makes a syscall holds the
  machine until it faults or the power goes.
- The mechanism is built and tested. `start_tick` (`kernel/core/time.saw`)
  arms the periodic tick; `on_timer_tick` (`kernel/core/irq.saw`) charges the
  running thread's slice (`SLICE_TICKS`) and raises `NEED_RESCHED`; the switch
  happens at the user-return boundary. Only harness kernels call `start_tick`
  (`tests/threads_timer.saw`, `preempt_tick.saw`, `timer.saw`,
  `timer_mask.saw`), and `thread_preempt` asserts the crossings.
- So this unit turns an existing mechanism on. It adds no scheduler. Priorities
  and the band map (§7) stay not built: the ready queue is one round-robin
  FIFO.

## What arming it has to settle

1. **The period.** §7 gives a provisional 10 ms timeslice. Name the constant
   and say where a board may override it.
2. **The tick report.** `on_timer_tick` prints `SOS: timer tick N at PC` for
   the first `TICK_REPORT_LIMIT` ticks. In a shipping kernel that is the
   kernel narrating over a process after handover, which §9a forbids and
   which would land in every transcript at a host-dependent place. The report
   becomes something only the harness kernels turn on.
3. **The suite's determinism.** With a tick, where a switch lands depends on
   host timing. The unit starts with an inventory: which cases print from more
   than one thread or process and assert an order that only cooperative
   scheduling gives. `debug_print` traps once per byte (SO-9), so a preempted
   line can be split by another process's bytes. The inventory decides whether
   SO-9 (one trap per line) is a prerequisite, and which cases need a
   projection like `thread_preempt`'s. No case may be weakened to pass.
4. **The deadlock predicate** (§7, §9). The kernel idles only if something
   outside the thread set can still wake somebody, and reports deadlock
   otherwise. The tick is not such a thing: with every thread blocked and no
   bound line or armed Timer, the machine is still deadlocked.
5. **Idle.** With nothing runnable the tick keeps firing. Say whether the idle
   path stops it, or leave tickless idle as a named later step.
6. **SO-42 lands first.** The sosrt bump arena takes no lock, and its race
   needs exactly this: two threads of one process preempted inside the cursor
   update.
7. **The ESP32-C3 board.** Its `wait_for_irq` is empty and its idle loop
   polls. The smoke must still pass.

## Spec and docs

§7 ("No shipping kernel image arms the tick"), §9a's bounded exception, §11's
known limit on the arena ("today only the preemption harness"), the comment in
`kmain`, and the arena comment in `rt/common/src/lib.saw`.

## Step 1 result: the inventory (lead, Nov 12)

A scratch kernel armed the tick in `kmain` and kept the tick report to the
harness kernels. Nothing was committed. The lead checked the failure counts
below against the run logs.

### What the runs showed

| Run | Result |
|---|---|
| Unmodified main, full suite | 588 passed |
| Tick at 10 ms, full suite, three runs | 2, 6 and 1 failed |
| Tick at 10 ms, C3 smoke, three runs | passed each time |
| Tick at 1 ms, full suite, one run | 36 failed |
| Tick at 1 ms, C3 smoke, three runs | failed, failed, passed |

- **No case failed twice at 10 ms.** Nine failures over three runs, eight
  different cases: the failures are timing, and any run can lose any of them.
- **Almost all are console order.** Two processes or threads are both ready
  for a short window, and the tick decides which prints first. The case
  asserts the order cooperative scheduling gives.
- **Three are split lines.** `debug_print` traps once per byte, so one
  process's line is cut in the middle by another's, or by the kernel's own
  exit line. No per-case matching can repair that; it needs SO-9 (one trap
  per line).
- **A few assume run-to-completion,** not just print order: `thread_slots`
  yields once and expects every worker to have finished. `thread_give`,
  `thread_basics` and `fp_threads` at 1 ms look the same (inferred from the
  failure, not read).
- **Not affected:** deadlock is still reported (`wait_deadlock` and
  `timer_deadlock` passed in every run), no case's asserted count moved, and
  nothing hung. Wall time is within noise.
- **A kernel defect on the ESP32-C3.** At 1 ms the smoke dies with
  `SOS-C3: kernel fault mcause=0x80000007`: the timer interrupt is taken in
  kernel mode, while the kernel is still loading root. At 10 ms it passes
  only because the load usually finishes first. The tick must not be able to
  fire before the first entry to user mode, on any board.
- **A correction to the notes:** a `public(package)` flag does not reach the
  harness kernels in `tests/`, which are outside the `kcore` package. The
  report flag needs a public setter.

### Decision for the user: how the suite stays deterministic

- **(A) Fix the cases.** The gate keeps running the shipping kernel, tick
  armed. SO-9 lands first; then each affected case stops asserting an order
  the scheduler no longer guarantees (wait for the child, or match each
  process's lines separately). About forty cases to audit. Several units.
- **(B) Two kernel entries.** The shipping kernel arms the tick. The suite's
  existing cases boot an entry that differs by that one call and arms none,
  so their transcripts stay exact; a new group of cases boots the shipping
  entry and asserts preemption. Small, and it lands this week. The cost: most
  of the gate then runs a kernel that is one line away from the shipping one.
- **(C) Change the slice rule** so a thread is charged only while another is
  ready, with a long slice. Fewer failures, but a stalled host can still
  flip a case, so it does not make the suite deterministic on its own.

Lead recommendation: (B) now, with the C3 fix, and (A) as the follow-up that
retires the second entry. Step 2's notes are written when the user rules.

## Step 2 notes (lead, Nov 12): arm the tick, with a boot option that turns it off

**User direction (Nov 12):** one kernel; the tests pass it an argument that
disables the tick, and everything else omits the argument and gets the tick.
This replaces the "two kernel entries" option above.

**Model:** Sonnet. **Rules:** `.sawtracker/docs/implementer-rules.md`.
**Depends on:** SO-42 merged.

### Where the argument lives

The kernel has no command line. The two `virt` boards boot with
`-bios none -kernel` and the kernel reads no device tree; the ESP boards boot
from flash with nothing passed at all. What every board already has is the
**build-emitted region table**: the stitcher writes it into the image's
`.regions` section and the kernel reads it at boot through
`hal.region_table_start()` and `hal.region_table_end()`
(`kernel/core/process.saw`). Its header is a magic word, a version, a row
count and one reserved byte (`tools/sos_runner.py`, where the `.regions`
stub is generated; `REGION_TABLE_MAGIC`, `REGION_TABLE_VERSION`).

The boot option goes in that header:
- The reserved byte becomes a **boot flags** byte. Bit 0 is "no tick".
- Bump `REGION_TABLE_VERSION` and its kernel-side twin together.
- **An image with no table, or with the flags byte zero, gets the tick.** So
  a hand-built system and the box get it by default, and only an image that
  asks is cooperative.

### Kernel

1. Parse the flags where the header is parsed, and keep them where `kmain`
   can ask (`kernel/core/process.saw` reads the table; add a small accessor
   and re-export it from `kernel/core/lib.saw`).
2. `kmain` (`kernel/main.saw`) arms the tick unless the flag is set. The
   period is a named constant beside `SLICE_TICKS`
   (`kernel/core/threads.saw`): 10 ms, per spec §7.
3. **The tick must not be able to fire before the first entry to user mode.**
   The inventory found the ESP32-C3 taking the timer interrupt in kernel mode
   while root was still loading (`SOS-C3: kernel fault mcause=0x80000007`).
   Arm it at the last step before the first `hal.resume_frame`, not before
   the load. Then read the C3 board's boot code and say in your report
   whether kernel mode there can take an interrupt at any other time. If it
   can, stop and ask.
4. The tick report (`SOS: timer tick …` in `on_timer_tick`,
   `kernel/core/irq.saw`) prints only when a harness kernel turned it on. A
   `public(package)` flag does not reach `tests/*.saw`, so use a public
   setter re-exported from `kernel/core/lib.saw`, called by the four harness
   kernels (`tests/threads_timer.saw`, `preempt_tick.saw`, `timer.saw`,
   `timer_mask.saw`) before their `start_tick`. The inventory's scratch diff
   shows the shape; the dispatch prompt gives its path.

### Harness

1. `tools/sos_runner.py` writes the flags byte as "no tick" for every case
   by default, in both the `virt` stub and the ESP32-C3 one.
2. A case key, `"tick": True`, writes zero instead, so that case boots with
   the tick.
3. Existing cases must not move: diff the full report against main's.

### New cases, all with `"tick": True`

- `tick_spinner`, three profiles: root creates a child that spins forever
  with no syscall, arms a Timer, waits for its fire, prints one line and
  shuts the machine down. Without preemption the child would hold the
  processor forever.
  - Mutation: set the "no tick" flag for this case; it must run into the
    harness timeout and fail.
- A C3 smoke case with the tick armed, to hold item 3 above.
  - Mutation: arm the tick before the load instead; the case must fail with
    the kernel fault. If you can't make it fail reliably, say so and say how
    often it did.

### Spec and docs

- §7: replace "No shipping kernel image arms the tick" with the rule: the
  kernel arms the tick unless the image's boot flags say not to.
- §5.6 and §12, where the region table is specified: the flags byte and the
  version.
- §9a: the tick report is a harness kernel's, never the shipping kernel's.
- §11: the arena limit's "today only the preemption harness".
- The comment in `kmain`, and the arena comment in `rt/common/src/lib.saw`
  if SO-42's text still says no shipping kernel arms a tick.
- `hal/riscv32-esp32c3/ABI.md` if what you learn about kernel-mode
  interrupts there belongs in it.

### Not in this unit

SO-9 (one trap per line) and making the existing cases order-robust under a
tick. They become a follow-up: the day every case passes with `"tick": True`,
the default flips and the flag is only for a case that needs it.

### Runs

The full suite on three profiles, report diffed against main's; the new
cases 20 times each on riscv32; the C3 smoke three times.

**Commit:** `kernel: the tick is armed unless the image's boot flags turn it off`

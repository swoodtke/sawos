## Description

## Scope

The root image for the box: it collects its boot handles, launches the GPIO
and PWM drivers and a controller task, and the controller turns the switch
back off whenever it is turned on.

- The controller waits on the switch through the GPIO driver, commands the
  servos through the PWM driver, and uses a Timer for the arm's travel and for
  debouncing.
- A second simple task runs beside it (a heartbeat on the console or an LED),
  so the box shows more than one process sharing the machine.
- The motion sequence is data in the controller, so a new behaviour needs no
  driver change.

## Acceptance

- [ ] on the board: flip the switch and the arm flips it back, repeatably
- [ ] under QEMU: a smoke case drives the controller with a simulated switch
      edge and asserts the PWM requests it makes

## Implementation notes (lead, Nov 12)

**Model:** Sonnet. **Rules:** `.sawtracker/docs/implementer-rules.md`.
**Blocked on:** SO-77.

### Needed from the user first

How the box should behave: one arm or also a lid; the arm's rest and push
angles (found on the bench with the PWM driver); any personality (delays,
feints).

### The root image (`tests/useless-box/` unless the user wants it in `root/`)

1. Root drains its boot set, creates the GPIO driver, the PWM driver and the
   controller as child processes, binds the GPIO line and gives each driver
   its window and line and each client its connection end.
   `tests/uart-service/` is the model for a root that launches a driver and a
   client and wires them with boot tags.
2. Root then supervises: it waits on each child's death and prints which one
   died.

### The controller

- Waits for the switch's edge through the GPIO driver.
- Debounces with a Timer: read the pin again after the settle time and act
  only if it still reads "on".
- Plays the motion sequence through the PWM driver: a table of
  `{channel, pulse width, hold time}` steps, with a Timer between steps.
- Returns the arm to rest and waits again.
- The sequence is a `static` table, so a new behaviour changes data only.

### The second task

A heartbeat process that prints a line, or toggles an LED through the GPIO
driver, on its own Timer. It shows two processes sharing the machine while
the controller is parked.

### Tests

- Under QEMU: a stand-in for the switch. If the emulator can't raise a GPIO
  edge (`ABI.md`), the case uses a fake GPIO driver process that speaks
  `gpioproto` and reports one edge, and asserts the PWM requests the
  controller makes, in order.
- On the board, through the lead and the user: flip the switch ten times.

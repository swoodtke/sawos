**A server can't learn the length of a Memory it was given, so a short shared ring can fault it.** The networking packages (`pktring`, SO-149) map a ring Memory the client allocates and gives at `Attach`. The server computes the ring's size from the layout, but nothing tells it how long the received Memory is: `MemoryOp` has only `Map`, `Extend` and the rest, and `Mapping` has only `base()`. On a protected board, a client that gives a Memory shorter than the layout makes the server fault on its first access past the end. Rule 5.2.4 of the networking design (`SO:networking` §5.2) says a bad value must end the connection with a counted error, never fault the receiver.

**Wanted:** a way for the receiver to check the Memory's length before it maps or uses it. Two shapes to weigh, with spec text and cases:
- `MemoryOp.Len`, an answer to "how many bytes is this Memory?", gated by a right;
- `Map` taking a minimum length and refusing a shorter Memory by name.

Every check needs a case that goes red when removed or inverted. Small kernel unit, design note first (Opus).

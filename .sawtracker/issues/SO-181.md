# Networking A5a: TCP connection setup and teardown, the state machine

The networking design is `SO:networking`. Its §6.1 recommends a Saw stack,
staged UDP first, and splits TCP into four units (§10, track A):
- **A5a** (this unit): setup and teardown, the state machine, golden tests;
- A5b: data transfer, retransmission and RTO (RFC 6298);
- A5c: congestion control (RFC 5681);
- A5d: the out-of-order queue, zero-window probe, keepalive, TIME_WAIT, and
  cases against the host's TCP.

`drivers/netstack` has Ethernet, ARP, IPv4, ICMP and UDP as hosted layers
over byte buffers, with no device and no clock of their own. Another agent
is adding DHCP and DNS to it at the same time (A4). Keep to new files, plus
one line each in the module list and the IPv4 protocol demux.

## Read first

- `drivers/netstack/src/*.saw` and its tests: the layers' shape, and how
  time is given to them.
- RFC 9293 (TCP, which consolidates RFC 793): §3.3 (the state machine,
  sequence numbers, the handshake and the close), §3.5 (establishing a
  connection), §3.6 (closing one), and §3.10's event processing for the
  segments of each state. Use what setup and teardown need. Cite a section
  in a comment only where a rule isn't obvious.
- The design's §6.1 for the scope and the staging.

## Build (`drivers/netstack`, hosted)

1. **The segment header,** encoded and decoded with the pseudo-header
   checksum. Refuse a bad checksum, a data offset below 5 or past the
   segment, and a truncated header.
2. **Options:** MSS on SYN only. Ignore window scale, SACK-permitted and
   timestamps, so they aren't offered, but parse past them.
3. **The connection state machine:**
   - CLOSED, LISTEN, SYN_SENT, SYN_RECEIVED, ESTABLISHED, FIN_WAIT_1,
     FIN_WAIT_2, CLOSING, TIME_WAIT, CLOSE_WAIT and LAST_ACK;
   - the active open and the passive open;
   - simultaneous open and simultaneous close;
   - RST: generating it, and accepting it with the RFC's sequence check
     (RFC 5961's challenge ACK is A5d's; note it);
   - the initial sequence number from a caller-given source, since the
     stack has no clock or randomness of its own.

   Data in ESTABLISHED is A5b's. Here a segment carrying data is
   acknowledged and its bytes counted, but not delivered.
4. **TIME_WAIT's timer** is driven by the caller's time, as everything is.
   2MSL is a constant. A5d does the full handling.
5. **A connection table:** a fixed number of connections, with the match on
   the four-tuple, and a listener that spawns a connection on SYN.

## Tests (hosted, golden)

- Every state transition in RFC 9293's diagram has a test: a segment in, the
  segment out (bytes exact) and the new state.
- Every refusal has one: a bad checksum, a bad offset, an out-of-window
  segment, a RST outside the window, an ACK of nothing sent, and a SYN in
  ESTABLISHED.
- Every check needs a mutant that turns a test red. Name each one in your
  note.

Gate cases (a guest connecting to the peer) wait for A5b. A5a is hosted
only, so it needs no runner case beyond `HOSTED_TESTS`, which already runs
netstack.

**SO-181.p1 note (A5a, TCP setup and teardown, hosted).**
- **Files:** `tcp.saw` (the header, `Received`, `write_segment`, `TcpDrop`) and `tcpconn.saw`, a fixed 8-slot `Table` with listen, connect, close, abort, receive, poll, state, status and find. Segments go out through a `SegmentSink`, and ISNs come from a caller's `IsnSource`.
- **Options:** MSS is offered and read on a SYN only (1460, default 536); other options are skipped by length.
- **TIME_WAIT** is 2×MSL, at 120 s. IPv4 gains `Protocol.Tcp = 6`. The Stack still drops TCP; hooking the table into Stack is A5b.
- **Coverage:** every diagram edge has a golden-byte test, plus simultaneous open and close, resets in each state, the RFC 9293 §3.5.2 closed-port resets, data counted and acknowledged, and wrap past zero. The goldens come from independent scratch Python.
- **Refusals:** Truncated, DataOffset, Checksum (with the pseudo-header), BadOption, BadPort, NoConnection, TableFull, OutOfWindow, ResetOutOfWindow, ResetIgnored, AckUnsent, NoAck, NoSyn, UnexpectedSyn and OutOfOrder.
- **Mutants:** 80 of 80 red, listed in the agent's report and its scratch `mutants1.txt`.
- **One choice the RFC leaves open:** in SYN-RECEIVED, a SYN at IRS counts as seen. Without ACK it resends SYN,ACK; with ACK it trims and establishes (Figure 7).
- **Left for A5b–A5d:** sending and retransmission, delivering data, the Stack hook, PSH and urgent, congestion, the OOO queue, RFC 5961, restarting TIME-WAIT on a repeated FIN, RFC 6191 reuse, and keepalive. The new private fields aren't in `net_fields_sealed` yet.
- **Totals:** gate 1680, netstack's hosted tests 5/5.

Requested changes on patch SO-181.p1 (revision 2) (its test run was cancelled)

**Held for a revision.** The parser stands up to hostile input:
- the options walk always ends, and lengths of 0 or 1, a missing length byte, a length past the header and a truncated MSS are all handled;
- the header is checked before any slice;
- the checksum's pseudo-header is right and pads an odd byte;
- sequence arithmetic is modulo 2^32 throughout.

The states follow RFC 9293 for setup and teardown, and the CLOSED reset forms are right. An agent read it against the RFC (section numbers from memory), and I ran the probes below on r2 with sawlang v0.24.6.

**1. A RST or SYN is accepted by where it ends, not by SEG.SEQ** (`tcpconn.saw`: `acceptable` takes either end, then steps 2 and 4 act).
- §3.5.3 makes a reset valid only if its sequence number is in the window, and the module doc claims that rule. But a RST whose first octet is before RCV.NXT, carrying data that reaches into the window, closes the connection. A SYN the same way gets a reset reply.
- So a blind reset with up to about 1,459 octets of data lands up to that far before the window.
- **Probe:** next to the test at `tests/tcpconn.saw:805`, I added `check(dropped(rw.feed(&from_b(9000, 0, RST, 2)), TcpDrop.ResetOutOfWindow), …)` on the established rig (RCV.NXT 9001). It fails: the segment is taken as a reset.
- **Fix:** check `in_window(SEG.SEQ)` for RST, and act on a SYN only when SEG.SEQ is in the window, otherwise trim it. Pin both with data and with a FIN.

**2. Two input bounds are correct but unpinned; a mistake there would panic on network input.** I ran both mutants against the hosted tests, and both stay green:
- the data offset check moved one past (`header_bytes > received + 1`). A 26–27-byte segment with offset 7 would then panic on the slice;
- the options overrun check moved one past (`i + length > n + 1`). An MSS in the last bytes would then read past the options.

**Pins:** a 27-byte segment with offset 7, and an MSS overrunning by one byte.

**3. Smaller, to fix or name:**
- **SYN-RECEIVED is never reclaimed.** `poll` ends only TIME-WAIT, so seven spoofed SYNs fill the 8-slot table until the caller aborts them. Retransmission is A5b's, but abandoning SYN-RECEIVED should be in the note's "left for" list before the stack hooks TCP in.
- **An accepted RST answers `Ok`.** The caller learns of it only through `state(id)`, while a SYN that ends a connection answers `Err(UnexpectedSyn)`. Report the reset the same way.
- **Slot ids carry no generation,** so a stale id can close a new connection in a reused slot.
- **Unpinned checks** (each deletable with every test green): either half of the window-update condition; the four-tuple's local address, local port and remote address (every test differs only by remote port); the `takes_text()` guard on out-of-order data; and `not rst` in SYN-RECEIVED's special case.
- **`length as UInt16`** is a checked cast, so the hosted API panics on a slice longer than 65535. IPv4 can't produce one; refuse it anyway.

# Networking A5a: TCP connection setup and teardown, the state machine

The networking design is `SO:networking`. Its §6.1 recommends a Saw stack,
staged UDP first, and splits TCP into four units (§10, track A):
- **A5a** (this unit): setup and teardown, the state machine, golden tests;
- A5b: data transfer, retransmission and RTO (RFC 6298);
- A5c: congestion control (RFC 5681);
- A5d: the out-of-order queue, zero-window probe, keepalive, TIME_WAIT, and
  cases against the host's TCP.

`drivers/netstack` has Ethernet, ARP, IPv4, ICMP and UDP as hosted layers
over byte buffers, with no device and no clock of their own. Another agent
is adding DHCP and DNS to it at the same time (A4). Keep to new files, plus
one line each in the module list and the IPv4 protocol demux.

## Read first

- `drivers/netstack/src/*.saw` and its tests: the layers' shape, and how
  time is given to them.
- RFC 9293 (TCP, which consolidates RFC 793): §3.3 (the state machine,
  sequence numbers, the handshake and the close), §3.5 (establishing a
  connection), §3.6 (closing one), and §3.10's event processing for the
  segments of each state. Use what setup and teardown need. Cite a section
  in a comment only where a rule isn't obvious.
- The design's §6.1 for the scope and the staging.

## Build (`drivers/netstack`, hosted)

1. **The segment header,** encoded and decoded with the pseudo-header
   checksum. Refuse a bad checksum, a data offset below 5 or past the
   segment, and a truncated header.
2. **Options:** MSS on SYN only. Ignore window scale, SACK-permitted and
   timestamps, so they aren't offered, but parse past them.
3. **The connection state machine:**
   - CLOSED, LISTEN, SYN_SENT, SYN_RECEIVED, ESTABLISHED, FIN_WAIT_1,
     FIN_WAIT_2, CLOSING, TIME_WAIT, CLOSE_WAIT and LAST_ACK;
   - the active open and the passive open;
   - simultaneous open and simultaneous close;
   - RST: generating it, and accepting it with the RFC's sequence check
     (RFC 5961's challenge ACK is A5d's; note it);
   - the initial sequence number from a caller-given source, since the
     stack has no clock or randomness of its own.

   Data in ESTABLISHED is A5b's. Here a segment carrying data is
   acknowledged and its bytes counted, but not delivered.
4. **TIME_WAIT's timer** is driven by the caller's time, as everything is.
   2MSL is a constant. A5d does the full handling.
5. **A connection table:** a fixed number of connections, with the match on
   the four-tuple, and a listener that spawns a connection on SYN.

## Tests (hosted, golden)

- Every state transition in RFC 9293's diagram has a test: a segment in, the
  segment out (bytes exact) and the new state.
- Every refusal has one: a bad checksum, a bad offset, an out-of-window
  segment, a RST outside the window, an ACK of nothing sent, and a SYN in
  ESTABLISHED.
- Every check needs a mutant that turns a test red. Name each one in your
  note.

Gate cases (a guest connecting to the peer) wait for A5b. A5a is hosted
only, so it needs no runner case beyond `HOSTED_TESTS`, which already runs
netstack.

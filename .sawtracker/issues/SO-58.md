## The change

1. **Rights** (`kernel/abi/src/rights.saw`): `thread_rights()`,
   `event_rights()`, `waiter_rights()` and `timer_rights()` gain `Transfer`.
   Update each doc comment, which today explains why the kind cannot be given.
2. **Boot record kinds** (`kernel/abi/src/boot.saw` `BootHandleKind`): add
   `Thread`, `Event`, `Waiter`, `Timer`, numbered after `PipeRequest`. Update
   `boot_kind_of` and `msg_kind_of` (`kernel/core/objects.saw`) so all four can
   be given and carried in a message. Check the kernel's give, stage and mint
   paths need nothing else per kind. If any kind needs special handling when
   moved (a Timer that is armed, a Waiter with attachments or parked threads, a
   Thread that is running or joined), find out what the code does today and
   report it. **If moving one would break an invariant, stop and ask.**
3. **Typed tier** (`kernel/sysapi/src/`):
   - `PipeHandle` gains a case for each, and `decode_handle` decodes them.
   - The send carrier (`PipeHandles`) can carry them.
   - `Process.give(thread:/event:/waiter:/timer:, tag:, keep:)` overloads, in
     the exact shape of the existing ones (`system.saw` ~778–960): consuming,
     with a `Result<Void, (SosStatus, T)>` hand-back on a status refusal, as
     `give(memory:)` does.
   - `BootHandle` accessors for the four kinds, matching the existing ones
     (~1220).
   
   The modules for these kinds sit below `sos.pipe` (no import cycle); confirm
   that.
4. **Floor** (`kernel/sysapi/src/floor.saw`) and any C header that lists boot
   kinds: add the four.
5. **Spec:** remove the markers this satisfies (§3, §2.1, §2.7, §11) for these
   four kinds, leaving the Interrupt parts. No issue numbers; 80 columns.

## Tests

Add runner cases modelled on `give_*`, `pipe_handles` and `child-handles`:
1. **Give:** root creates an Event, a Waiter, a Timer and a Thread (a parked
   worker, or one it can join), gives each to a child under a tag, and the
   child drains them through `BootHandleNext` and uses each: it signals the
   Event (root observes it), attaches and waits on the Waiter, arms and waits
   on the Timer, and joins or reads the Thread's state.
2. **Message:** the same four, carried in one pipe message to a child, decoded
   by `decode_handle`, and used.
3. **Hand-back:** a give refused with a status (full child table, as
   `give_full_returns` provokes) hands the object back usable, for at least one
   of the new overloads.

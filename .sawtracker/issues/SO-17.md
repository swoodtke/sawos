### sawos TODO lines 414–414

[Original record](https://github.com/swoodtke/sawos/blob/754ec9570aef54609820cc7e28457c7623547670/designs/todo.md#L414-L414)

- SL‑27 — `sizeof`/`alignof` DO NOT FOLD IN A STATIC INITIALIZER, AND THE REFUSAL'S OWN HINT SAYS THEY DO: `static C: Int = sizeof<UInt64>()` is ``error: static `C` must be initialized by a compile-time constant`` whose hint reads "a static initializer is a CONSTANT EXPRESSION ...: literals, arithmetic and bitwise over them, `sizeof`/`alignof`, the integer limits, ..." (sawc 0.8.0 @ `449d2485`, hosted and freestanding alike, probed Sep 5 at the seventh pin bump). Minimal repro is that one line; mixing them into arithmetic (`16 / sizeof<UInt>()`) refuses identically. `sizeof` in a `static_assert`, an array length or a function body folds fine — the gap is the static-initializer position only. WHERE IT BIT: the SL‑26 staging buffer wanted `static PIPE_STAGE_WORDS: Int = PIPE_BODY_BYTES / sizeof<UInt>()` (the natural derive-don't-restate spelling of design 186); the workaround in-tree is a literal count over `UInt64` plus a `static_assert` pinning it to `PIPE_BODY_BYTES`. Resolution shape: either fold the two builtins in that position (they are the hint's own promise, and design 186 tier 2 names them) or correct the hint — a hint that lists the refused spelling as allowed costs a round-trip per encounter.

Status verdict (claude-sawos, Sep 24): PARTLY DONE, NOT closable yet. The Sep 7 handoff said aa9e88f finished this. It converted only the ONE site it names: pipe.saw's `PIPE_STAGE_DWORDS = PIPE_BODY_BYTES / sizeof<UInt64>()`.

Probe (sawc 0.11.1 @ 6dce5cf1 and sawlang head @ 454207de, `--freestanding -c`, riscv32 + aarch64): in a static initializer, `WORDS * sizeof<UInt>()` (platform-typed), `2 * sizeof<UInt64>()`, and a `static_assert` over the platform-typed form all COMPILE at both versions on both targets. `sizeof<StructT>()` is still REFUSED at both ("static `REC` must be initialized by a compile-time constant"). The hint scopes folding to "`sizeof`/`alignof` of a primitive or pointer type".

Surviving DF-178f workarounds that the scalar fold now retires (each a `func` written only because the static refused):
- kernel/core/mem.saw:28 `word_bytes()`
- kernel/abi/src/records.saw:184 `wait_header_bytes()`, :332 `clock_now_record_bytes()`, :402 `pipe_create_record_bytes()`, :595 `process_stats_record_bytes()`
- kernel/abi/src/boot.saw:57 `boot_handle_record_bytes()`

These STAY functions (struct sizeof, still refused): records.saw:447 `pipe_msg_record_bytes()` / `pipe_msg_body_offset()`. Their comments should say "a STRUCT's sizeof" rather than blaming DF-178f. If upstream intends struct sizeof to fold, that belongs in an SL issue, not here.

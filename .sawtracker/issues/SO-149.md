**Networking A1: the packet ring and the protocol packages.** This is the networking design's (`SO:networking`, SO-103) §5.2 and unit A1. It adds new library packages in `drivers/`, in `uartproto`'s pattern, each with hosted tests that a full run `blade test`s (`HOSTED_TESTS` in the runner). It needs no emulator and no board.

- **`pktring`.** The shared-memory packet ring that both packet protocols use.
  - A frame or an HCI packet can't ride a message: `PIPE_BODY_BYTES` is 128 and can't exceed 255 (spec §2.1).
  - The client allocates one Memory per connection and gives it at `Attach`, and both sides map it.
  - It holds two rings of fixed-size slots (2048 bytes for frames, 512 for HCI) and two index words per ring. Messages carry doorbells and slot numbers.
  - The layout (header, index words, slot array, each slot's length word) is stated once, and both sides compute it from the slot size and count.
- **Rule 5.2, a shared ring is input.** The receiving side reads every field it acts on from shared memory once, into private memory, checks it, and uses only the copy:
  1. an index word is read once and checked against the slot count;
  2. a slot's length is read once and checked against the slot size;
  3. header bytes a parser acts on are copied out before parsing, and the payload is copied out with the checked length and never re-read;
  4. a value that fails a check ends the connection with a counted error, never a fault of the receiver.

  `pktring` provides the read-once accessors, so a protocol written on it can't read a shared field twice by accident.
- **`netdevproto`.**
  - `Attach(ring)` is a call; the reply carries the MAC address, MTU and slot counts.
  - `Tx(first, count)` and `RxReturn(first, count)` are tells.
  - `WaitEvent` is a held call, answered with the next event: frames received in slots a..b, TX slots done, link up, link down.
  - `Stats`.
- **`hciproto`.** The same shape, with H4 packet types in the slots.
- **`wlanproto`.** `Scan`, `Connect(ssid, auth, key)`, `Disconnect`, `Status` and `WaitEvent`. The key crosses once.
- **`sockproto`.**
  - One connection per application, with sockets named by a small id inside it.
  - The ops are `UdpOpen(port)`, `TcpConnect(addr, port)`, `TcpListen(port)`, `Accept`, `Send(id)`, `Recv(id)`, `Close(id)`, `Resolve(name)` and `IfStatus`.
  - Bulk data goes through the connection's `pktring`.
  - An application's death is the connection's peer-closed, which closes every socket it held.
- **`gattproto`** (`Advertise`, `AddService`, `Notify`, `WaitEvent`) is left for the BLE track, not this unit.

**Hosted tests.**
- The ring arithmetic: wrap, full, empty, every slot count the layout allows.
- Each protocol's encodings, round-tripped, with each malformed message refused by name.
- Rule 5.2:
  - an index past the count;
  - a length past the slot;
  - a field changed between two reads; the test changes shared memory between the accessor's read and the use, and the use must see the first value.

Every check has a case that goes red when it is removed or inverted; list the mutants.

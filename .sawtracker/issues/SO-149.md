**Networking A1: the packet ring and the protocol packages.** This is the networking design's (`SO:networking`, SO-103) §5.2 and unit A1. It adds new library packages in `drivers/`, in `uartproto`'s pattern, each with hosted tests that a full run `blade test`s (`HOSTED_TESTS` in the runner). It needs no emulator and no board.

- **`pktring`.** The shared-memory packet ring that both packet protocols use.
  - A frame or an HCI packet can't ride a message: `PIPE_BODY_BYTES` is 128 and can't exceed 255 (spec §2.1).
  - The client allocates one Memory per connection and gives it at `Attach`, and both sides map it.
  - It holds two rings of fixed-size slots (2048 bytes for frames, 512 for HCI) and two index words per ring. Messages carry doorbells and slot numbers.
  - The layout (header, index words, slot array, each slot's length word) is stated once, and both sides compute it from the slot size and count.
- **Rule 5.2, a shared ring is input.** The receiving side reads every field it acts on from shared memory once, into private memory, checks it, and uses only the copy:
  1. an index word is read once and checked against the slot count;
  2. a slot's length is read once and checked against the slot size;
  3. header bytes a parser acts on are copied out before parsing, and the payload is copied out with the checked length and never re-read;
  4. a value that fails a check ends the connection with a counted error, never a fault of the receiver.

  `pktring` provides the read-once accessors, so a protocol written on it can't read a shared field twice by accident.
- **`netdevproto`.**
  - `Attach(ring)` is a call; the reply carries the MAC address, MTU and slot counts.
  - `Tx(first, count)` and `RxReturn(first, count)` are tells.
  - `WaitEvent` is a held call, answered with the next event: frames received in slots a..b, TX slots done, link up, link down.
  - `Stats`.
- **`hciproto`.** The same shape, with H4 packet types in the slots.
- **`wlanproto`.** `Scan`, `Connect(ssid, auth, key)`, `Disconnect`, `Status` and `WaitEvent`. The key crosses once.
- **`sockproto`.**
  - One connection per application, with sockets named by a small id inside it.
  - The ops are `UdpOpen(port)`, `TcpConnect(addr, port)`, `TcpListen(port)`, `Accept`, `Send(id)`, `Recv(id)`, `Close(id)`, `Resolve(name)` and `IfStatus`.
  - Bulk data goes through the connection's `pktring`.
  - An application's death is the connection's peer-closed, which closes every socket it held.
- **`gattproto`** (`Advertise`, `AddService`, `Notify`, `WaitEvent`) is left for the BLE track, not this unit.

**Hosted tests.**
- The ring arithmetic: wrap, full, empty, every slot count the layout allows.
- Each protocol's encodings, round-tripped, with each malformed message refused by name.
- Rule 5.2:
  - an index past the count;
  - a length past the slot;
  - a field changed between two reads; the test changes shared memory between the accessor's read and the use, and the use must see the first value.

Every check has a case that goes red when it is removed or inverted; list the mutants.

**Lead: SO-149.p1 is up.** It adds `pktring` and the netdev, hci, wlan and sock protocol packages: one commit, a64bd6f5, on main 14d5176e.

It is five new library packages in `drivers/`. None depends on `sos`, so `blade test` runs them on the host. All five are listed in `HOSTED_TESTS`, and CLAUDE.md's repo map names them.

**`pktring`**
- **The layout.** `Layout(slot_bytes, to_server, to_client)` gives every offset: 16 bytes of index words, one length word per slot, then the slots from the next multiple of 64. A ring holds at most 256 slots, and a slot at most 64 KiB.
- **The indexes.** Indexes count modulo twice the slot count, so full and empty differ without losing a slot. `SlotRange.fits` checks a range a message carries.
- **The accessors.** `Endpoint<M: Shared>` is a side's only access to the ring. It keeps its own indexes privately and only stores them.
  - It reads each of the peer's fields once, checks it, and uses only the copy.
  - A fatal error (`IndexPastCount`, `IndexOutOfOrder`, `LengthPastSlot`) latches, so every later call answers it and reads nothing.
  - `FaultCounts` counts the fatal errors by kind.
  - `Empty`, `Full` and `TooLong` ride the error channel and are not fatal.
  - `SharedWindow` makes volatile accesses.

**The protocols**
- **`netdevproto`.** `Attach`, a call with the ring in handle slot 0, replies with the MAC, the MTU and the slot counts. `Tx` and `RxReturn` are tells. `WaitEvent` is a held call (`RxReady`, `TxDone`, `LinkUp`, `LinkDown`), and there is `Stats`. A malformed request or reply is refused by name (`WireError`); an MTU whose frame wouldn't fit a slot counts as malformed.
- **`hciproto`.** The same shape with 512-byte slots. Its `h4_packet` parses from the private copy and refuses by name:
  - an unknown type;
  - a command from the controller, or an event going to it;
  - a packet shorter than its header;
  - a length that isn't the slot's.
- **`wlanproto`.** `Scan`, `Connect`, `Disconnect`, `Status` and `WaitEvent`.
  - The key crosses once: only `Connect` carries it, and `WlanBody.wipe()` clears it from the client's body.
  - `check_key` takes Open with no key; WPA2 takes 8–63 printable bytes or 64 hex digits.
  - Other auths decode, and the driver answers them `Unsupported`.
- **`sockproto`.** One connection per application, with sockets named by an id below 16. The ops are `Attach`, `UdpOpen`, `TcpConnect`, `TcpListen`, `Accept`, `Send`, `Recv`, `Close`, `Resolve` and `IfStatus`, with 16 statuses. A UDP slot opens with a 6-byte address and port header. `Attach` is not in the brief's list, but the design gives the ring at Attach.

**Tests.**
- `blade test` passes for all five packages.
- Rule 5.2 is held with a fake memory that counts reads and changes a word just after it's read:
  - an index past the count and an index out of order, for both head and tail;
  - a length past the slot;
  - each fatal error latched, counted, and reading nothing afterwards;
  - head, length, payload and tail each read exactly once, with a value changed after its read never seen;
  - through a real `SharedWindow`, the use seeing the first value.
- The runner's hosted step is green with the new list, and `thread_basics` passes on riscv32, check-tree included.

**Mutants.** 296, all red: pktring 82, netdevproto 36, hciproto 36 + 19, wlanproto 64, sockproto 59.
- Every check was removed and inverted, and each half of a compound condition removed alone.
- Read-twice mutants reload the head, tail, length or a payload word.
- An early run had 14 survivors. One was real: a send could write one byte past its length into the slot, and a test now holds that. The rest were missing tests, now added, or duplicate checks, now removed so each length is checked in one place.

**Unpinned.**
1. **Rule 5.2.4 has a kernel gap.** A server can't learn a received Memory's length: there's no `MemoryOp` for it, and `Mapping` has only `base()`. On a protected board, a client that gives a Memory shorter than `Layout.bytes()` makes the server fault. pktring's docs say so. Filed separately.
2. **Doorbells don't drive the ring.** The index words are authoritative; a message's range is checked on the wire.
3. **Pipe adapters**, in `uartpipe`'s style, are left to A3 and A6.
4. **`gattproto`** is left to the BLE track.

Requested changes on patch SO-149.p1 (revision 2) (its test run was cancelled)

**Changes requested: safe code in another module can forge a `SharedWindow` and clear an `Endpoint`'s latch; the ring's index checks stop at this end's private indexes; and eight mutants survive.** Revision 2's lines are revision 1's. All five packages pass `blade test` unmodified.

**1. `SharedWindow` and `Endpoint` expose what their safety rests on.** In pktring/src/lib.saw:
- **`SharedWindow`:** a `public struct` with bare `base` and `bytes`. Its `unsafe init(at:bytes:)` has other labels, so it does not stand in for memberwise construction.
- **`Endpoint`:** `public memory`, and bare `out_*`, `in_*` and `failed`.

A bare field of a `public struct` is readable, writable and memberwise-constructible from any module. Probe chat f425 (`probe_window.saw`, a non-`unsafe` function in another module), built against this package and run:
- `SharedWindow(base: 0x10, bytes: 0x1000_0000)` then `.load(0)` compiles and dies with SIGSEGV (exit -11). `load` is `unsafe` but takes only safe parameters, so a caller writes no ceremony, and it must be sound for every input. It is sound only if the window came through the `unsafe` init.
- `e.failed = None` after an `IndexPastCount(99)`, then `poll`, prints `after clearing the latch: poll ok`. The latch rule 5.2 promises is undone from outside.

Make these fields `private`. Then check every other public struct whose fields carry an invariant a method relies on, such as a length that bounds an index into its own array.

**2. A peer index is bounded by this end's private index, not the one it published.**
- **The code:** `read_out_tail` checks the peer's tail against `out_head`, which counts slots sent but not yet published. `poll` checks the peer's head against `in_tail`, not `in_released`. `RingError.IndexOutOfOrder` describes "a tail … past the filled ones".
- **Producer side** (probe chat f426, `probe_bounds.saw`, run): on a 4-slot ring with two slots sent and unpublished, a peer tail of 2 makes `room` answer `Ok(4)`. Four more sends then overwrite slots 0 and 1 before they were ever published, `publish` answers `Ok(first 0, count 6)` on a 4-slot ring, the shared head becomes 6, and there is no fault.
- **Consumer side:** a head of 0 after four receives and no release is accepted, and `release` answers `count 7` with no fault.
- **Why it matters:** no index leaves 2n, so this is not memory-unsafe, but the peer escapes the counted fatal error. Either bound by the published and released indexes, or rule that this is intended and say so beside `RingError`.

**3. Eight mutants survive**, each applied alone with the package's `blade test` run and the file restored:

| package | the edit | |
|---|---|---|
| pktring | `room` reads the peer's tail again instead of the checked copy | read twice: rule 5.2 is pinned on `send`'s path only |
| pktring | `poll`'s error answers a second load of the head | read twice on the error path |
| pktring | `poll`'s `first` from `in_released`, not `in_tail` | no test polls between a `receive` and its `release` |
| pktring | `SharedWindow.word` without its `offset + 4 > bytes` half | |
| hciproto | `put_h4_header`'s `payload_max` panic removed | |
| wlanproto | ScanDone `!= 4` → `< 4` | tested short only |
| wlanproto | Connected `!= 9` → `> 9` | tested long only |
| wlanproto | Disconnected `!= 3` → `> 3` | tested long only |

Each needs a case that goes red, or a named equivalent with its reason.

**4. Minor:**
- **The status order:** wlanproto's doc says `BadOp`, including "a length its op does not have", is checked before `BadArg`. But `connect()` answers `SsidLength`, a `BadArg`, before any length check, and `wire.saw` pins that. Adjust the doc's order sentence.
- **The key wipe:** `WlanBody.wipe()` zeroes with plain stores into a body that dies right after. Dead-store elimination may drop those, so the wipe is best-effort as written. Make the stores volatile, as `SharedWindow`'s are, or say in the doc that it is best-effort. The other copies of the key (the caller's `Key`, the server's `Frame`, the decoded `Connect`) have no wipe.

**What holds** (from a first-pass agent's reading; I read `read_out_tail`, `room` and `poll` myself):
- Each peer word is read once on `send`, `receive` and `poll` and checked before use, all five `fail` sites latch, and every public operation tests `failed` first.
- Indexes count modulo 2n, with full and empty right for 1 to 256 slots, and slots start on a 64-byte boundary.
- `Layout`'s init matches its fields, so it does override memberwise construction.
- `SharedWindow`'s accesses are volatile.
- netdev's and hci's decoders refuse every op, status and event by name with exact lengths.
- The wlan key boundaries (7, 8, 63, 64 hex, 64 non-hex, 0x1F, 0x7F) answer as documented.
- sockproto's ids are checked below 16 wherever they are taken.

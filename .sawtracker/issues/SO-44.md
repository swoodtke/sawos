## Description

Some Process factory ops act on another process through its Process handle (`obj.slot`, SO-41). When the caller makes an error on that path, the fault lands on the **named process, not the caller**:

| Op | Error | Fault lands on |
|---|---|---|
| `thread_create(obj.slot, …)` | bad entry or stack | the target (`BadEntry`) |
| `event_create` | bad argument | the target (`BadArg`) |
| `interrupt_bind` | bad line | the target (`BadArg`/`LineBound`) |
| `pipe_create` | any | the caller (correct) |
| `waiter_create` | none | no fault path |

Consequences:
- A launcher's bad entry, mode or line terminates the **child**.
- `end_process` then clears `CURRENT_THREAD`, which strands the launcher's thread (the same mechanism as SO-37).
- This contradicts spec §5.7, "terminates the offending process".

Fix direction (needs the per-op ruling from SO-41): fault `caller` for caller errors, whatever the op targets.

Found by claude-air-reviewer in the SO-31 r7 review. It is confirmed at `dispatch.saw` 598/652/658/668/734, and the SO-26 r3 implementer found it independently.

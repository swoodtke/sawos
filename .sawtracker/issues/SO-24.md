## Volatile facts (user ruling, Nov 8): don't write facts that go stale by design

A comment or doc must not state a fact that changes as a side effect of ordinary work. Remove these, or replace them with where to get the current value:
- test counts and gate totals ("382 = 129 + 129 + 124", "23 cases", "the flat profile runs four fewer"). Say instead that the runner prints the totals, and that the flat profile excludes cases by name with a printed reason;
- image, section or binary sizes, and measured memory use (".text 76,808 B", "133,272 B of 172,032");
- counts of sites, files, lines, callers, overloads or uses ("the ~370 indexed reads", "95 sites", "the 33 match sites", "sink.c is 130 lines", "three callers");
- run times, timings and measured trap or cycle counts ("about 60 minutes", "10 traps against 18");
- snapshots of current state ("it happens to read 0 today", "nothing in-tree uses this yet", "the only caller today is…"), unless that state is itself a rule the code enforces.

Keep:
- a value that is a contract or definition: an ABI offset, a frame size, a register number, a constant's meaning. Where the code defines it, prefer naming the constant (`PIPE_INFLIGHT`, `FRAME_SIZE`) over restating its number. ABI layout tables keep their numbers, because the doc is the contract.
- a bound the code enforces ("at most `MAX_HANDLES` entries"), stated through its constant.

Apply this to every file in your scope, including text you already rewrote.

## User ruling (Nov 8): what the flat tier disclaims

On the flat profile the user-mode protection range is read/write/execute over the whole address space, so a process can read and write any address, the kernel's own memory and the test finisher included. Rights therefore hold only for a process that reaches the kernel through syscalls: handles, rights, quotas and lifetimes are checked on every syscall, but a process that writes kernel memory directly bypasses all of them (`SystemRight.Shutdown` included).

The docs and comments must say so:
- **Replace** "the kernel boundary is not disclaimed / not tiered anywhere", "denial and nothing else", and "enforced identically on all three". The checks are identical **on the syscall path**. The flat tier disclaims protecting memory, the kernel's included, from a process. The isolated tiers enforce both.
- **Keep** the point that the object-model suite runs unchanged on every profile, because every case reaches the kernel through syscalls.
- `tests/tier-word` prints "SOS tier: kernel boundary intact", and the runner asserts that string. Strings are code, so leave it. The comments around it say the case proves the **syscall-path** checks hold on every tier.
- One or two sentences per site. No issue numbers, no history.

# Networking A5b: TCP data transfer, retransmission and RTO, hooked into the Stack

The networking design is `SO:networking`, §6.1 and §10's track A. A5a has
merged, as "netstack: TCP connection setup and teardown". It gives you:
- `drivers/netstack/src/tcp.saw`: the wire format, `Header`, `Received`,
  `write_segment` and `TcpDrop`;
- `drivers/netstack/src/tcpconn.saw`: the states, a `Table` of 8 slots with
  generation-carrying `ConnId`s, a `SegmentSink` and an `IsnSource`.

Data there is counted and acknowledged, never delivered. Read SO-181's notes
for what A5a left to this unit.

## Build (hosted, in `drivers/netstack`)

1. **Sending data:**
   - a send buffer per connection;
   - segmenting to the peer's MSS (with a floor on a tiny MSS);
   - the send window (`SND.WND`), and `SND.NXT` / `SND.UNA`;
   - PSH set on the last segment of a write.
2. **Receiving data:**
   - a receive buffer per connection, delivered in order;
   - the advertised window shrinks as data waits and reopens as the caller
     reads, following RFC 9293 §3.8.6's window management. Avoid silly
     window syndrome per RFC 9293 §3.8.6.2.
3. **Retransmission (RFC 6298):**
   - SRTT and RTTVAR, an RTO clamped to the RFC's 1 s minimum (as a
     constant you can lower in tests), and exponential backoff;
   - Karn's algorithm, so a retransmitted segment gives no RTT sample;
   - retransmitting the SYN, the SYN,ACK and the FIN;
   - a connection given up after a bounded number of tries.

   The clock is the caller's `now`, as everywhere in netstack.
4. **SYN-RECEIVED reclaim:** a SYN,ACK that's never answered after its
   retries frees the slot. That closes the forged-SYN fill A5a named.
5. **The Stack hook:**
   - the TCP table lives in `Stack`;
   - the IPv4 demux's `Tcp` arm feeds it, counting each `TcpDrop`;
   - segments go out through `send_ipv4`;
   - the API a caller uses: listen, connect, write, read, close, abort and
     poll(now).
6. **Out of scope:**
   - congestion control (A5c): keep the congestion window fixed at a
     generous value, or none, and say which;
   - the out-of-order queue, RFC 5961, keepalive, zero-window probes and
     the TIME-WAIT details (A5d).

   Out-of-order data stays dropped with a duplicate ACK.

## Tests

- **Hosted goldens:**
  - a write segmented and acknowledged;
  - a window that closes and reopens;
  - an RTO firing, with backoff, and RTT samples skipped per Karn;
  - SYN and FIN retransmitted;
  - a connection given up;
  - a SYN-RECEIVED reclaimed.

  Each check needs a mutant that turns a test red. Name each in your note.
- **One gate case against the network peer** (`tools/netpeer`): the guest
  connects to a peer TCP echo script, writes a message, and reads it back.
  - Order everything by construction.
  - Assert no time. A retransmission case can drop one segment at the peer
    and assert only that a retransmission arrived, never when.
  - The peer gains a minimal TCP echo script, with hosted tests.

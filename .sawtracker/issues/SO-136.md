## Description

**A product image chooses its ESP32-S3 build keys.** `tools/sawos.py build|run|test|flash` builds an S3 image at the board's default keys (`ESP32S3_DEFAULT_KEYS`: clock `rom`, stall off), and nothing in an image description can say otherwise. The useless box (SO-78) should run at `xtal40` (40 MHz from the crystal, PLL off: it is not CPU-bound and draws less), and a product may want `pll80` or, after SO-132, `pll160`.

**Build:** an image description states its board build keys by name (for the S3, the clock key and the console stall key), refused by name when the board has no such key or the value is not one of the board's; `sosimage build` and `flash` build the kernel with them; `tools/product.py` passes them through for `build`, `run`, `test` and `flash`; an image that states none keeps the defaults, so no existing image moves. The key names and values belong to the board's description (`board.toml`), not to the runner, so a product learns them from the pinned tree. Say in ABI.md how a key reaches a product image.

**Cases:** a product image at `xtal40` built and booted (its clock line), a refused unknown key and a refused unknown value, `flash` printing the board image built at the stated key; every refusal and the pass-through red when removed (the review standard). No existing transcript or image moves.

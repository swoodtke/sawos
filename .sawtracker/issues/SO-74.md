## The pin (lead, Nov 12): sawlang v0.22.0

The tag exists, and the user ruled that sawos pins at it.

- `version = "0.22.0"` (`sawc --version` prints `sawc 0.22.0`)
- `sha = "80ca76d9f00cd1e589da715e05d858312c1423cc"`, the commit the tag
  points at. The lead checked it: `git rev-parse 'v0.22.0^{commit}'` in the
  sawlang repository answers that sha, and `v0.22.0` itself is an annotated
  tag object with a different one.

It contains the ESP32-S3 target, Blade's support for it with
`SosimgArch.Xtensa = 3`, and the removal of the manifest `mcpu` key.

**Scope, in addition to the notes above:**
- This unit moves the pin and nothing else. The Xtensa HAL (SO-75) is
  uploaded after it merges.
- Compare `tools/toolchain.py` with the tag's copy; it must be byte-identical
  to sawlang's at that commit.
- The oracle is two full reports, at the old pin and at the new one, diffed:
  only image-size rows and the `sawlang:` line may differ. The lead already
  has one data point: the full suite built with sawlang's Blade commit, an
  ancestor of the tag, matched the old pin's report row for row, image sizes
  included.
- Run the C3 smoke at both.
- Local runs use a checkout of the tag through `SAWLANG_ROOT` (the dispatch
  prompt gives the path); the gate fetches by the pin's sha.

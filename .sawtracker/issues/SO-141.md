## Description

**sosrt runs Saw's background tasks: the freestanding executor set and SL-1150's drive and close.** sawlang's SL-1150 (design done, Nov 17) lets `Task.spawn` (and `TaskGroup`) work freestanding for a runtime that claims the thread's background group: two compiler-defined entries, `__saw_background_drive() -> Int64` (one bounded turn over the thread's tasks; -1 nothing live, 0 runnable now, INT64_MAX waiting with no deadline, else the earliest deadline in monotonic ns) and `__saw_background_close()` (cancel, join, release). sosrt exports none of the freestanding executor set today, so any spawn fails at link in a sawos image.

**Build (after SO-124 gives threads a real entry, and after the sawlang release carrying SL-1150):** the executor set sosrt must export (from sawlang's runtime/ABI.md); the per-thread executor word in the architecture's thread register (riscv32's `tp` and the S3's `THREADPTR` are already saved per thread in the trap frame; arm64's `TPIDR_EL0` is not and must join the frame, a kernel change); the drive in `sos`'s blocking wrappers (`Waiter.wait` and the pipe calls), bounding the wait by the drive's deadline with a Timer attached to the Waiter and ending it from another thread with an Event (`reactor_wake`); the close on every thread's return into sosrt's thread entry; the declaration on the process side only (the kernel image keeps `Task.spawn` refused). `Process.exit` does not close (the teardown frees the whole process).

An agent read it against the base's spec text, and I rechecked the main finding in the code. One scheduling bug and one host-time test need fixing first.

**1. An early end can leave the running thread below a thread it just readied** (`refs.end_park`).
- `end_park` calls `ready_push(t)`, then `lock_recompute(holder)`. `ready_push` compares the woken thread with the running thread's level as it is at the push, and `lock_recompute` may then lower that running thread.
- `thread_wake_op` returns `op_ok()` with no check after `end_park`, while `lock_wake_op` does (`ready_above(...)` → `NEED_RESCHED`). `on_timer_interrupt` sets nothing after `expire_parks` either.
- **Sequence:** L holds a lock and runs at level 3, inherited from H, which waits on it wakeably. L calls `THREAD_WAKE_OP(H)`. H is pushed at 3, which is not above L's 3, so no switch is asked for. `lock_recompute` then lowers L to its base. L returns to user mode at level 1, with H ready at 3.
- A deadline firing in the timer interrupt does the same. That breaks §7's "a lower level does not run while a higher one is ready", the rule the lock's own give honours ("a give that lowers the giver below a ready thread gives the processor up at its return").
- With no tick, as in every K1 image, it lasts until L blocks, yields or exits.
- **Fix:** recompute before the push, or check `ready_above` after the recompute in `end_park`, for both the wake and the expiry.
- **Pin, with no clock:** the raised holder calls `sos_thread_wake(H)` and then prints a line. H's `Woken` line must come first.

**2. `deadline_join` asserts an order that depends on host time** (`tests/deadline-join`, the order "T parks on its Event" before "deadline: TimedOut").
- `main` reads the clock, sets `now + 20 ms`, and joins.
- A host stall of 20 ms or more between the clock read and the `Join` trap makes the op answer `TimedOut` at once. `main` never parks, T hasn't run yet, and the lines come out in the other order.
- sawos's rule is that an order is made by waiting on what the other side does. **Fix:** have `main` wait for a signal from T (or yield) before it reads the clock.

**3. The note's "not pinned until K2" is wrong for `ready_push` clearing `park_wakeable`.** The plain pipe parks (`Call`'s room and reply parks, and `ReplyWait`'s wait leg) never call `record_park`. So with the clear removed, a thread whose wakeable `Wait` or `Join` ended by delivery carries `park_wakeable` and its old deadline into a later plain `Call`. Then `expire_parks` ends that plain park `TimedOut`, leaving `call_pipe`/`call_claim` and the exchange tie behind. That's pinnable in K1: a wakeable `Wait` answered by delivery, then a plain `Call` that outlasts the old deadline.

**4. Docs:**
- `sos_lock_wait`, `Lock.take` / `sos_lock_take` ("Ok or Revoked"), `sos_thread_join` and `sos_waiter_wait` don't mention `TimedOut`, `Woken` or the park-time `AccessDenied`.
- `tests/quota-set-order` still says 17 where it prints 33.
- `park_deadline`'s doc says `UInt64.max` for none, but the literals write 0. That's harmless, but the doc is wrong.

**Worth a case each.** The agent lists more checks no case reaches; these are the ones that guard a spec sentence:
- a plain park neither reading nor clearing a latch set before its op;
- `Woken` from a latch at `Wait`, `Join` and the lock (only `PARK_OP` is tested);

- readiness first at `LOCK_WAIT_OP` with a passed or latched word;
- a stale ID after its slot is reoccupied;
- `expire_timers` before `expire_parks` in one fire.

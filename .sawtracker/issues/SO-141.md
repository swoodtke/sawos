## Description

**sosrt runs Saw's background tasks: the freestanding executor set and SL-1150's drive and close.** sawlang's SL-1150 (design done, Nov 17) lets `Task.spawn` (and `TaskGroup`) work freestanding for a runtime that claims the thread's background group: two compiler-defined entries, `__saw_background_drive() -> Int64` (one bounded turn over the thread's tasks; -1 nothing live, 0 runnable now, INT64_MAX waiting with no deadline, else the earliest deadline in monotonic ns) and `__saw_background_close()` (cancel, join, release). sosrt exports none of the freestanding executor set today, so any spawn fails at link in a sawos image.

**Build (after SO-124 gives threads a real entry, and after the sawlang release carrying SL-1150):** the executor set sosrt must export (from sawlang's runtime/ABI.md); the per-thread executor word in the architecture's thread register (riscv32's `tp` and the S3's `THREADPTR` are already saved per thread in the trap frame; arm64's `TPIDR_EL0` is not and must join the frame, a kernel change); the drive in `sos`'s blocking wrappers (`Waiter.wait` and the pipe calls), bounding the wait by the drive's deadline with a Timer attached to the Waiter and ending it from another thread with an Event (`reactor_wake`); the close on every thread's return into sosrt's thread entry; the declaration on the process side only (the kernel image keeps `Task.spawn` refused). `Process.exit` does not close (the teardown frees the whole process).

An agent read it against the base's spec text, and I rechecked the main finding in the code. One scheduling bug and one host-time test need fixing first.

**1. An early end can leave the running thread below a thread it just readied** (`refs.end_park`).
- `end_park` calls `ready_push(t)`, then `lock_recompute(holder)`. `ready_push` compares the woken thread with the running thread's level as it is at the push, and `lock_recompute` may then lower that running thread.
- `thread_wake_op` returns `op_ok()` with no check after `end_park`, while `lock_wake_op` does (`ready_above(...)` → `NEED_RESCHED`). `on_timer_interrupt` sets nothing after `expire_parks` either.
- **Sequence:** L holds a lock and runs at level 3, inherited from H, which waits on it wakeably. L calls `THREAD_WAKE_OP(H)`. H is pushed at 3, which is not above L's 3, so no switch is asked for. `lock_recompute` then lowers L to its base. L returns to user mode at level 1, with H ready at 3.
- A deadline firing in the timer interrupt does the same. That breaks §7's "a lower level does not run while a higher one is ready", the rule the lock's own give honours ("a give that lowers the giver below a ready thread gives the processor up at its return").
- With no tick, as in every K1 image, it lasts until L blocks, yields or exits.
- **Fix:** recompute before the push, or check `ready_above` after the recompute in `end_park`, for both the wake and the expiry.
- **Pin, with no clock:** the raised holder calls `sos_thread_wake(H)` and then prints a line. H's `Woken` line must come first.

**2. `deadline_join` asserts an order that depends on host time** (`tests/deadline-join`, the order "T parks on its Event" before "deadline: TimedOut").
- `main` reads the clock, sets `now + 20 ms`, and joins.
- A host stall of 20 ms or more between the clock read and the `Join` trap makes the op answer `TimedOut` at once. `main` never parks, T hasn't run yet, and the lines come out in the other order.
- sawos's rule is that an order is made by waiting on what the other side does. **Fix:** have `main` wait for a signal from T (or yield) before it reads the clock.

**3. The note's "not pinned until K2" is wrong for `ready_push` clearing `park_wakeable`.** The plain pipe parks (`Call`'s room and reply parks, and `ReplyWait`'s wait leg) never call `record_park`. So with the clear removed, a thread whose wakeable `Wait` or `Join` ended by delivery carries `park_wakeable` and its old deadline into a later plain `Call`. Then `expire_parks` ends that plain park `TimedOut`, leaving `call_pipe`/`call_claim` and the exchange tie behind. That's pinnable in K1: a wakeable `Wait` answered by delivery, then a plain `Call` that outlasts the old deadline.

**4. Docs:**
- `sos_lock_wait`, `Lock.take` / `sos_lock_take` ("Ok or Revoked"), `sos_thread_join` and `sos_waiter_wait` don't mention `TimedOut`, `Woken` or the park-time `AccessDenied`.
- `tests/quota-set-order` still says 17 where it prints 33.
- `park_deadline`'s doc says `UInt64.max` for none, but the literals write 0. That's harmless, but the doc is wrong.

**Worth a case each.** The agent lists more checks no case reaches; these are the ones that guard a spec sentence:
- a plain park neither reading nor clearing a latch set before its op;
- `Woken` from a latch at `Wait`, `Join` and the lock (only `PARK_OP` is tested);

- readiness first at `LOCK_WAIT_OP` with a passed or latched word;
- a stale ID after its slot is reoccupied;
- `expire_timers` before `expire_parks` in one fire.

**The implementer's note for R2 (the one-word lock's runtime seams in `sos.exec`).**

**The seams (`kernel/sysapi/src/exec.saw`).**
- **The identity** is the record's address, taken at the first lock if the thread has none yet, or `sos_rt_lock_owner`'s odd number on a thread with no block.
- **`__saw_rt_lock_acquire`:**
  - It panics, naming the lock by address, if the word already holds the caller's identity, block or not.
  - A record thread at depth 0 takes its own pair (owner = thread ID) **before** the swap, then swaps 0 to its identity. A failed swap gives the pair back, with `LOCK_WAKE_OP` if the waiters flag is set.
  - On contention it reads the holder:
    - a record holder is waited on with `LOCK_WAIT_OP` on its pair, with the wait word 0, so the park is plain. `Ok` swaps again, `Revoked` panics naming the lock, and anything else panics;
    - an odd holder is spun on, yielding through the block's Thread handle when the waiter has one and spinning when it doesn't.
  - It raises the depth after the swap.
- **`__saw_rt_lock_release`:** it swaps its identity back to 0, panicking if it wasn't the holder, and drops the depth. At 0 it clears the pair's owner, with `LOCK_WAKE_OP` if the waiters flag is set.
- The bodies use only floor ops and atomics, plus the allocator for a thread's first record.
- `give_record_back` keeps a record whose depth isn't 0, so a thread that ends holding the lock keeps its record for good.

**The record's words (8):** next, claimed, thread ID, parked, seen, the pair's owner and waiters flag (adjacent), and the lock depth. A claim zeroes the last three.

**The pair-first order (lead's ruling).** Taking the pair before the swap means a waiter that reads a record from the word always finds that record's pair held. - **The order is sound on one core.** The pair is taken before the swap and given back on a failed try; release goes swap, then owner 0, then flag, then wake; the kernel's read-and-park is one masked trap. - **The self-check** is right with a block and without, since record addresses are even and lock-owner numbers odd.
- **The pair** is taken and cleared only at depth 0.
- **`give_record_back`** keeps a record held at depth ≠ 0, so a dead holder's waiters get `Revoked`.

An agent read it against §7, §10.1 and sawlang's `runtime/ABI.md`. I booted a probe for each item below that says so (riscv32, sawlang v0.24.6, no tick, direct seam calls as the recursion cases make them).

**1. ✓ A waiter waits on the holder's record, not on the lock. So a lock its holder gives back while holding another isn't handed on, and an acyclic lock order can kill the process.**
- **Why:** `wait_for` parks on the holder's pair, which is given back, with the wake, only at depth 0.
- **The two texts disagree:** §7 says exactly that ("answers once the holder has given back every runtime lock it holds"), but the ABI's contract for these seams is "acquire blocks the calling thread until the lock is held; release hands it on". And std's `Mutex` takes these seams in `sync` windows, which nest.
- **Probe 1** (`probe-lock-nested`): T takes A and then B; W, at T's level, waits for B; T gives B back and yields 64 times.
  - `after B's release, W got B: false`, then `after A's release, W got B: true`.
  - A T that then waits on W while still holding A never gets past it.
- **Probe 2** (`probe-lock-chain`): T (Low) takes M1 and M2 and yields; W (High) takes M3 and waits for M2; T gives M2 back and takes M3. The order M1→M2, M1→M3, M3→M2 has no cycle.
  - Output: `W holds M3 and waits for M2` / `T gives M2 back` / `T takes M3` / `SOS: process fault: a lock wait closes a cycle or passes the bound`.
  - W is still parked on T's pair, so T's wait on W's pair closes the kernel's chain.
- **A related trace:** T holding A and B gives B back and exits holding A, so W, waiting for B, panics "its holder exited holding it" with B free.
- **A fix that keeps inheritance:** a release at depth > 0 whose pair has its waiters flag set gives the pair back, with the wake, and takes it again. The woken waiters swap again; those whose lock is still held park on the pair once more and raise the holder again. Or move to a pair per lock.
- **Either way §7 changes,** so this is the owner's design to rule on. The patch matches the spec as it stands.

**2. ✓ A holder with no block below its waiter is a livelock.**
- **Why:** the waiter on an odd holder takes its pair, fails the swap, gives the pair back and yields, but a yield never runs a lower level.
- **Probe** (`probe-lock-odd-below`): T, with no block, at Low, takes the lock; main, at Normal, acquires it. It prints `T holds the lock: true` and then QEMU hangs. Nothing is blocked, so the kernel reports no deadlock.

- An odd holder that exits holding the lock leaves its waiters spinning for good, with no `Revoked`.
- **A ruling or a mechanism:** state it as the program's obligation (a thread with no block shares no runtime lock with a higher thread), or give the spin a way down.

**3. `lockseam_noblock_spin` depends on host time.** T parks on a 5 ms deadline (`WORD = now() + DELAY_NS`, then `sos_park()`) to order itself against main.

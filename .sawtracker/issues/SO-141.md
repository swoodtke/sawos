## Description

**sosrt runs Saw's background tasks: the freestanding executor set and SL-1150's drive and close.** sawlang's SL-1150 (design done, Nov 17) lets `Task.spawn` (and `TaskGroup`) work freestanding for a runtime that claims the thread's background group: two compiler-defined entries, `__saw_background_drive() -> Int64` (one bounded turn over the thread's tasks; -1 nothing live, 0 runnable now, INT64_MAX waiting with no deadline, else the earliest deadline in monotonic ns) and `__saw_background_close()` (cancel, join, release). sosrt exports none of the freestanding executor set today, so any spawn fails at link in a sawos image.

**Build (after SO-124 gives threads a real entry, and after the sawlang release carrying SL-1150):** the executor set sosrt must export (from sawlang's runtime/ABI.md); the per-thread executor word in the architecture's thread register (riscv32's `tp` and the S3's `THREADPTR` are already saved per thread in the trap frame; arm64's `TPIDR_EL0` is not and must join the frame, a kernel change); the drive in `sos`'s blocking wrappers (`Waiter.wait` and the pipe calls), bounding the wait by the drive's deadline with a Timer attached to the Waiter and ending it from another thread with an Event (`reactor_wake`); the close on every thread's return into sosrt's thread entry; the declaration on the process side only (the kernel image keeps `Task.spawn` refused). `Process.exit` does not close (the teardown frees the whole process).

An agent read it against the base's spec text, and I rechecked the main finding in the code. One scheduling bug and one host-time test need fixing first.

**1. An early end can leave the running thread below a thread it just readied** (`refs.end_park`).
- `end_park` calls `ready_push(t)`, then `lock_recompute(holder)`. `ready_push` compares the woken thread with the running thread's level as it is at the push, and `lock_recompute` may then lower that running thread.
- `thread_wake_op` returns `op_ok()` with no check after `end_park`, while `lock_wake_op` does (`ready_above(...)` → `NEED_RESCHED`). `on_timer_interrupt` sets nothing after `expire_parks` either.
- **Sequence:** L holds a lock and runs at level 3, inherited from H, which waits on it wakeably. L calls `THREAD_WAKE_OP(H)`. H is pushed at 3, which is not above L's 3, so no switch is asked for. `lock_recompute` then lowers L to its base. L returns to user mode at level 1, with H ready at 3.
- A deadline firing in the timer interrupt does the same. That breaks §7's "a lower level does not run while a higher one is ready", the rule the lock's own give honours ("a give that lowers the giver below a ready thread gives the processor up at its return").
- With no tick, as in every K1 image, it lasts until L blocks, yields or exits.
- **Fix:** recompute before the push, or check `ready_above` after the recompute in `end_park`, for both the wake and the expiry.
- **Pin, with no clock:** the raised holder calls `sos_thread_wake(H)` and then prints a line. H's `Woken` line must come first.

**2. `deadline_join` asserts an order that depends on host time** (`tests/deadline-join`, the order "T parks on its Event" before "deadline: TimedOut").
- `main` reads the clock, sets `now + 20 ms`, and joins.
- A host stall of 20 ms or more between the clock read and the `Join` trap makes the op answer `TimedOut` at once. `main` never parks, T hasn't run yet, and the lines come out in the other order.
- sawos's rule is that an order is made by waiting on what the other side does. **Fix:** have `main` wait for a signal from T (or yield) before it reads the clock.

**3. The note's "not pinned until K2" is wrong for `ready_push` clearing `park_wakeable`.** The plain pipe parks (`Call`'s room and reply parks, and `ReplyWait`'s wait leg) never call `record_park`. So with the clear removed, a thread whose wakeable `Wait` or `Join` ended by delivery carries `park_wakeable` and its old deadline into a later plain `Call`. Then `expire_parks` ends that plain park `TimedOut`, leaving `call_pipe`/`call_claim` and the exchange tie behind. That's pinnable in K1: a wakeable `Wait` answered by delivery, then a plain `Call` that outlasts the old deadline.

**4. Docs:**
- `sos_lock_wait`, `Lock.take` / `sos_lock_take` ("Ok or Revoked"), `sos_thread_join` and `sos_waiter_wait` don't mention `TimedOut`, `Woken` or the park-time `AccessDenied`.
- `tests/quota-set-order` still says 17 where it prints 33.
- `park_deadline`'s doc says `UInt64.max` for none, but the literals write 0. That's harmless, but the doc is wrong.

**Worth a case each.** The agent lists more checks no case reaches; these are the ones that guard a spec sentence:
- a plain park neither reading nor clearing a latch set before its op;
- `Woken` from a latch at `Wait`, `Join` and the lock (only `PARK_OP` is tested);

- readiness first at `LOCK_WAIT_OP` with a passed or latched word;
- a stale ID after its slot is reoccupied;
- `expire_timers` before `expire_parks` in one fire.

**The implementer's note for R2 (the one-word lock's runtime seams in `sos.exec`).**

**The seams (`kernel/sysapi/src/exec.saw`).**
- **The identity** is the record's address, taken at the first lock if the thread has none yet, or `sos_rt_lock_owner`'s odd number on a thread with no block.
- **`__saw_rt_lock_acquire`:**
  - It panics, naming the lock by address, if the word already holds the caller's identity, block or not.
  - A record thread at depth 0 takes its own pair (owner = thread ID) **before** the swap, then swaps 0 to its identity. A failed swap gives the pair back, with `LOCK_WAKE_OP` if the waiters flag is set.
  - On contention it reads the holder:
    - a record holder is waited on with `LOCK_WAIT_OP` on its pair, with the wait word 0, so the park is plain. `Ok` swaps again, `Revoked` panics naming the lock, and anything else panics;

# SO-141 K3: one-word locks, the kernel's only lock

**The owner's ruling (Nov 29).** Every lock in a process is one machine
word. The word holds the holder's thread ID, with one bit meaning "a thread
waits". The kernel's lock ops take that word, and every lock works this way:
`sos.Lock`, the runtime's output lock, and std's lock seams
(`__saw_rt_lock_acquire`/`_release`). The two-word pair (owner word plus a
separate waiters flag) goes away.

**Why.** Std gives a lock one word. Today's kernel lock needs two, so R2 put
one pair per thread and made waiters wait on the holder thread instead of on
the lock. The reviewer of SO-141.p5 found the two faults that follows from
that:
1. **Nested locks aren't handed on.** A lock given back while its holder
   holds another isn't handed to its waiters, and an acyclic lock order can
   close the kernel's chain.
2. **A holder with no block can't be raised.** One running below its waiter
   livelocks it.

A per-lock word with the holder's ID fixes both, as Linux's PI futexes do.
Read `.leadwork/SO-141/r2-review.md` for both findings and their probes
(`.leadwork/SO-141/r2-probes/`).

This is a kernel unit, with the spec, `sos.Lock` and the output lock in it.
R2's std seams are reworked on top of it afterwards, as a separate unit.

## Read first

- spec.md §7:
  - "Every thread has an ID" (the ID's split);
  - "Inheritance inside a process: the lock" and "The lock's answers";
  - the wait word's rows for `LOCK_WAIT_OP`;

## Build

1. **The word.**
   - 0 while free. Otherwise the holder's thread ID in the low bits, with a
     waiters bit, `LOCK_WAITERS_BIT`, the word's top bit.

     plus generation fills the word: 12 index bits and 19 generation bits
     on the 32-bit boards, so the top bit is free. Keep the compile-time
     asserts that the fields fit, now with the bit.
   - Say the cost in the spec: a slot's ID repeats after 2^19 reuses
     instead of 2^20.
2. **The ops**, made with `NO_HANDLE` and needing no right, as today:
   - **`LOCK_WAIT_OP(addr)`:**
     - It reads the word through the copy-in door, in the same trap as the
       park.
     - 0 answers `Ok` at once, so the caller swaps again.
     - A word naming a live thread of the caller's process sets the waiters
       bit in the word (a compare-and-swap on the process's memory, retried
       while the ID is unchanged), parks the caller, and raises the holder
       and its chain, as today.
     - A word naming a dead thread answers `Revoked`. One naming another
       process's thread, or nothing, is the fault the spec gives today.
     - The wait word applies as for every park.
   - **`LOCK_WAKE_OP(addr)`:** made by a holder whose release found the bit
     set. It answers every thread of the process parked on that word and
     brings each holder they named back to its due level.
   - **Release, in the process:** a compare-and-swap of own ID to 0 with no
     trap when the bit is clear. Otherwise swap to 0, then
     `LOCK_WAKE_OP`.
   - **Acquire, in the process:** a compare-and-swap of 0 to own ID. On
     failure, `LOCK_WAIT_OP`, then try again.

     its word. Faults and alignment are as today, for one word instead of
     two.

**The implementer's note for SO-141.p7 (K3: one-word locks, the kernel's only lock, per the owner's ruling).**

**The word.**
- 0 while free. Otherwise the holder's thread ID, with the top bit `LOCK_WAITERS_BIT` (`UInt.max ^ (UInt.max >> 1)`, in `kernel/abi/src/ops.saw`, exported by `sos`).
- **The ID split:** 12 index bits and 19 generation bits on riscv32, flat, the C3, the S3 and r8 (down from 20); arm64 keeps 12 and 20, since its 64-bit word has room. `limits.saw` asserts that index plus generation bits fit in word bits minus 1.

**The ops.**
- **`LOCK_WAIT_OP`:**
  1. it checks the word with the one-word copy-out door (`BadAlign`, or the door's fault) and reads it;
  2. 0 answers `Ok`, and the caller's own ID is `BadState`;
  3. otherwise `thread_named` decodes it: `Revoked`, or `BadArg` with the other-process line, and the bit alone is `BadArg`;
  4. the chain check and `park_plan` run;
  5. it sets the bit with a new `copy_out_swap` (a compare-and-swap on process memory), retrying while the word names the same holder and answering `Ok` if it names another or none;
  6. it parks the caller and raises the chain.
- **`LOCK_WAKE_OP`:** it checks the word, then answers every thread of the process parked on that address and recomputes each holder's level. It writes nothing.
- **Give, in the process:** a compare-and-swap of own ID to 0 with no trap. Failing that, own ID plus the bit to 0, then the wake. Failing both, a panic: the caller doesn't hold it.
- **Take:** a compare-and-swap of 0 to own ID, then `LOCK_WAIT_OP` and try again.

**The users moved.** `sos.Lock` is one `Atomic<Int>`, and `sos_lock_take`/`sos_lock_give` take its address. The output lock in `rt/common` is one word, with its hooks in `rt.saw`. The tests that used pairs now use words. lock-root's foreign wake gives back with `sos_lock_give`, since a wake clears nothing now.

**Case `lock_word`** (every profile, the S3 and r8; no tick, every order forced), each mutant red on riscv32:

| round | shows | mutant |
|---|---|---|
| NESTED | T holds A and B and gives B back; W gets B while T holds A | wake only at the last release |
| ACYCLIC | M1→M2, M1→M3, M3→M2: no fault, every thread finishes | the same mutant (`LockChain` fault) |
| NO BLOCK | a holder with no block, below its waiter, is raised | the wait never raises |
| HOLDER EXITS | the waiter's take answers `Revoked` | exit skips revoking |
| BIT CLEAR | 100 takes and gives make 0 syscalls (the kernel's count) | give always traps |
| BIT SET | the word reads ID plus bit while W waits, and the give wakes W and leaves 0 | give doesn't wake; the kernel never sets the bit |
| ID SPLIT | no ID carries the bit | 20 generation bits on riscv32 (the build fails on the assert) |

**Moved expectations, all in `lock`:** "pair" becomes "word" in three lines, and `straddle` becomes `last word`, which answers `Ok` since a one-word lock can't straddle. Every other lock case passes unchanged.

**The spec.**
- §7's ID split and its cost: an ID repeats after 2^19 reuses on 32-bit boards;
- §7's lock is rewritten as the single mechanism: handed on where it's given back, every holder can be raised, and no give is lost on one core or two, since the bit is set before the park and the release swaps then wakes;
- "the lock's answers", process-local locks, the `sos` side and the runtime's locks are reworded;
- R2's per-thread pair is removed, and so are the record's pair and depth in §10.1;
- §5.7's rows;
- §11 keeps only "the runtime's lock seams over §7's lock", which is R2's rework.

# SO-141 K4: a contended release hands the lock to the highest waiter

**The owner's ruling (Nov 29).** A release that finds the waiters bit set
gives the lock, in the kernel, to the highest-priority waiter, and wakes
only that waiter. Nobody can take the lock between the release and the
new holder running.

## What is there

K3, the one-word lock, is on main (or about to merge; it is SO-141.p7):
- the word holds the holder's thread ID, with `LOCK_WAITERS_BIT` on top;
- the release swaps the word to 0 and, with the bit set, makes
  `LOCK_WAKE_OP`, which wakes every thread parked on the word;
- each woken waiter retries its own swap, and the first to run wins.

That lets a running thread take the lock while the word is 0 (barging),
lets an equal-priority thread that gives and re-takes in a loop starve
its waiters, and wakes waiters that will only park again. Read spec §7's
lock section, K3's note on SO-141, and the K3 code (`dispatch.saw`'s
`lock_wait`/`lock_wake`, `kernel/sysapi/src/exec.saw`'s
`lock_take`/`lock_give`, `rt/common`'s output lock).

## Build

1. **The hand-off, in the kernel's wake.** A contended release becomes one
   op. Name it as you see fit: `LOCK_WAKE_OP` changed, or a new op. The
   kernel then:
   - checks that the caller holds the word (its ID, with the bit) and
     faults otherwise, as the give's panic does today;
   - picks the highest-level thread of the process parked on that word,
     breaking ties by the longest wait. That needs a park order the kernel
     keeps, such as a sequence number stamped at the park; if that's
     costly, break ties by slot order and say why;
   - writes the chosen waiter's ID into the word, with the bit still set
     if other waiters remain, or clear if none;
   - wakes only that waiter, answering its wait `Ok` **as the holder**,
     and recomputes the old holder's level and the new holder's (the
     remaining waiters now raise the new holder).

   The read, the choice, the write and the wake are one trap.
2. **The waiter's side:** a wait answered `Ok` by a hand-off means the
   thread now holds the lock, with no swap to retry. Tell this apart from
   the wait's at-once `Ok`, when the word was 0, which still means retry:
   use a distinct answer value, or a status, or re-read the word and
   compare with own ID. Say which, in the spec.
3. **The users:** `lock_take`/`lock_give` in `sos.exec` (which `sos.Lock`
   and R2's std seams share), and the output lock in `rt/common`.
4. **Revoked, and a dead or early-ended waiter:**
   - a waiter whose park ended early (a deadline, a wake) or that was
     killed is never chosen;
   - if no live waiter remains, the word becomes 0;
   - a holder that exits holding the lock still answers its waiters
     `Revoked`, as K3 does.
5. **The spec (§7):** the release, the wait's answers, the hand-off and
   its tie-break, and that no thread can take a lock between a contended
   release and the new holder running.

## Cases

Each case needs a red mutant. Order by construction, and assert no time.
- **No barging:** an equal-priority thread gives and immediately re-takes
  in a loop while W waits. W gets the lock at the first contended give.
  Mutant: the old wake-all.
- **Only the chosen waiter wakes:** three waiters at different levels, and
  the highest gets the lock. The others stay parked, with a count the
  kernel keeps or by construction. Mutant: wake all.
- **The tie-break:** two equal waiters, and the one that parked first gets
  the lock. Mutant: slot order (or the reverse, if slot order is the
  rule).
- **The bit stays while waiters remain** and clears with the last.
- **A waiter whose park ended early** (a deadline on its wait word) is
  skipped.
- **Every existing lock case** passes (`lock`, `lock_word`,

## Description

**Move the sawlang pin from v0.24.0 to v0.24.1.** Tagged by the sawlang lead on Nov 14: `03326f4656243da2cd95ca69727aea196380587f` (`sawc 0.24.1`). Its contents are the description of sawlang's SL-1132.

**Why now: a memory-safety fix in safe code.** SL-1124: `==` or `!=` of an Optional with a bare value of its payload type (`s == want` with `s: String?`; any payload not trivially copied; `T? == T` in a generic body) wrapped a reference as the Optional's payload, giving wrong answers, crashes and out-of-bounds reads in every earlier release. v0.24.1 tests presence and compares the payload in place.

**What else is in it, and what can change for this tree:**
- **Refused now:** a comparison of an Optional with a bare value that only a member declared on `Optional` in an extension answered. Search for any extension on `Optional` in the tree.
- **SL-1120 and SL-1131:** an error a `main` returns is written whole, however long (it was cut at 512 bytes). The image builder's `main` returns `Int` and prints because of the old cut; returning `Result<Void, E>` again is a separate change, not this unit's.
- **`libs/toml` unit 1** (the typed reader) is in it; Blade itself still reads manifests through the old reader in this release, so no manifest reading changes.
- **Blade's up-to-date check** now covers nested sources, a root `main.saw`, a dependency's manifest, native units, the C compiler and linker, `SAWC` and the compiler's version. Keep every `--force` the runner and the builder pass: a rebuilt compiler with an unchanged version is still not seen.
- **Known, not fixed in it:** SL-1133 (windowed Xtensa: the frame pointer is an argument register; this tree compiles no windowed Saw), SL-1134 (a capturing closure called where it is written is never dropped: search the tree for a closure literal called in place, `}(`, and say what you find).

**The oracle.** The gate resolved by fetch as the server does, at the old pin and the new, the two outputs diffed and every difference explained (the toolchain line is expected; image sizes may move with a compiler change: list and explain each).

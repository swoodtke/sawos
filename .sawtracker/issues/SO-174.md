## v0.24.5's changes since v0.24.4 that touch sawos

Read sawlang's `runtime/ABI.md` in the toolchain checkout for the exact
rules.

1. **SL-1161: no seam runs program code on the caller's thread.** A seam may
   block, spin or return an error. It never calls back into the program's
   Saw code, and never runs one of the thread's tasks before it returns.
   - Check each seam sosrt defines against that rule: `rt/common`,
     `rt/main`, `kernel/sysapi/src/rt.saw`, and the kernel's side.
   - List each seam with one line on why it holds. Change nothing that
     already holds.
   - The same change makes a group's teardown in a task park, and adds the
     `coro.window-drives` refusals inside a static root's exclusive
     `borrows(sync)` window. Fix any refusal by moving the call out of the
     window. If a refusal looks wrong, record the program and the error in
     your note rather than working around it.
2. **SL-1150: `Task.spawn` with no operating system underneath.** A runtime
   that declares `__saw_background_drive` and `__saw_background_close` owns
   the thread's background group (runtime/ABI.md, "The background group").
   - Don't declare them in this bump. Running background tasks is its own
     unit.
   - If the bump forces a change here (a new required symbol, say), make the
     smallest one, and say so in your note.
3. **SL-1156 U7c: root-free at creation.** A closure, function pointer,
   erasure or hook that reaches a lent static root is refused where it is
   made. sawlang checked that sosrt's heap table is unaffected. Fix any
   refusal it raises anyway, and list it.
4. **SL-1197: the sosimg header's `reserved0` word is now `rt_map`.**
   Version 4 is written only when the word is nonzero, and a loader opts in
   with `reads_rt_map: true`.
   - Don't opt in here. Leave the loader reading as it does.
   - Check that every image sawos builds today still has the version and
     header the kernel's loader accepts: the gate does.
   - If `imgformat`'s API changed shape, adapt the callers without changing
     behaviour.
5. **SL-1190: hosted builds split codegen units by default.** Freestanding
   objects are unchanged. If the image builder's or a hosted package's build
   or tests change because of it, say how.

**Approved.** The pin moves both lines together: `version = "0.24.5"` and `sha = "cb66b6327f08b61fbd912f6e412484e155d5b2dc"`, which is `v0.24.5^{commit}` in sawlang, as I checked at the tag.

**The loader:** its one edit is the zero header's field, `reserved0` to `rt_map`. The header check still calls `has_known_version()` with its default, so the kernel accepts version 3 alone and refuses a v4 image until the code that honours `rt_map` passes `reads_rt_map: true`.

**No refusal fixes were needed** (SL-1156 U7c, `coro.window-drives`), which matches the sawlang lead's reading of the heap shape.

**v0.24.5's seam rule, read against sosrt:**
- `__saw_rt_panic` takes the output lock and traps to `sos_rt_abort`;
- `__saw_rt_alloc` and `__saw_rt_dealloc` run the runtime's own heap and arena code;
- the write, lock-owner, yield and output-lock seams trap or run the runtime's own lock;
- every `sos_rt_*` hook they reach is defined in sawos's own `kernel/sysapi/src/rt.saw` (a process) or `kernel/core/sched.saw` (the kernel), never by the program.

No seam runs program code on the caller's thread.

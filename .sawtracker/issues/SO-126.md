## Description

**Windowed Saw processes on the ESP32-S3** (the windowed-threads design's U5, `SO:windowed-threads`). The kernel runs windowed processes beside call0 ones (window handlers, Alloca, the 64-register frame, one start state); every windowed case today is hand-assembled. The pin is now sawlang v0.24.2, which compiles Saw for the windowed ABI.

Build what the design's U5 lists: an S3 process package compiled windowed (the `[sos.xtensa-esp-unknown-elf]` section's way of choosing the ABI, or what sawlang provides), its runtime (`sosrt`, the syscall stub, `_start`) in that ABI, and cases that run a real Saw program windowed in the S3 smoke: deep recursion that overflows and underflows the window file across a preemption, a windowed and a call0 process side by side, and a windowed process's fault reported as its own. Read the design for the rules a windowed entry must keep (the start state, `retw` from the first frame). If sawlang lacks something this needs, stop and say what, for the sawlang lead.

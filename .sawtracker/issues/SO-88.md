## Description

## Why

The pinned compiler (v0.22.0) wraps an enum case written by name into a
`Result<integer, E>` slot as `Ok(raw)` (SO-87). sawlang fixes it in
SL-1087, in the release after v0.22.0. The sawlang lead posts the version
and sha in the chat room when the tag exists.

## The unit

1. Bump `sawlang.pin`'s two lines together to the tagged release (user
   ruling: pin only at a tag).
2. Build and run the gate and both smokes under it. A build under the
   fixed compiler is the proof that nothing else in the tree depended on
   the old wrap: any case whose behaviour changes is a finding, reported
   with its transcript, not adjusted.
3. Read the release's notes for anything else that moves (the lone-case
   fold into `UInt?` and into a `Result` with another enum as its error
   stays as it was, pending a sawlang ruling).
4. The four sites that spell `Result<…>.Err(error: …)` with a comment about
   the old behaviour (`translate_user`, `handle_rights`, `ceiling_word`,
   `tests/pipe-table-full`) may return to the bare case, and their comments
   go, once the pin has the fix. Do it in the same patch, or say why not.

## Acceptance

- [ ] the pin at the tag, both lines
- [ ] the gate and both smokes green under it; anything that moved, named
- [ ] the four sites and their comments settled

**Brief (lead): the tidy-up that closes this issue.** Both things it waited on have landed (SO-84, SO-90) and the memory work that touched the same files is merged (SO-92).

**1. The spelled-out `Err` sites return to the bare case.** At the pinned compiler a case of a `Result`'s written error enum, given bare, is the `Err`. Every site that spells `Result<…>.Err(error: …)` only because the older compiler wrapped a bare case as `Ok(raw)` goes back to the bare case, and the comment explaining the spelling goes with it: `translate_user`, `handle_rights`, `ceiling_word`, `tests/pipe-table-full`, and any other the grep finds (`Result<.*>\.Err(error:`). Leave a spelled-out `Err` that is there for another reason, and say which and why.
- Caution, from the sawlang lead: with an ERASED error type (`Result<UInt, Box<any Error>>`) a bare case is still `Ok(raw)` at this pin. None of these sites has one; if you find one, leave it spelled out.
- Each site keeps its behaviour: the cases that reach it stay green, and for each site name the case and line that would go red if the bare case were wrapped as `Ok`.

**2. `SosStatus.NoResource` says what it means.** It prints as "out of kernel objects", which describes a full slab. It also answers a `map` that meets a row its target holds, a handle table or a grant record with no room, a donation too small to hold one slot or of a pool with no bytes, and more: read every place the kernel answers it and the spec's words for it. Widen its console text and its doc in `kernel/abi/src/status.saw` (and wherever `sos` documents it) to one short phrase true of all of them. The lead's proposal: **"the kernel has no room for it"**; take it unless reading the uses shows it false for one, in which case say which and propose another.
- The old text is asserted in many cases (the runner names it about as often as any line). Change every expectation and every comment that quotes it, in the runner, the packages, each HAL's `ABI.md` and `README.md`, and `spec.md` if it quotes the text. No behaviour changes: after the change, the only difference in any case's console is that phrase.
- The runner matches expected lines by substring, so check that the new phrase is not a substring of some other status's text or of a failure line a case prints when it is red.

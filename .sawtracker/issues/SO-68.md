## The ruling

A third universal op, **`INFO_OP`**, beside `RELEASE_OP` (`0xFFFF`) and
`MINT_OP` (`0xFFFE`) in `kernel/abi/src/ops.saw`. It is intercepted before the
dispatch decides the kind, as those two are. On any word in the caller's own
table it answers facts about **that handle**:
- **its rights word;**
- **its kind.**

**No right gates it.** It describes the caller's own handle, not the object,
and every op on the object is still checked on use. It spends none of the
reserved universal bits. A word that doesn't resolve is the ordinary
`BadHandle` fault.

**A handle to an invalid object answers normally:** the handle and its rights
still exist. It describes the handle, not the object.

## Decisions for you (report each)

1. **Two values, one value register.** A syscall answers one status and one
   value (`kernel/core/result.saw`). A rights word is a `UInt32`, and on riscv32
   it may use all 32 bits (each kind owns bits 8–31), so packing kind and rights
   into one word doesn't fit. The lead's suggestion: `INFO_OP` takes a selector
   argument, a small published enum (`HandleInfo.Rights`, `HandleInfo.Kind`,
   room for more), and answers that one value. An unknown selector is a
   `BadArg` fault. A copy-out record, as `Stats` uses, is acceptable if it is
   clearly simpler. Pick one and say why.
2. **The kind's spelling.** The kind number is `ObjType`'s, which `sosabi`
   holds and `sos` doesn't export. The typed tier doesn't need it, since each
   wrapper knows its kind. Publish whatever the C floor needs to spell kinds,
   and keep the typed API free of raw kind numbers unless a typed use appears.

## The change

1. **Kernel:** `INFO_OP` in the universal-op interception (where `RELEASE_OP`
   and `MINT_OP` are dispatched); `static_assert`s holding every per-object
   table below it, as the others have.
2. **Typed tier:** `rights() -> Result<UInt32, SosStatus>` (or the plain value,
   if it can't fail for a live wrapper; say which) on **every** handle wrapper:
   `System`, `Process`, `Thread`, `Event`, `Waiter`, `Interrupt`, `Clock`,
   `Timer`, `Memory`, `IoMemory`, `Mapping` and the four pipe ones. Put it in
   one shared helper the wrappers call.
3. **Floor:** `sos_handle_info(handle, selector, out)` or the equivalent in
   `kernel/sysapi/src/floor.saw`, with its doc.
4. **Docs:**
   - `MINT_OP`'s doc says "There is no rights-introspection op (a process
     cannot ask what a handle carries)". Rewrite it: the keep mask still needs
     no introspection, and introspection now exists for other reasons.
   - Update `rights.saw`'s universal-byte comment if it lists introspection as
     a candidate bit: the op is ungated, so it takes no bit.
5. **Spec:** §3's universal ops (grep `MINT_OP` and `RELEASE_OP` in §3) gain
   `INFO_OP`.
   - State that it is ungated, why (it describes the caller's own handle), and
     that it answers normally on an invalid object.
   - Say it makes "a missing right is a caller-checkable fault" literally
     checkable for a received handle.
   - No issue numbers; 80 columns.

## Tests

One case, or a few small ones:
1. `rights()` on a default handle of several kinds (an Event, a Memory region,
   a Process from `process_self`) matches the kind's default set. Print and
   assert the values against the runner's known defaults, or assert specific
   bits with the exported enums.
2. A `mint(rights:)`-narrowed sibling reports exactly the narrowed set.
3. A handle received through `give` with a keep mask reports the given rights
   (child side).
4. The kind selector answers the right kind for two kinds.
5. A released (stale) word is the `BadHandle` fault.
6. An invalid object's handle (an Event survives its owner, so use a Thread or
   Timer invalidated by its owner's death, held through a give) answers
   normally.

## Description

**ESP32-S3: the kernel sleeps when idle (`waiti`), instead of spinning.** The owner's priority for power (Nov 16). Today `hal/xtensa-esp32s3/kernel/lib.saw`'s `wait_for_irq` is empty and the idle loop spins on `irq_poll`, so the core runs flat out with nothing to do. `ABI.md` §6d says why: `waiti n` sets INTLEVEL to n and wakes only for an interrupt it will then take, so the C3's shape (sleep masked, wake, poll) is not available, and an interrupt taken at idle arrives in kernel mode, which the trap entry does not handle (the kernel runs at INTLEVEL 15 and takes interrupts from user mode only).

**Build:** an idle that executes `waiti` at a level that lets every line the kernel uses in (the tick, and each device line bound to an Interrupt), and a kernel-mode entry for an interrupt taken there: it takes nothing else (an interrupt in kernel mode anywhere but the idle `waiti` is a kernel fault, stated and tested), puts INTLEVEL back to 15 and returns into the idle loop, whose `irq_poll` then finds the pending line as today. Nothing above the HAL changes (`kernel/core/irq.saw`'s idle shape stays). Find each vector a line can arrive on (level 1 and the levels SYSTIMER and the device lines use) from the code, and say which the kernel uses.

**Plan first** and return a `CLARIFICATION REQUEST:` before building if the change reaches the spec, the trap frame, or any user-visible behaviour, or if the kernel-mode entry needs more than the idle case.

**Cases:** every existing S3 case unchanged (transcripts, totals; image sizes may move and are listed); a case that idles waiting on a Timer and on a device line and shows each woke the idle `waiti` (counted by the kernel, printed, asserted only as "at least one", per the no-host-time rule); the kernel-mode-interrupt-outside-idle fault. A board run through the reviewer under the owner's standing approval: `kill_churn` at `pll80` unchanged in time within noise, and an idle image that runs to its end. The review standard (the owner's ruling, Nov 15): every check and stop has a case that goes red when removed or inverted; list the mutants.

**Not in this unit:** light or deep sleep (chip-level clock gating, RTC wake sources), a tickless kernel, the C3's `wfi` (no board; its emulator never raises `mip`, as its `wait_for_irq` says).

**Lead: SO-133.p1 is up: the ESP32-S3 idles in `waiti`, under the owner's spec amendment** (Nov 16: "yes, amend the spec to allow kernel interrupt handling for waiti idle waits"). One commit on main 6adf9e09. Gate on the implementer's machine against a baseline of main: sos-test 1122, C3 smoke 7, S3 smoke 69 → 72 and 1 board-only; **only the three new S3 rows and the renumbering after them moved**; S3 image sizes grow (most +112 bytes; `preempt_tick`, `thread_preempt`, `timer_tick` +116; `timer_masked_in_kernel` +124; `bus_probe` +64); C3 unchanged.

**What it does.** `boot.S`'s `sos_idle_wait` (IRAM) is `waiti 0` then `ret` at `sos_idle_resume`. The kernel vector, after its Alloca test, compares EPC1 with `sos_idle_resume`: equal, it adds one to `sos_idle_wakes`, writes PS = 0x1F, `rsync`, takes a0 back from EXCSAVE1 and `rfe`s, so the level-triggered line stays pending and the idle loop's `irq_poll` finds it as before; otherwise `vec_fatal` as today (`SOS-S3: kernel fault vector=0x00000300 exccause=0x00000004`, 0x8C). `wait_for_irq` returns without sleeping when the timer is due (`timer_due()`, `irq_poll`'s own test, now shared), else calls `sos_idle_wait`; `hal.idle_wakes()` reads the count (`sink.c`). No EXCCAUSE test in the idle entry: EPC1 at the resume point can only be that interrupt (an equivalent mutant). The entry uses a0 (via EXCSAVE1) and a8 only.

**spec.md** states the one exception: §9's "never delivers" paragraph, §9's interrupt-line bullet, §7's "What is built", §9b, the Stats attribution sentence. `kernel/core/irq.saw`, `tests/preempt_tick.saw`, the HAL's comments and README, ABI.md §5a, §6c, §6d (with the probe below), §7f and §11's `waiti` bullet. The "taken from user mode only" serialization comments in `refs.saw` and `threads.saw` are left: the idle wake runs no kernel code.

**Probe:** this emulator's SYSTIMER fires for a target already behind the counter (TARGET0 at 1 ns, and 1 ms behind: `INT_RAW=1`, `INTERRUPT=0x2` 20 ms later, as for one 2 ms ahead). So the expired-timer guard changes nothing under emulation; it is for the part, whose alarm ESP-IDF treats as not firing for a past target. It still has its red case (M8).

**Cases (S3):** `idle_wake` (a deadline 1 ms ahead, then UART0's line, each `woke the idle waiti` with the count printed and not asserted; a deadline behind the counter, `did not sleep`), `kernel_irq_fault` (an interrupt at `rsil 0` in a kernel leaf), `kernel_irq_stray_waiti` (at a `waiti 0` of the test's own); both fault cases stop with the fault line and 0x8C.

**Mutants: 9, each alone, all red:** the EPC1 test removed (both fault cases) and inverted (`idle_wake`, both fault cases, `timer_oneshot`), the idle dispatch removed, the PS write removed, PS written with INTLEVEL 0, the count not incremented, the guard inverted, the guard removed, no sleep at all (the old spin). A board run follows under the owner's standing approval (`idle_wake`, `kill_churn` at pll80, and `kill_churn_profile` at pll80 from this commit and from main for before-and-after totals).

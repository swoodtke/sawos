## Description

**A case that parks a launcher on a Timer to let a child run now depends on host time.** Found when SO-120.p1's server gate failed `process_reclaim` on riscv32 (it passes alone on the patch's tree and on main, 15 of 15 each, here and on the reviewer's machine).

**Why, by reading.** `process_reclaim`'s root starts its child, arms a Timer `PARK_NS` (20 ms) out, attaches it, and waits, relying on the wait to park root so the child runs and dies first. `CLAUDE.md` states this idiom as safe: "a case that parks a launcher on a Timer to let a child run orders them by scheduling, not by the clock". That was true while a Timer became ready only when its interrupt was serviced. Since SO-83 (merged `0b6652a8`), a wait first brings a Timer up to the clock: if the host stalls longer than the Timer's delay between the arm and the wait, the Timer is already expired at the wait, the wait answers at once, root never parks, and the child has not run. The failed run shows exactly that: `SOS reclaim: started`, then `body_back_while_held=0 (no room for what was asked)` with no fault line between.

**What is built.**
- Every case that parks on a Timer to let another process or thread run first is found (the runner's cases and their packages; search for a Timer armed and then waited on before an assertion about what the other side did), and each waits instead on an observable that says the other side did it: the child's death (a `Process` attached to the Waiter), an Event the other side signals, or a count the kernel keeps. The Timer stays only where the case is about the Timer.
- `CLAUDE.md`'s sentence is corrected: a wait now answers at once for a Timer whose expiry has passed, so parking on a Timer orders nothing under a stalled host.
- Each changed case is shown red under construction where one can be made (for example a Timer armed with a delay of zero, which is expired at the wait), and green after.

**Acceptance**
- [ ] the list of cases found, each with what it now waits on
- [ ] `CLAUDE.md`'s rule corrected
- [ ] the gate green

## Owed, as a follow-up

**1. `tick_spinner` still parks on a Timer, and passes with no tick when the Timer has expired at the wait.** Root arms 50 ms, starts a child that spins forever, waits, and prints "timer fired while the child spun". With the case's tick turned off: at a delay of 0 the case passes (the wait answers at once; the child never runs); at 50 ms it hangs, as it should (chat f166, `setup_tick.py`; I ran both). A host stalled past 50 ms between the arm and the wait gives the first. The case is about the tick, not the Timer, so the issue's sweep covers it. It also runs in the S3 smoke.

**2. CLAUDE.md: "yield on an image with no tick, where a yield returns once everything else has parked" is not what a yield does.** The ready list is one FIFO (`sched.saw` puts the yielding thread on the tail, `ready_push` appends): a yield returns once every thread runnable at the yield has run until it blocked, yielded or exited. A thread woken during those turns runs after the yielder, and one that yields hands back early. `uart-cancel` leans on the narrower fact, which holds: the driver neither yields nor blocks before its first park.

**3. Comments that describe the old code.**
- `tools/sos_runner.py`, `pipe_child` and `pipe_delegate`: "root's first take necessarily answered `Ok(None)` ... so root parked on the child's death", and the same for "first look for the reply". Root makes no take or look before the death now; only the second half of each sentence was rewritten.
- `tests/irq-peer-gone`'s header: "`child-hold`, which sleeps first". The patch removes that sleep; `CHILD_SYSTEM` there still grants `ClockGet`.
- By the agent's reading of the kernel, not run: `pipe-delegate`'s `if not arrived` branch and `pipe-child`'s "nothing arrived" branch cannot run after a death (a claim whose obligation is released is ready; a dry ring with no inlet answers `PeerClosed`), so their comments describe a path that does not exist.

## What holds

- **Under load:** the 22 cases that use a changed package, 12 runs on each of riscv32, arm64 and riscv32-flat with six cores kept busy: 36 runs, no case red. That is seven cases more than the note names, since `child-hold`, `child-hold2`, `quota-exceeded`, `quota-vs-wall` and `uart-cancel` serve other cases too (`cases_of.py`).
- **Red under the old idiom** (the agent's run, riscv32): each of the twelve base packages with its park delay at 0 is red, `process_reclaim` with the server's own line, and `death_late_attach` is red without its scratch wait; all thirteen green as patched.
- **Each new wait is on something the other side does**, and what the case then asserts is settled by then: a death is reported after the teardown (spec §8); a pipe keeps what was written after its writer dies, and the only writer posts before dying, so one read misses nothing; `charge_disown`'s ready message follows all three spends; `death_late_attach` still attaches after the death to a Waiter that never watched the child, and gains a check (`polled != first`).
- **A passing run prints what it printed**: the runner's hunks are comments, and only failure-path strings changed in the packages.
- **CLAUDE.md's other new sentences** are the kernel's: a wait scans before it parks, and the scan brings each Timer up to the clock.
- **The Timer uses left** (about thirty packages, listed in `timer_sweep.txt`): each is about the Timer or the clock, but for `tick_spinner`.

Smaller: the patch changes 19 packages, and `child-disown` is not in the note's list; `uart-cancel`'s `PARK_NS` is a deadline now, not a park.

**Not run by me:** the C3 smoke's `isolation` and `tick_armed` and the S3 smoke's cases (the server's gate passed); the red runs, which are the agent's.

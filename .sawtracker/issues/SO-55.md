## Description

## Finding

claude-air-reviewer found this by code reading during the SO-39.p1 review. It has not been probed.

A reply may carry its own obligation word (the `PipeRequest` handle the reply is invoked through):
- `check_send` never compares a carried word with the invoking handle.
- In `pipe_reply_status`'s `Ok` arm, `hold_staged` unbinds that word and stages a reference on the exchange's own obligation column.
- `consume_entry` then unbinds the same index again. `unbind_handle` does not check that the index is bound, so the generation bumps twice and the handle quota is credited twice.
- It then unrefs a reference the handle no longer holds.
- The staged obligation is minted into the client, so a `PipeRequest` naming the exchange can outlive its settle.

The same mechanism applies to every op that consumes its invoking handle after staging (`reply_wait`).

## Proposed fix

- Refuse a carried word equal to the invoking handle with `BadArg`. The caller chose the handle, so it is a caller error.
- Consider making `unbind_handle` assert that the index is bound, so a double unbind is a kernel stop rather than a silent double credit.

## Description

## Finding

From claude-air-reviewer's review of SO-26.p1 r2 (SO-26 c6). The lead confirmed the call sites in `kernel/core/dispatch.saw`; nothing has been probed.

The Process op table's factory ops act on **`obj.slot`, the process the handle names**, not on the calling process `p`:
- `ThreadCreate` → `thread_create(obj.slot, …)`
- `EventCreate` → `event_create(obj.slot, …)`
- `WaiterCreate` → `waiter_create(obj.slot)`
- `InterruptBind` → `interrupt_bind(obj.slot, …)`

Each one charges `obj.slot`'s quota, mints into `obj.slot`'s handle table, and returns that word to the caller. A launcher holds its child's Process handle with every right (`process_rights()` is the one default set), so through a child's handle:
- **`EventCreate` / `WaiterCreate` / `InterruptBind`:** the launcher gets back a word that is meaningful only in the **child's** table, which sysapi then wraps as the launcher's own Event, Waiter or Interrupt. In the launcher's table that word names nothing, or a different object. The child is charged the quota.
- **`ThreadCreate`:** starts a thread **inside the child** at an entry point the launcher chose. That could be intended supervision, but nothing specifies it.

`PipeCreate` is the exception: it passes both `obj.slot` and the caller `p`. `ProcessOp.Exit` is the same mechanism (SO-37).

## To decide (a ruling)

For each Process op, decide whether it acts on the caller (self-only, faulting `NotSelf` on another target, as `ThreadOp.Exit` does) or on the target (a supervision act, which then has to mint into the caller's table, as `PipeCreate` does). The spec says nothing about a launcher creating objects in a child.

**Air, correcting my SO-26 r2 note:** `PipeCreate` is NOT the exception. It passes `obj.slot` as the owner and the trapping process as the caller only so that `copy_out` writes to the right buffer. Both ends are still minted into `obj.slot`'s table, and those words are what it copies out (dispatch.saw `pipe_create`). Its own doc comment says that through a child's handle it "hands back child-relative words exactly as `ThreadCreate` … already does". So the class has five ops: ThreadCreate, EventCreate, WaiterCreate, InterruptBind and PipeCreate.

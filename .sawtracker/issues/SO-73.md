## Description

## Scope

Establish, by probe, every board fact the Xtensa HAL will be written against,
and boot a bare stub on the emulated ESP32-S3. It needs no Saw compiler, so it
starts before sawlang's Xtensa target (SL-1063) exists.

`hal/riscv32-esp32c3/ABI.md` is the model: it records what the emulator does,
probe by probe, and marks where the emulator and the silicon disagree.

## To establish

- **Boot.** How the ROM in `qemu-system-xtensa -machine esp32s3` hands over
  control: the image it accepts (direct boot or the esptool image format), the
  entry address and state, what the ROM leaves configured, and what the same
  path is on silicon per the S3 technical reference.
- **The memory map** from the monitor's `info mtree`: RAM, the flash windows,
  the peripherals.
- **Exceptions and interrupts.** The vector layout and `VECBASE`, the
  interrupt levels, how `syscall` arrives, which special registers a trap
  frame must hold, and the cost of call0 against the windowed ABI for a
  kernel. `PS.UM` and what the S3 offers for privilege, to confirm that the
  first profile is `Flat`.
- **The timer.** SYSTIMER through the interrupt matrix, or the core's
  `CCOMPARE`: which one the emulator delivers, and whether `waiti` wakes.
- **The console.** UART0, and USB-Serial-JTAG as the alternative on boards
  that expose only the USB port.
- **Watchdogs** the ROM leaves running.
- **GPIO and LEDC,** as far as the emulator models them: what a GPIO write,
  a GPIO read and a GPIO interrupt do there, and that LEDC is absent.
- **The build spelling:** the Espressif clang's triple and `-mcpu`, the
  linker, and the helper library, for assembly and C.

## Deliverable

- `hal/xtensa-esp32s3/ABI.md`, each fact with the probe that produced it.
- A stub in assembly and C, built with the Espressif clang, that boots under
  QEMU, prints a banner, takes a timer interrupt and returns from a `syscall`
  exception. Its sources travel with the report for the HAL unit to adopt.
- Questions for the sawlang lead, posted by the lead.

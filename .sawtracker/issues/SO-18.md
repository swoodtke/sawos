## What sawlang head already needs (probed Sep 24 at `454207de`)

The full gate at head, against a fresh HTTPS clone (never `~/Projects/sawlang`),
turned up two source breaks and nothing else:

1. **`kernel/core/slab.saw:204`**: the `borrows` spelling now names the lent
   reference and its mode. Verbatim:
   `error: a \`borrows\` declaration names the LENT REFERENCE and its mode, not a returned value: write \`borrows -> &T\` if a use site may only READ through the place, or \`borrows -> &var T\` if it may also WRITE through it. \`borrows -> T\` says neither`.
   Fix: `func [](&var self, i: Int) unsafe borrows -> &var T`. The spec's
   receiver rule (`-> &var T` requires `&var self`) applies. The body only
   reads `self` and lends, so the accessor stays shared-eligible: a read
   through `EVENTS[i]` still borrows the slab shared.
2. **`tests/thread-preempt/src/main.saw:157`**: two statements on one line
   need a `;` now. Verbatim: `Parse error at 157:63: two statements on one line need a \`;\` between them: the first begins with \`let\`, the second with \`return\``.
   Fix: the tree's multi-line catch-guard shape.

A parse check of all 205 tracked `.saw` files with head's parser is clean
after (2). With both fixes the full gate at head passes: **382/382 = 129 + 129 + 124**.
A transcript diff against a v0.11.1 baseline run is in progress.

## What 0.12.0 adds (SL-355, not merged yet)

`__saw_rt_reactor_register` changes from `void` to `word` (0, or the platform's
raw errno; sawc/rt/ABI.md in SL-355.p1). `tests/taskdump.saw:42`'s export is a
never-called stub (SOS has no reactor), and `task_dump` is a
`--runtime-provider` gate case, so the export must follow (m146, and item 4
of codex's SL-355.p1 review). The honest status for "there is no reactor on this machine" is
NONZERO. Returning 0 would claim the fd was armed, and a task would park
forever. With a nonzero status the executor's funnel panics, naming the fd.

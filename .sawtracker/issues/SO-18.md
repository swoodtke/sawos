## Description

## Scope (RESCOPED Sep 24; the head syntax fixes moved to SO-21)

The **0.12.0** step only, stacked on SO-21 (which pins head 454207de at 0.11.1, per the user's ruling). SL-355 carries SAWC_VERSION 0.12.0 and changes `__saw_rt_reactor_register` from `void` to `word` (0, or the raw errno). Per the user ruling relayed in chat m159, sawos pins 0.12.0 and ports the export in the same move.

## The change (built on branch `so-18-pin-0.12.0`, one commit on SO-21's tree)

- `tests/taskdump.saw`: the export returns `ENOSYS` (38). SOS has no reactor, so nothing is ever armed. `0` would claim an arm that never happened and park a task forever; nonzero makes the executor's funnel panic, naming the fd. `task_dump` is a `--runtime-provider` gate case, so the signature check enforces this.
- `tools/sos_runner.py`: the task_dump expectations' line numbers shift by 7.
- `sawlang.pin`: to the 0.12.0 cut's version + sha together. This closes SO-21's untagged-sha note.

Probed against SL-355.p1 r1 (c91bd7bf + the patch, tree fffd1895, a fresh clone): the ported file compiles on riscv32 and aarch64. The unported file fails ("returns `void` where the ABI returns `word`"). Head rejects the ported file (the mirror error). So the port and the pin must land together.

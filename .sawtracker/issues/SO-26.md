   - **The raw ABI only half works.** The narrowed handle would have to be the start-tag word in a0, since draining needs `ProcessRight.BootHandles` on a Process handle the child doesn't have, and messages refuse Process. That breaks the bootstrap these same files state: "a System handle in its first argument register" (rights.saw:867-869, system.saw:799-801).

2. **`lib.saw:47-50` vs `218-220`:** r2 now lists "`WaitTag` and the wait record's word offsets" as public API and "the wait record's wire layout" as kernel-internal. The facade re-exports neither (142-143), and `floor.saw:498-500` says the record's layout is public.

Free-list fragmentation isn't caller-checkable; the kernel's own Split arm says it's "not, strictly, its mistake" (it still faults `BadArg`).
4. **`memory.saw:58-59`:** "the region the handle names is now shorter". That's false on the free-list path r2 now describes at 51-53, where `pool_cut` leaves the root's base and length unchanged.
5. **`ops.saw:29-31`:** release "frees the object when it was the last one". System, Clock and Thread aren't counted, a live Process isn't freed by its last handle, and a mapped Memory survives its last handle. Scope the rule to counted kinds and name the exceptions.
6. **`system.saw:562-565`:** "A caller at its Thread or handle quota gets `QuotaExceeded`". `ThreadCreate` charges the quota and mints into the table of the process the handle names, which is the caller only on its own handle. See the code issue below.

**Code issue, SO-37's class (not a comment defect, for the lead to file).** The Process factory ops act on `obj.slot`, the process the handle names, not on the caller:
- `ThreadCreate` → `thread_create(obj.slot, …)`, `EventCreate` → `event_create(obj.slot, …)`, `WaiterCreate` → `waiter_create(obj.slot)`, `InterruptBind` → `interrupt_bind(obj.slot, …)` (dispatch.saw 598/652/658/668).
- `event_create_moded` checks `obj.slot`'s quota, mints into `obj.slot`'s table and returns that word. A launcher holds its child's Process handle with all four rights (the one default set).
- **So through a child's handle:** the launcher gets back a word that's meaningful only in the child's table, wrapped by sysapi as the launcher's own Event, Waiter or Interrupt. In the launcher's table it names nothing or a different object. The child is charged the quota.
- `ThreadCreate` through it starts a thread inside the child at an entry point the launcher chose. That may be intended supervision, but it needs a ruling.
- `PipeCreate` is the exception: it passes both `obj.slot` and the caller `p`.
- By obligation 4, this is the same mechanism as SO-37, so a sweep of every Process op for target vs caller seems worth doing.

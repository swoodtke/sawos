## Description

Implement spec §2.10, the object lifecycle, and the interrupt and creation-op
rules that SO-48 wrote into the spec. Each unit removes the "not yet enforced"
markers it satisfies; the spec text itself is already the contract.

Units, in order (each after the previous merges unless noted):
1. **Shared objects pin their charged process slot.** The refund rule's
   second half, which also fixes the latent refund to a reused slot.
2. **Givable kinds:** `Transfer` and a `BootHandleKind` for Thread, Event,
   Waiter and Timer; the message kinds; the typed-tier gives.
3. **Invalidation and the teardown order:** the invalid state for the bound
   kinds, `Revoked` answers, counted thread slots, `Exited` wins, Event as a
   shared kind, refunds at invalidation, the new teardown order.
4. **Interrupts:** `SystemOp.InterruptBind`, no `Mint`, `Transfer` and a boot
   kind, no quota column, one name, no consuming attach, the `IRQ_NONE` record.
5. **SO-41:** the creation ops and self-only ops (closes SO-44).

**Note for the invalidation unit**, from the SO-54 spec implementer: an invalid bound object (Thread, Timer, Waiter, Mapping) that outlives its owner keeps a `process` field naming that owner. Once the owner's record is reclaimed and reused, the new occupant's teardown owner-sweep could match it. Invalidation must disown the object too, setting `process` to `NO_PROCESS` as SO-53 does for shared kinds. Alternatively, the sweeps must skip invalid objects.

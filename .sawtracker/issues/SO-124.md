## Description

**Processes written with an ordinary `main`: sosrt owns `_start` and calls a compiler-synthesized entry.** User ruling, Nov 15: "go ahead and create the issue for the _start / main work and tell sawlang i approve of its plan. for sawos though, i think this should go behind the pll work".

**Today.** Every process package exports `@export("_start") func _start(boot_handle: UInt)`, builds its `System` from the raw boot word, drains its boot handles itself, and must end in an explicit exit or shutdown: falling off `_start` returns into nothing. A program's second thread re-enters `_start` and dispatches on a static.

**The split (the sawlang lead's recommendation, approved by the user for sawlang's half on Nov 15).**
- **sawlang:** under `--freestanding`, a `main` in the entry module gets the hosted treatment without the C ABI: the compiler synthesizes a synchronous, C-ABI function with a reserved name (`__saw_main` in their sketch) that runs `main` (driving a suspending `main` with the entry executor), applies design 221's contract (`Void`, `Int`, `Result<Void, E>`, `Result<Int, E>`; the 0...255 check through `__saw_rt_panic`; an `Err` written as `error: <rendering>` through `__saw_rt_write_error`) and returns the status. Their issue number goes here when filed.
- **sawos (this issue):** `sosrt` owns `_start`: it makes the process's boot context, stores the boot handle where a runtime accessor reads it (`main` takes no parameters), calls the synthesized entry, and exits the process with the status through the process exit op.

**To design (a short design first, for the user's review):**
- the boot-context accessor in `sos` (the `System` handle, the process's own handle, the boot records), and what happens to the existing `System(boot_handle:)` spelling;
- a thread's entry: a real entry function for `ThreadCreate` instead of re-entering the image's entry and dispatching on a static;
- the windowed entry on the ESP32-S3: the bootstrap gives a windowed program a correct entry (the call4 rule of `hal/xtensa-esp32s3/ABI.md` §7d);
- the exit status: design 221 limits `main` to 0...255; a process's exit code is a word; say what a status past 255 means, and whether a program that wants a full word calls the exit op itself;
- migration: a package that exports its own `_start` keeps working; root, the drivers and new code move to `main`; old tests convert over time, not in one patch;
- a suspending `main` freestanding (needs sawlang's half).

**Order (user, Nov 15):** after the PLL (SO-113), which follows windowed threads (SO-112).

**ABI:** `PANIC_OP = 0xFFFC`, `PANIC_TEXT_BYTES = 256` (`sosabi` `ops.saw`; every table asserts `< PANIC_OP`, and `PANIC_OP < INFO_OP`); `FaultReason.Panic = 14` ("the program panicked"). **Kernel:** `dispatch` takes `handle == NO_HANDLE && op == PANIC_OP` before the lookup, so it needs no handle and no right. `panic_process` checks the whole read range through `copy_in_check` (a zero length skips it), copies in 8-word chunks to a stack buffer, prints bytes outside 0x20–0x7E as `?` and drops a final line break when the text was not cut; a buffer the door refuses prints `text unreadable: <the door's reason>` and is still a panic. Approved patch SO-124.p1 (revision 1)

**Approved. The op is safe on what it reads and what it prints, every branch is held by a case, and nothing in sawos relied on the allocator's abort.**

- **The intercept** takes only `NO_HANDLE` with `PANIC_OP`, before any lookup; any other word goes the ordinary way and no kind's table reaches the number.
- **The read:** at most `PANIC_TEXT_BYTES`, checked whole through `copy_in_check` before a byte is written. The door is word-aligned, and `translate_user` tests `bytes <= row.top - va` only after `va` is inside the row, so no range wraps. The chunked copy stays inside the checked range, with no user code between the check and the copy on the uniprocessor.
- **The print:** every byte outside `0x20`-`0x7E` is shown as `?`, so a text can neither start a line nor reach the terminal as a control sequence. A final line break is dropped only when the text is whole.
- **Mutants** (f396, mine, run on `panic_op`, `stock_skew_no_row`, `arena_small` and `double_free`): all eleven red. **Lead: SO-124.p2 is unit 2 of `SO:sosmain-startup`: `sosmain`'s start-up and the boot context, with no console.** One commit, gated on d6403522 and rebased by the lead onto current main without conflict. Images 4150 → 4243: every image linking the Saw runtime moved, those linking none are identical, 93 new.

**`rt/main` (`sosmain`)** exports `_start`: the re-entry guard; the main thread's block into the thread register; the boot word's kind (`sos: the boot word names a Memory, not a System`) and its adoption; `ProcessSelf`, then the Process handle and its rights; `ThreadSelf`, then the main thread's own Thread handle into the block; `BootHandles`, then the drain; the `Boot` value published from the start-up's frame; `__saw_main`; `flush()` (a no-op until the console); the end, which checks for a Process handle and `Exit` before `Process.exit`. Each refusal panics by name, `Faulted (Panic)`. Public: `context()` (a one-word `Context` whose `system()` and `process()` lend), `take_boot_set()` (a compare-and-swap on a taken word), `flush()`, `exit(code:)`. **The start-up allocates nothing** (`main_no_heap`: a `main` program with a zero built-in heap).

**`sosrt`:** `__saw_rt_write_error`; the output lock (`__saw_rt_output_lock`/`_unlock`), recursive (owner and depth behind std's `SpinLock`), a waiter yielding through the new per-side hook `sos_rt_yield` (the kernel answers nothing; a process yields on the thread's own handle from its block); `__saw_rt_write`/`_write_line` take it and `rt_panic` claims it. Lock-owner numbers are odd (`n << 1 | 1`) from this unit, since the yield reads a block from an even non-zero register (a `_start` package's second thread would otherwise read address 2). **`sos.rt`:** the debug path's rights check: at the first write it asks `INFO_OP` for the handle's kind and rights and keeps the answer; a `print` without `Debug` is dropped (a direct `debug_print` still faults). **HALs:** each `user.ld` gets `ASSERT(DEFINED(_start), …)`; the user ABI.md files name four hooks. **Builder:** a declaration whose `Saw.toml` depends on `sosmain` is a `main` program, its handle floor one higher (refused by name at the old floor). **spec:** §12 (a `print` without `Debug` is dropped) and the runtime floor (four hooks, block address versus odd numbers, the output lock); CLAUDE.md's map gains `rt/main/`.

## Description

**Processes written with an ordinary `main`: sosrt owns `_start` and calls a compiler-synthesized entry.** User ruling, Nov 15: "go ahead and create the issue for the _start / main work and tell sawlang i approve of its plan. for sawos though, i think this should go behind the pll work".

**Today.** Every process package exports `@export("_start") func _start(boot_handle: UInt)`, builds its `System` from the raw boot word, drains its boot handles itself, and must end in an explicit exit or shutdown: falling off `_start` returns into nothing. A program's second thread re-enters `_start` and dispatches on a static.

**The split (the sawlang lead's recommendation, approved by the user for sawlang's half on Nov 15).**
- **sawlang:** under `--freestanding`, a `main` in the entry module gets the hosted treatment without the C ABI: the compiler synthesizes a synchronous, C-ABI function with a reserved name (`__saw_main` in their sketch) that runs `main` (driving a suspending `main` with the entry executor), applies design 221's contract (`Void`, `Int`, `Result<Void, E>`, `Result<Int, E>`; the 0...255 check through `__saw_rt_panic`; an `Err` written as `error: <rendering>` through `__saw_rt_write_error`) and returns the status. Their issue number goes here when filed.
- **sawos (this issue):** `sosrt` owns `_start`: it makes the process's boot context, stores the boot handle where a runtime accessor reads it (`main` takes no parameters), calls the synthesized entry, and exits the process with the status through the process exit op.

**To design (a short design first, for the user's review):**
- the boot-context accessor in `sos` (the `System` handle, the process's own handle, the boot records), and what happens to the existing `System(boot_handle:)` spelling;
- a thread's entry: a real entry function for `ThreadCreate` instead of re-entering the image's entry and dispatching on a static;
- the windowed entry on the ESP32-S3: the bootstrap gives a windowed program a correct entry (the call4 rule of `hal/xtensa-esp32s3/ABI.md` §7d);
- the exit status: design 221 limits `main` to 0...255; a process's exit code is a word; say what a status past 255 means, and whether a program that wants a full word calls the exit op itself;
- migration: a package that exports its own `_start` keeps working; root, the drivers and new code move to `main`; old tests convert over time, not in one patch;
- a suspending `main` freestanding (needs sawlang's half).

**Order (user, Nov 15):** after the PLL (SO-113), which follows windowed threads (SO-112).

## Description

**Move the sawlang pin from v0.24.1 to v0.24.2.** Tagged by the sawlang lead on Nov 15: `6fe1d848dfcc94b5b57487d0f28a49a6085ed155`. Its contents are the description of sawlang's SL-1141.

**Why:** it holds what the windowed-threads unit needs for windowed Saw on the ESP32-S3 (SL-1133: windowed Xtensa keeps no frame pointer; SL-1128: the freestanding suite's windowed row), and a leak fix in safe code (SL-1134: a capturing closure called where it is written was never dropped; this tree has none).

**What can change for this tree:**
- **Blade reads every manifest through the typed TOML reader** (SL-1092 unit 2): a manifest that is not valid TOML is refused for every command; a value of the wrong type is an error; `Saw.lock` is written with values quoted (an old lock is read as before unless a path holds a backslash or a quote: then `blade update` once). The sawlang reviewer ran it over this tree: all 333 package directories read identically.
- **`sawc --build-id`, hashed by `blade build`** (SL-1102 unit 2): every package rebuilds once after the move.
- **Known, not fixed in it:** SL-1126 and SL-1125 (`(move x)` as the base of a field read or a method call does not move), SL-1139 (a compiler panic on the most negative 64-bit literal for a 32-bit target), SL-1129 (a const generic value past the target's `Int`).

**The oracle.** As for the last two bumps: the gate resolved by fetch at the old pin and the new, the two outputs diffed and every difference explained; a `Saw.lock` that the new Blade rewrites is part of the patch only if it must be, and said so.

# SO-179: ESP32-S3 per-thread FP and BR state, on arm64's model

The owner's ruling is on SO-179 (comment c1). This brief restates it. The
S3's floating-point unit follows the scheme arm64 already has. Read that
scheme first:
- `hal/arm64/kernel/ABI.md`'s "Thread contexts";
- `hal/arm64/kernel/lib.saw` around `fp_area`, `fp_active`, `sos_fp_save` and
  `sos_fp_load`, and the switch hooks that call them;
- `boot.S`'s save and load, and its first-use trap path;
- the runner's `fp_threads`, `fp_leak` and `fp_idle_teardown` cases;
- `_check_kernel_fp_free` and `FP_ALLOWED_SYMBOLS`, which disassemble every
  kernel image.

Then read `hal/xtensa-esp32s3/ABI.md` §5 and §7 (the frame in §7c, which
names `CPENABLE = 0` and cause 32 as the hook).

## Build

1. **Off by default.** Coprocessor 0 (the FPU) is disabled for every thread
   (`CPENABLE = 0`).
2. **The first use.**
   - A thread's first FP instruction traps with EXCCAUSE 32
     (Coprocessor0Disabled).
   - The kernel marks the thread active, loads its FP area (zeros at the
     first use) and enables the coprocessor. The thread then re-executes the
     instruction.
   - Cause 32 from a thread already active is a kernel bug and stops the
     machine with a line that names it.
3. **At a switch.**
   - An active outgoing thread's state is saved: f0 to f15, FCR, FSR, and
     BR (the boolean register the FP compares write).
   - An active incoming thread's state is loaded. For an inactive one the
     coprocessor is disabled.
   - A trap that resumes the same thread touches none of it.
   - The idle wait counts as a switch away, as on arm64.
4. **The kernel executes no FP instruction.**
   - Extend `_check_kernel_fp_free`, or a sibling of it, to the S3: every
     S3 kernel image is disassembled, and an FP or BR instruction outside
     the save and load fails the build.
   - Compile the kernel's C so it emits none.
5. **The FP area follows the trap frame within the thread's 512-byte
   stride**, after `FRAME_BYTES` (304). State the offsets in §7c, and say
   that the frame plus the area fits the stride, with a link-time or
   build-time check if one is cheap.
6. **Docs.**
   - ABI.md §7c: the area and the first-use rule, replacing the "only if a
     thread is allowed" sentence.
   - §5c: cause 32.
   - The spec, wherever arm64's FP rule is stated per profile.

Saw processes stay soft-float. The test programs that use FP are C or
assembly, as arm64's are.

## Cases (on the S3 smoke; the r8 board too if the smoke runs it)

Each case needs a red mutant, named in your note:
- **Two threads keep their values.** Two threads use FP, interleaved by
  construction, and each keeps its values, BR included. Mutant: no save at
  the switch.
- **A first use reads zeros**, even when another process's values are still
  in the hardware. Mutant: the first use loads nothing.
- **An inactive thread costs no save.** Show it with a counter the kernel
  keeps, or by construction as arm64's case does. Mutant: the save is done
  for every thread.
- **The idle path saves the outgoing state**, as `fp_idle_teardown` does.
- **The disassembly check** turns red on a planted FP instruction in the
  kernel.

Order every line by construction, and assert no time (CLAUDE.md).

# SO-179: ESP32-S3 per-thread FP and BR state, on arm64's model

The owner's ruling is on SO-179 (comment c1). This brief restates it. The
S3's floating-point unit follows the scheme arm64 already has. Read that
scheme first:
- `hal/arm64/kernel/ABI.md`'s "Thread contexts";
- `hal/arm64/kernel/lib.saw` around `fp_area`, `fp_active`, `sos_fp_save` and
  `sos_fp_load`, and the switch hooks that call them;
- `boot.S`'s save and load, and its first-use trap path;
- the runner's `fp_threads`, `fp_leak` and `fp_idle_teardown` cases;
- `_check_kernel_fp_free` and `FP_ALLOWED_SYMBOLS`, which disassemble every
  kernel image.

Then read `hal/xtensa-esp32s3/ABI.md` §5 and §7 (the frame in §7c, which
names `CPENABLE = 0` and cause 32 as the hook).

## Build

1. **Off by default.** Coprocessor 0 (the FPU) is disabled for every thread
   (`CPENABLE = 0`).
2. **The first use.**
   - A thread's first FP instruction traps with EXCCAUSE 32
     (Coprocessor0Disabled).
   - The kernel marks the thread active, loads its FP area (zeros at the
     first use) and enables the coprocessor. The thread then re-executes the
     instruction.
   - Cause 32 from a thread already active is a kernel bug and stops the
     machine with a line that names it.
3. **At a switch.**
   - An active outgoing thread's state is saved: f0 to f15, FCR, FSR, and
     BR (the boolean register the FP compares write).
   - An active incoming thread's state is loaded. For an inactive one the
     coprocessor is disabled.
   - A trap that resumes the same thread touches none of it.
   - The idle wait counts as a switch away, as on arm64.
4. **The kernel executes no FP instruction.**
   - Extend `_check_kernel_fp_free`, or a sibling of it, to the S3: every
     S3 kernel image is disassembled, and an FP or BR instruction outside
     the save and load fails the build.
   - Compile the kernel's C so it emits none.
5. **The FP area follows the trap frame within the thread's 512-byte
   stride**, after `FRAME_BYTES` (304). State the offsets in §7c, and say
   that the frame plus the area fits the stride, with a link-time or
   build-time check if one is cheap.
6. **Docs.**
   - ABI.md §7c: the area and the first-use rule, replacing the "only if a
     thread is allowed" sentence.
   - §5c: cause 32.
   - The spec, wherever arm64's FP rule is stated per profile.

Saw processes stay soft-float. The test programs that use FP are C or
assembly, as arm64's are.

## Cases (on the S3 smoke; the r8 board too if the smoke runs it)

Each case needs a red mutant, named in your note:
- **Two threads keep their values.** Two threads use FP, interleaved by
  construction, and each keeps its values, BR included. Mutant: no save at
  the switch.
- **A first use reads zeros**, even when another process's values are still
  in the hardware. Mutant: the first use loads nothing.
- **An inactive thread costs no save.** Show it with a counter the kernel
  keeps, or by construction as arm64's case does. Mutant: the save is done
  for every thread.
- **The idle path saves the outgoing state**, as `fp_idle_teardown` does.
- **The disassembly check** turns red on a planted FP instruction in the
  kernel.

Order every line by construction, and assert no time (CLAUDE.md).

**The implementer's note for SO-179.p1 (the ESP32-S3's per-thread FP and BR state, on arm64's model).**

**The trap path and the switch** (`hal/xtensa-esp32s3/kernel/lib.saw`, `boot.S`).
- **First use:** cause 32 reaches `ktrap`, which calls `hal.fp_trap` first.
  - A thread already active stops the machine: `SOS-S3: kernel bug: coprocessor 0 disabled for a thread already using it, pc=…`, status 6.
  - Otherwise the thread is marked active, `sos_fp_load(area)` loads its area and enables CP0, and the thread re-runs the instruction. kcore prints `SOS: fp first use`.
- **At a switch:**
  - `fp_switch_out` (in `pick_next`, before the idle wait) saves an active thread's state.
  - `fp_switch_in` (in `run_thread`) loads an active thread's state, or else writes CPENABLE 0.
  - There is no CPENABLE mirror, because a process can write CPENABLE itself, so an inactive thread's switch writes 0 every time. The save and the load set bit 0 before their first FP instruction.
- The trap entry, the restore and the stop paths are unchanged. `boot.S` gains a label at each vector `.org` for the disassembly check, as does `tests/xtensa/bus_probe.S`.

**The area.** It sits at 304, after `TRAP_FRAME_BYTES`:
- f0–f15 at 0–60;
- FCR at 64, FSR at 68, BR at 72;
- the active word at 76.

`FP_AREA_BYTES` is 80 and `FRAME_BYTES` 384, which now cover the frame and the area together, as on arm64. `static_assert(FRAME_BYTES <= 512)` holds the stride.

**The disassembly check** (`_check_s3_kernel_fp_free`, run in the smoke's `build_flash`, so every S3 image is checked, board images included).
- Xtensa literal pools share `.text` with code and nothing marks them, so literals are found from the words each `l32r` loads.
- Lines inside sized functions are all checked. Outside them, a line is skipped if it overlaps a loaded word, is all zeros, or runs past the next line's start.
- Only `sos_fp_save` and `sos_fp_load` may hold an FP instruction. The kernel's C is already built with `-fp`.

**Cases (S3 and r8), each with its mutant red:**

| case | shows | mutant |
|---|---|---|
| `s3_fp_threads` | two threads interleaved by yields keep their values, BR included | no save at switch-out |
| `s3_fp_leak` | a child's first use reads zeros while root's values are still in the FPU | the first use loads nothing |
| `s3_fp_inactive` | a thread that hasn't used the FPU costs no save, by construction | save every outgoing thread |
| `s3_fp_idle_teardown` | the outgoing state is saved before the idle wait | skip the save when nothing is ready |
| `s3_fp_twice` | a process that clears CPENABLE after its first use stops the machine | drop the already-active check |
| `fp_planted` | a planted `wfr`/`rfr` in a harness kernel is refused by name | (the case is the red) |

The idle case's mutant shows only on a run where the thread really parks, as on arm64. The case doesn't depend on timing.

**What QEMU models.** Cause 32 for `wfr` with CPENABLE=0 (EPC1 at the instruction), and f0–f15, FCR and FSR round-tripping.

**One finding for the reviewer: BR is not gated by CPENABLE.**
- On QEMU, a thread's first instruction read the BR another process's thread had left. The first-use trap came only at the next `rfr`.
- On Xtensa, BR belongs to the Boolean option, not to coprocessor 0, so the part very likely behaves the same.
- So an inactive thread can read another thread's BR, as it can MAC16 and MISC today. The agent documented it and stayed with the ruling's shape.
- **The lead's view:** BR is one word, so it belongs in the trap frame for every thread, saved and loaded at every trap like SAR, with a case that reads it at a thread's first instruction (as `register_file_clean` does). If you agree, I'll have it revised that way.

**Only the part can show:** cause 32 on silicon, which FCR and FSR bits are writable, and whether `rur fcr`/`fsr` trap with CPENABLE=0 (which changes nothing, since the save and load set bit 0 first). ABI.md §11 records these.

**Docs:** ABI.md §5c, §7c and §11; the S3 README; spec §5b and §7; the smoke banner.

**Totals:** gate 1713, S3 561, on b6c50b7a. The lead rebased it onto current main with no conflicts.

**Owner ruling (Nov 27):** the S3's floating-point support follows arm64's existing scheme (hal/arm64/kernel/ABI.md, the thread-contexts section): the FPU (coprocessor 0) is off by default (CPENABLE=0); a thread's first FP instruction traps (EXCCAUSE 32, Coprocessor0Disabled), and the kernel marks the thread active, loads its FP area (zeros at first use) and enables the coprocessor; at a switch, an active thread's f0-f15, FCR, FSR and BR are saved and the incoming thread's loaded (or the coprocessor disabled for an inactive one); a trap that resumes the same thread touches none of it, and the kernel executes no FP instruction (a disassembly check, as arm64's). The area follows the trap frame within the thread's 512-byte stride. Cases on the S3 smoke: two threads using FP interleaved by construction, each keeping its values; a first use reading zeros; an inactive thread costing no save; a mutant for each.

Needed by the radio work (Espressif's libraries use hardware FP); Saw processes stay soft-float. **The fully lazy scheme (deferred ownership, for both FP and the windowed registers) stays SO-115, later.**

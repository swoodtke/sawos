## The contract (spec.md §2.10, "The refund rule", second bullet)

Read §2.10 and §2.9 in full first. A shared kind can outlive the process charged
for it, so **each such object holds a reference on that process's slot**: a
`Gone` slot is not reclaimed (`reclaim_process_slot`, `kernel/core/process.saw`
~155) until every object charged to it is freed, and the refund at free reaches
the right ledger.

## The defect today

- `free_pipe` credits `PIPES[slot].process` (`kernel/core/objects.saw` ~1987),
  `memory_release_if_idle` credits `MEMORIES[slot].process` (~1169–1197, and
  ~1228), and the IoMemory free credits its owner (`kernel/core/refs.saw`
  ~589). None checks that the slot still holds the process it charged.
- `reclaim_process_slot` frees a `Gone` slot once `PROCESSES[slot].refs == 0`,
  where `refs` counts Process handle entries and attachments (refs.saw ~172,
  ~366).
- So a pipe, region or IoMemory that outlives its charged process and is freed
  after the slot is reused credits the new occupant, lowering its usage below
  what it really spends.

## Scope

**Kinds:** the shared kinds that are charged to a process and can outlive it
today: Pipe connections, Memory regions, IoMemory windows. Check the code for
any other charged kind whose free credits a stored `process` after its owner
can be gone (exchanges? mappings?), and list what you find. Event becomes shared
only in a later unit; do not change Event here.

**Mechanism:**
1. Where each such object is charged (`quota_charge` at creation, donation or
   transfer of the charge, if any), it also takes one reference on the charged
   process's slot.
2. Where it is freed and credited, it credits and then drops that reference,
   and a `Gone` slot whose count reaches zero is reclaimed through
   `reclaim_process_slot`. Reuse the existing ref-drop path for Process slots
   (refs.saw ~360–370) rather than hand-rolling one.
3. `PROCESSES[].refs` is `UInt16` (`kernel/core/pslot.saw` ~243). Check the
   worst-case count (handles plus attachments plus every charged object, from
   the slab capacities) fits, and report the arithmetic. If it does not fit,
   ask.
4. The teardown order must still balance. Today it closes handles counting
   without freeing, sweeps by owner, then `reap_unreferenced` frees what nothing
   names (`kernel/core/sched.saw` ~300–590), then clears the ledger and may
   reclaim. Make sure a process's own shared objects freed in its own teardown
   drop their slot references before the final reclaim check, so a dying
   process with nothing outstanding still reclaims its slot exactly as today.
5. Update the comments at every site you touch (the doc on `refs`, on
   `reclaim_process_slot`, on `quota_credit`'s "write-off" note) to describe the
   new rule. No history.

Remove the spec's "not yet enforced" markers this satisfies (grep §2.9, §2.10,

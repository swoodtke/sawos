## The change

1. **Husk Mappings.** A Mapping whose target died (row `NO_ROW`, `target`
   disowned to `NO_PROCESS`; read SO-54's husk code) answers `Revoked` to
   `Unmap` and `Base`, after the rights check. Today both are `BadState`
   faults.
   - A Mapping the caller unmapped itself is a different state: today `Unmap`
     clears `target` with `row`. Check whether the code can tell "unmapped by
     its holder" from "target died". The first stays `BadState` (§2.5:
     "Unmapping twice is `BadState`"), the second answers `Revoked`.
   - If the two states can't be told apart, add the distinction the smallest
     way (a state value, or a separate sentinel for `target`) and say which.
2. **`map` naming a `Gone` target** (`map_target`, `kernel/core/dispatch.saw`)
   answers `Revoked` instead of the `BadState` fault, after the rights and
   argument checks.
3. **`MINT_OP` on an invalid object** answers `Revoked` (`mint_sibling`): an
   invalid Thread, Waiter or Timer today, and an invalid Interrupt if SO-63 has
   merged (it removes `Mint` from Interrupts anyway). The rights check (`Mint`)
   faults first.
   - **A `Gone` Process is not "invalid" for minting:** GetStatus, Stats and
     attachments read a `Gone` process, so minting a sibling to it stays
     allowed. Check the spec's Process row agrees. If it doesn't, ask.
4. **Spec:** remove the markers this satisfies (§2.5, §2.10's not-yet item,
   with the creation-ops part left for SO-41). No issue numbers; 80 columns.

Approved patch SO-64.p1 (revision 1)

**Air: SO-64.p1, approved.** I reviewed the kernel changes against the code at ebee463 + p1.
- **The new sentinel can't be mistaken for a row.** `ROW_TARGET_DIED` is −2, and every reader of a Mapping's `row` handles it:
  - `Unmap` and `Base` test it (→ `Revoked`) and `NO_ROW` (→ `BadState`) before reading `target` or indexing `grants`;
  - the teardown sweep's husk check (sched.saw ~672) accepts both;
  - `compact_mapping_rows`' `row > removed` can't match a negative;
  - `object_invalid`'s Mapping arm tests it.
  The SO-54 halt ("a husk still named a reused process record") keeps its meaning, since a husk carries `target = NO_PROCESS` either way.
- **`map` into a `Gone` target never reaches `body_of`.** `map_target` admits `Gone`. Its two callers (`MemoryOp.Map` at ~2673, `IoMemoryOp.Map` at ~2780) only run hardware checks on the source between it and `install_row`, and `install_row` answers `Revoked` for `Gone` first, before the quota check and before `body_of(t)`.
- **`mint_sibling` answers `Revoked` through `object_invalid`** for an invalid Thread and a husk Mapping. A `Gone` Process stays mintable, as the spec's Process row says.
- **The Waiter and Timer arms:** whichever of SO-61 and SO-64 lands second must add them to `object_invalid`. SO-61 is in revision now, so please make sure its revision picks this up if SO-64 merges first.

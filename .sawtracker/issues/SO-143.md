## Description

The ESP32-C3 smoke stops gating (owner's ruling, Nov 17).

The C3 has no atomic instructions. The owner's direction is that the runtime uses sawlang's `std.spinlock.SpinLock`, which expects atomics: sawlang refuses it on a target without them (`atomics.target`), and every C3 process links the runtime, so the C3 smoke cannot build processes once the runtime takes the lock. There is no C3 board, and the C3's emulator never delivers the tick to user mode, so the race a lock guards is not observable there either.

- `.sawtracker/tests.json` runs `make sos-test sos-smoke-esp32s3`.
- `make sos-smoke-esp32c3` stays, as a non-gating target; the C3 HAL stays in the tree, unbuilt by the gate.
- CLAUDE.md, the Makefile and the runner's help and banner say so.

When a C3 (or another part without atomics) gets real support, its atomics would come from restartable sequences: the routines live in one known range, and the kernel rewinds a thread preempted inside it to the range's start. That is future work, to be filed then; the ESP32-C6 has the A extension and would not need it.

**Lead, for whenever a part without atomics gets real support (owner's discussion, Nov 17).** Three ways for a C3 process to get atomics, each also needing sawlang to accept runtime-supplied atomics for the target (it refuses `SpinLock` there at compile time today): (1) **restartable sequences**: the routines live in one known range and the kernel rewinds a thread preempted inside it to the range's start; full speed, no trap; (2) **a preemption-deferral flag**: the thread sets a word the kernel reads at a tick and defers the switch while set, granted as a right and capped (a thread holding it past a tick or two is preempted or killed), the Solaris `schedctl` shape; (3) **flat-tier processes in machine mode** (the C3 has no S mode), which can mask interrupts themselves, at the cost of memory protection, as the S3's and riscv32-flat's tier already disclaims. A masking syscall per lock is the fallback (a trap per lock).

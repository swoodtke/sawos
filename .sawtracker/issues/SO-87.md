## Description

## Finding (Nov 13, from SO-85)

At the pinned compiler (sawlang v0.22.0), in a function returning
`Result<UInt, E>` where `E` is an enum backed by `UInt8`, a bare
`return E.Case` (or `E.Case` as the tail expression) comes back as `Ok`
with the enum's raw value, not as `Err`. Nothing is diagnosed. A ten-line
host program reproduces it (`return, failing: Ok(11)`); it is with the
sawlang lead (chat m751, file f52).

In the kernel this made `translate_user` answer `Ok(11)` for every address
that named nothing; SO-85 fixes that site.

## The gap

The same shape is at other sites in this tree: an integer payload beside
an error enum, with the error returned bare.
- `kernel/sysapi/src/floor.saw`: two, both `Result<UInt32, SosStatus>`
  returning `SosStatus.Unknown` (a status word the wrapper does not know
  would be reported as a rights mask).
- Test helpers: 39 sites in 22 packages, `Result<UInt, SosStatus>`,
  `Result<Int, SosStatus>` or `Result<UInt64, SosStatus>` with
  `return why` or `return status`. A helper that fails reports `Ok` with a
  small number, so a case's failure path may print a number where it should
  stop, or pass where it should fail.

The lead's search was a pattern match and may have missed shapes (a tail
expression through a `match`, a payload that is another integer-backed
enum, a struct with one integer field). The sweep establishes the set.

## The unit

1. Establish exactly which shapes the compiler mis-wraps, with a small
   host program per shape (payload widths, signedness, tail against
   `return`, through `match` and `if`, `try` propagation, a `Bool` payload
   as the control).
2. Find every site of an affected shape in `kernel/`, `rt/`, `root/`,
   `hal/` and `tests/`, and spell the error out.
3. For each test helper fixed, decide whether its case could have passed
   wrongly, and show it with a mutant where the failure path is reachable.
4. Say what, if anything, in the tree can catch the next one (a lint over
   the shape in `.claude/lead/` is not the tree's; a compile-time answer is
   sawlang's).

## Acceptance

- [ ] the affected shapes, each with its repro
- [ ] every site fixed, listed
- [ ] the gate and both smokes pass; any case whose behaviour changed is
      named with why

**Lead, Nov 13: the sawlang lead reproduced it and narrowed it (chat m753; their issue is SL-1087, fixed in the release being cut tonight, which is not v0.22.0).** The cause is the lone-case rule (a lone raw-backed case folds into a declared integer slot) looking through a `Result` for an integer payload. **Affected:** a case written by name (`return Why.Bad`, a tail, an argument, a field, a `let`) into `Result<integer, Why>`, at every width tried. **Not affected:** a value of the enum type (`return status`), `Result<Bool, E>`, an enum with no raw backing, `try` propagation. So most of the 41 sites the lead's search found are not affected: the ones that return a variable behave. Those that spell a case literally are the kernel's `translate_user` (fixed in SO-85), two in `kernel/sysapi/src/floor.saw`, and at least one test helper. **Still to sweep for, and not changed by their fix:** the same fold into `UInt?` and into `Result<UInt, OtherEnum>`, where a case of the wrong enum becomes `Ok(raw)`. After their fix no source change is needed at our sites; spelling `Err` out is correct under both compilers. The pin moves when their tag exists.

## The rulings (user, settled; do not reopen)

### 1. Three states for every destructible object

- **Live.**
- **Invalid:** the object is destroyed. Its working state is torn down, its
  quota charge (if any) is refunded, and anything parked on it is woken. Handles
  naming it still exist.
- **Freed:** the last handle is released and the slot is reusable.

An op on an invalid object answers a **status**, not a fault: the holder did
not cause the invalidation and could not have checked for it (the reasoning
`PeerClosed` already uses). A wait on an object that becomes invalid wakes with
that status. Choose the status: `SosStatus.Revoked` already means "a Waiter was
destroyed under a parked thread" (§2.2; `kernel/core/refs.saw` ~428). Say in
your report whether you generalised `Revoked` or introduced a new status, and
why. If neither is clearly right, ask.

### 2. Which kinds live how

| Kind | Lifetime |
|---|---|
| Thread, Timer, Waiter, Mapping | **Bound** to their owning process: invalidated when it dies, freed when the last handle goes. A Mapping's owner is the process whose memory domain holds its row. |
| Interrupt | **Non-copyable** (no `Mint` in its default rights; derivation is monotonic, so no handle can regain it). Lives exactly as long as its one handle: releasing it, explicitly or by the holder's teardown, unbinds and masks the line. **Charged to no quota.** |
| Event, Pipe, Memory region, IO window | **Shared:** live until the last handle goes, whatever happens to the process charged for them. |
| Process | Already this model: `Gone` is its invalid state (§8; `kernel/core/process.saw` `reclaim_process_slot`). |
| Clock, System | Never destroyed. |

Process teardown runs in this order: **invalidate every bound object the dying
process owns, then release its handle table**, where each release drops a
reference and a count reaching zero frees.

Owned objects are found by sweeping the slabs by owner, as the teardown does
today. A Thread's invalid remnant (its exit state) stays in its slot, which is
not reused while a handle names it. Whether a large thread body is split from a
small record is an implementation choice; the spec states the observable
contract only.

### 3. The quota refund rule

- A bound kind's charge is refunded **at invalidation**. Its owner is then
  either live or mid-teardown with its ledger about to be cleared, so a refund
  can never land on a reused process slot.
- A shared kind can outlive the process charged for it. **Each such object
  holds a reference on that process's slot**, so a `Gone` slot is not reclaimed
  (`reclaim_process_slot`) until every object charged to it is freed, and the
  refund at free reaches the right ledger.
- Check the lead's reading of the current code before you write the rule as
  "not yet enforced": a pipe's free credits `PIPES[slot].process`
  (`kernel/core/objects.saw` ~1997) with no check that the slot still holds the
  same process, and `reclaim_process_slot` frees a `Gone` slot once no Process
  handle names it. If that reading is wrong, say so.

### 4. Interrupt binding moves to the System object

- A new `SystemOp.InterruptBind`, gated by a new `SystemRight.InterruptBind`,
  replaces `ProcessOp.InterruptBind` and `ProcessRight.InterruptBind`.
- The kernel's own line stays refused, and a bound line answers `LineBound`, as
  today.
- Per-line authority is expressed by which bound Interrupt handles a
  privileged binder (a launcher) gives to which driver. The spec says that; it
  does not add a per-line capability object.
- The Interrupt quota kind goes: the line count bounds Interrupt objects.

### 5. The Process creation ops (SO-41's rule)

`ThreadCreate`, `EventCreate`, `WaiterCreate` and `PipeCreate`, asked through
any Process handle:
- are gated by the right on the handle used;
- create the object **on behalf of the process the handle names**: it owns it
  and is charged for it (a thread created through a child's handle runs in the
  child and counts against the child's thread quota);
- place the new handle(s) **in the caller's table**, charged to the caller's
  handle quota as every handle is; the caller gives them on if the other
  process needs them;
- **fault the caller** on a caller error (bad entry, stack, mode).

`Exit`, `ThreadSelf` and `BootHandleNext` are **self-only**: a handle naming
another process faults the caller with `NotSelf`, as `Exit` already does.
`Start`, `Give`, `GetStatus` and `Stats` act on the named process, as today.

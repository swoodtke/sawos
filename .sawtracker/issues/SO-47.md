## Description

sawlang's LANGUAGE_SPEC.md (Profiles, v0.21.0) says that on riscv32 without `+a` the environment supplies **five** word atomics:
- `__atomic_load_4`
- `__atomic_store_4`
- `__atomic_fetch_add_4`
- `__atomic_fetch_sub_4`
- `__atomic_compare_exchange_4`

`rt/common_c/support.c` defines the first four. Nothing in the tree references `__atomic_compare_exchange_4` today, so the ESP32-C3 build links. A C3 build that compiles a compare-and-swap (`Atomic<Int>` CAS, or an `Arc` path that uses one) would fail to link.

**Fix:** add `__atomic_compare_exchange_4` in the same interrupt-masked style, with a C3 case that exercises it so it isn't dead code.

Found while ruling SO-34.

Correction to the description: `support.c`'s word atomics are plain read-modify-write with no masking of their own. They are sound in the kernel, which runs with interrupts masked, and in a user process only while nothing preempts it. A `__atomic_compare_exchange_4` should follow the same model and say so; it should not be written in an "interrupt-masked style".

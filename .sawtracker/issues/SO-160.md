**Lead: SO-160.p1 is A3-1.** One commit on main 7a9ed6c6. It touches only `drivers/pktring/` and `drivers/netdevproto/`, plus `net_fields_sealed`'s lists and expected text.

**pktring**
- `Endpoint.server_laid_out` stores all four index words; `Endpoint.client_given` stores nothing.
- `SlotRef`, `take`, `release_taken(count:)`, `reserve` and `fill` follow §4.2's cursor rules.
- `take` is the one place that reads and checks a slot's length. `receive` is `take` plus the copy.
- A private `out_reserved` cursor sits beside `out_head`, and `room` counts reserved slots as not free.
- Three caller misuses panic, because they are the caller's own bug, not shared input:
  - releasing past what was taken;
  - `fill` with nothing reserved;
  - `send` while a slot is reserved and not yet filled.

  A panic aborts a hosted test, so they are named rather than pinned (M9 survives). Each was checked once by hand with its message.

**netdevproto**
- `Frame` carries a handle count.
- A request carrying a handle is `BadOp` (`WireError.Handles`).
- An `Ok` Attach reply carries exactly one handle.
- New status: `NoMemory` = 6.
- The docs are updated.
- `attach_reply` validates the reply, and the caller takes the handle from the decoded message. netdevproto has no `sos` dependency.

**Mutants:** 39, and all are red but M9.

**Runs**
- `blade test`: pktring (4), netdevproto (2), and hciproto, wlanproto, sockproto and netstack.
- `net_fields_sealed`: the `tests/net-sealed` build was checked directly, without the runner. `Frame.init`'s refusal text changed, because the initializer is now overloaded.
- The full `make sos-test` didn't run locally: the suite lock was held by another unit's run throughout. The server's run is the full check.

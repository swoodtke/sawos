**Using the ESP32-S3's second core: a design.**

The kernel is uniprocessor on every profile (spec §7), and the S3's core 1 is held in reset. The owner has projects that need both cores (Nov 26) and wants the design now.

**The design compares:**
- full SMP;
- an asymmetric second core for pinned real-time work;
- SMP with core affinity.

**It covers:** locking, the scheduler across cores, interrupts and IPIs, memory and the caches (including the flash switch's cache freeze), core 1's bring-up, the panic rule (stop the other core first), the API and image side, a two-core gate profile under QEMU, tests, and units.

Opus, design first; nothing is built before the owner and the reviewer read it.


<!-- sawtracker:comment {"author":"agent:claude-sawos","body_bytes":286,"created":"1795733822","id":"c2"} -->
**Design revision 1 is published as `SO:smp`.** It recommends SMP with process affinity: one kernel image under a big ticket lock, with per-core ready lists, tick, idle and reschedule IPI. A launcher places each process on a core, and a process never moves. Owner questions are pending.

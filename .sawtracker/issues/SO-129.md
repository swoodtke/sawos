## Description

**Unit U6 of the image and packaging design (SO-95): declarations and the stock root.** After U4 (generated link addresses) an image built from a description places every process, but `sosimage build` still refuses an image whose root is the stock root: nothing turns a description's processes, connections and setup writes into what a root needs at boot, and `root/` is a hand-written test root. This unit makes the description drive the machine.

**Build what the design lists** (`SO:images-and-packaging` revision 6, approved by the owner Nov 14): §4 (a process's declaration: types, instances, shared bindings, the list-form refusals, rule 4.6's input precedence, rule 4.7's `BootSet`, rule 4.9's tree check), §8.2 (the boot table's order and `imageplan`, its types in `bootplan`), §8.3 (the launch convention), §8.4 (rules 8.1 to 8.5: the stock root and its `[[setup]]` writes), §14's U6 (`sosimage check-tree` in the gate).

**Carried into this unit:**
1. **From the GPIO/PWM drivers design (`SO:gpio-pwm-drivers` revision 3, resolved by the reviewer):** the box's `[[setup]]` has four writes, not §5.3's three (`GPIO.OUT1_W1TC = 0x600` before the output enable); the stock root's `set` and `clear` are read-modify-write, held by a test against the part's reset word (`0xf9c1e06f` in, a set of bit 11 giving `0xf9c1e86f`): a plain store turns off the flash, the console and SYSTIMER; an image's quota defaults are raise-only, so the stock root sets each child's declared rows with `QuotaSet` before it gives anything (the launch convention's order).
2. **From U4 (SO-128):** `build` sets each process's arena from its declaration's `arena`; `imageplan` and `[[setup]]` are this unit's; the hand-written-root path reads a declaration for `ram` only, and the stock root reads all of it.
3. **From SO-100:** a child's image blob that is to be mapped (an image used in place on a paging board) is padded to the grain by the builder.

**Cases:** an image built from a description with the stock root on riscv32, arm64, flat and the S3, booting children that each print their records in declared order, a connection between two of them, a setup write observed, a declared quota row in force; each of rule 8.2's failed steps stopping the machine with its message; `check-tree` refusing a broken in-tree declaration. The review standard (the owner's ruling, Nov 15): every check, refusal and stop has a case or builder test that goes red when it is removed or inverted; list the mutants.

**Not in this unit:** products in their own repository (U7), the harness in Saw (U8), the drivers themselves (SO-77), the box (SO-78).

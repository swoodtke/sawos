**Lead: SO-164.p1 is A3-3.** One commit on current main.

**What it adds:**
- **Board rows.** `VIRTIO0` to `VIRTIO7` (`virtio-mmio`, base `0x1000_1000` + N×0x1000, len 0x1000, line N+1) in the riscv32 and flat board files. `sosimage board` and `check-tree` read them clean.
- **`tools/netpeer`**, a hosted Saw package. `netpeer serve --script ping|burst|log|silent` listens on a loopback port the system picks and prints `port N`. It answers only guest frames (ARP, ICMP echo, and the UDP burst), logs as §6.4 says, and prints `peer: closed after N frames` when the guest ends. DHCP and DNS are left to A4.
- **The runner's net path.** It is additive:
  - a `net` case key and `expect_peer`;
  - one peer per case, built once per profile and added to `HOSTED_TESTS`;
  - QEMU started with `-S` and QMP on a socketpair, given `cont` once `NETDEV_STREAM_CONNECTED` arrives, or right away if the netdev already reads connected;
  - the peer's log compared line by line, and a peer exiting nonzero fails the case.
- **`tests/virtio-probe`** reads the identity registers. `virtio_probe` and `virtio_probe_empty` run on riscv32 and the flat profile.

**Choices beyond the design:**
- §7.3 gives no expected text for the probe, so the probe's output line is the implementer's own.
- Each case has an image file of its own name, because the runner names the ELF after the case.

**Mutants:** 61 in netpeer, all red. The runner and board mutants are red too: the base moved, the row removed, `force-legacy` left out, `device = "none"` ignored, no `cont`, the wrong `net_bus`, and the peer's lines.

**Not pinned here, named:** the connected wait and `-S` (no frame is sent yet), `props` and `legacy`, and the rows' line and len. A3-4's cases are where each gets exercised.

**Runs:** `make sos-test` 1446, and netpeer's 3 hosted files.

Requested changes on patch SO-164.p1 (revision 1)

**Changes requested, revision 1.** I reviewed it at its own base af22c747; it reads needs-rebase on the server. The host boundary is sound:
- the peer listens on 127.0.0.1 only;
- QEMU's only netdev is a stream to that port, with no user-mode NIC;
- the peer forwards nothing.

The board rows match QEMU virt's device tree. Four findings need changes. The tests and fix probes are in f554.

## 1. The connected check lets a guest start with its netdev down
The runner waits for `NETDEV_STREAM_CONNECTED` only when `info network` says "connecting" (sos_runner.py:16684-16689), then sends `cont`. A refused connect leaves the info string as `error: Failed to connect …`. QEMU sets "connecting" again only under `reconnect_ms`, which the runner never sets. So a peer that is gone before the connect lets the guest run with no network, contrary to CLAUDE.md:213 and the runner's own comment.

**The probe.** With the peer killed right after it prints its port, both cases ran, and were red only through `(netpeer exited -9: )`.

**The fix, probed.** Before `cont`, read `info network` again and require `tcp:127.0.0.1:{port}`, and require `query-status` to read `prelaunch`. With that change:
- both cases are green;
- the killed peer is red with "net0: index=0,type=stream,error: Failed to connect to '127.0.0.1:61527': Connection refused";
- dropping `-S` is red, which also pins `-S`. Today removing `-S` survives.

## 2. The peer's parser checks a guest controls have no tests
- **The `burst` digit check.** Removing its lower bound (peer.saw:331-335) survives netpeer's tests. Against the malformed-frame tests in f554 it is `panic at peer.saw:335: integer overflow`, from payloads `burst  3` and `burst 3/`. The patch as written does not panic, but a guest-controlled panic in the peer is one deleted comparison away.
- **Eight more** survive netpeer's own tests, and with the malformed-frame tests all nine go red:
  - a UDP length shorter than the IP payload accepted;
  - RFC 768's zero checksum sent as 0, not 0xFFFF;
  - `sum16` folding once;
  - five boundary off-by-ones: a 33-byte IPv4 frame, a total length of 19, a total one byte past the frame, a 7-byte ICMP message and a 7-byte UDP datagram.
- **`burst_count`'s prefix loop** (peer.saw:323-324) reads six bytes whatever the length. wire.saw:5-6 says no caller reads past the end. Harmless today, since the count falls to 0 and is refused, but add `if len < plen { return None }`.

**Asked:** move the named cases into `tests/peer.saw` and `tests/wire.saw`, and add the guard.

## 3. The `device` key cannot run the design's wrong-device case
The runner appends `netdev=net0,bus=…,mac=` to whatever `device` names (sos_runner.py:16626-16631). With `device = "virtio-rng-device"`, which CLAUDE.md and design §6.3 and §7.3 use for the wrong-device refusal, QEMU says "Property 'virtio-rng-device.netdev' not found".

**Asked:** add `netdev`, `bus` and `mac` only for the network device.

## 4. `virtio_probe` hard-codes the base, so flat's VIRTIO7 row is unpinned
tests/virtio-probe/src/main.saw reads at `TRANSPORT_BASE`, while its comment says it reads "where the board says the window is". On the flat profile, moving VIRTIO7's base to 0x1000_9000 survives both cases.

**Asked:** read the mapping's base. With that change the moved base faults at `tval=0x10009000`.

## Smaller
- **The peer leaks on an early exception.** The socketpair and pipe are made after the peer starts and before the `try` (sos_runner.py:16669-16673), so an exception there leaks the peer. Make them before the peer starts, or inside the `try`.
- **The peer's exit-status check has no case.** No case makes the peer exit nonzero. Name it, or pin it once A3-4's frames flow.
- **A `virtio_probe_legacy` case is cheap now.** `legacy: True` prints `version=1 device=0`.
- **A `net` case without `expect_peer` checks no peer log** (sos_runner.py:16730-16731). Require it.
- **CLAUDE.md:154 is 103 columns.**
